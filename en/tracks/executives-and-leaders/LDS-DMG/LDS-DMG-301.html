LDS-DMG-301 Governing Data for AI: Training, Retrieval and Agent Access

  • Level 300 · Develop
  • Workshop
  • 16 h
  • Audience: specialist

Track

Executives & Leaders

Stream

LDS-DMG Data Management and Governance Professions

Level

Level 300 · Develop

Audience

specialist

Format

Workshop: 2 days with labs on provided AI systems

Total hours

16 h

Prerequisites

  • LDS-DMG-204 Data Classification in Practice
  • Explains how an assistant retrieves documents and calls tools (FND-AIC-102 or equivalent)

Description

Participants decide what data AI systems may train on, retrieve, expose to agents or send to external models, then test those decisions on a provided assistant and agent over synthetic data. Pipelines are DEV-DAT-302; agent sandboxes LDS-AIG-302; personal data and copyright in training LDS-AIG-306.

Learning outcomes

By the end, the participant can:

  1. Applied

    Classify proposed AI data uses by data class, purpose and hosting as allowed, conditional or prohibited.

    Given twelve business requests.

    Evidence an eligibility matrix, ten of twelve matching the key.

  2. Applied

    Test a retrieval assistant for permission leaks and specify the label filter that closes them.

    Given 300 labelled documents and three roles.

    Evidence leakage test logs before and after the filter.

  3. Applied

    Configure per-tool agent permissions as scoped, read-only or approval-gated.

    Given an agent with two tool servers.

    Evidence a permission specification and a passing scripted test.

  4. Performance

    Review provider terms on retention, training on inputs, residency and deletion, and decide which data classes may be sent.

    Given two synthetic provider terms.

    Evidence a checklist and decision memo.

  5. Performance

    Defend a data-for-AI standard with logging and retention rules, and a decision record for one case.

    Given a citizen-reply agent using case files.

    Evidence both, defended before a panel that includes an engineer.

Topics

Uses and eligibility

  • Training, evaluation, retrieval, agent context and logs
  • Derived data inherits source rules; training cannot be undone
  • Classification, purpose, secondary use and source licences
  • Hosting tiers: local, sovereign cloud, external service

Permission-aware access

  • Labels at indexing, filters at retrieval
  • Least privilege and approvals for agents
  • Access through semantic layers and tool servers

External models and evidence

  • Provider terms, transfers and residency
  • Prompt and output logs
  • AI data-use register

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Retrieval index with metadata filters
pgvector, OpenSearch
Language models
a local open-weight model, a commercial API
Agent tool access
Model Context Protocol servers, plain function calling

How the work is assessed

  • AI-off supervised check on six unseen requests (20%)
  • Graded labs with test logs (40%)
  • Standard and panel defence (40%)
To pass
70% overall, 60% on the check, and no prohibited data class sent to an external model

Use of AI in the course

AI-off for the check. AI-tutor in the leakage and agent labs. AI-full for drafting the standard, which the participant defends live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
