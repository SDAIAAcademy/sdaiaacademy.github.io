LDS-DMG-208 Master and Reference Data Management

  • Level 200 · Apply
  • Workshop
  • 16 h
  • Audience: practitioner

Track

Executives & Leaders

Stream

LDS-DMG Data Management and Governance Professions

Level

Level 200 · Apply

Audience

practitioner

Format

Workshop: 2 days with labs and a stewardship mini-project

Total hours

16 h

Prerequisites

  • LDS-DMG-101 Data Management Foundations
  • Has profiled a table for completeness and duplicates (LDS-DMG-203 or equivalent)
  • Runs a provided notebook; no programming

Description

Participants consolidate supplier records from three synthetic systems, with Arabic and English names, spelling variants and conflicting addresses. They produce measured matching rules, golden records, a stewardship queue and a versioned reference code list, using provided notebooks and a visual tool.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Compare registry, consolidation, coexistence and centralised implementation styles.

    Given four organisational scenarios.

    Evidence a justified style for each, three of four matching the reference.

  2. Applied

    Configure matching rules with Arabic and English name normalisation and measure their precision and recall.

    Given about 20,000 records and 500 labelled pairs.

    Evidence a rule file and a match-quality table at two thresholds, split by script.

  3. Applied

    Implement survivorship rules that form golden records from source trust, recency and completeness.

    Given match clusters and a source trust matrix.

    Evidence a golden-record table and peer-reviewed rule document.

  4. Applied

    Prepare a versioned reference code list with owner, definitions and a crosswalk from source codes.

    Given inconsistent region and activity codes.

    Evidence the code list, crosswalk and change log.

  5. Performance

    Design a stewardship workflow for uncertain matches and code changes, with roles, service levels and indicators.

    Given the match results and the case roles.

    Evidence a workflow and decision log tested on twenty queued cases.

Topics

Concepts and styles

  • Master, reference and transactional data
  • Implementation styles and ownership

Matching

  • Standardisation and blocking
  • Arabic name normalisation and transliteration
  • Deterministic and probabilistic rules
  • Precision, recall and thresholds

Golden records and reference data

  • Survivorship, cross-references and history
  • Standard code sets and hierarchies
  • Versioning and crosswalks

Stewardship

  • Queues and decision rights
  • Quality indicators for core entities
  • Language-model match suggestions under human review

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Record linkage
Splink, OpenRefine
SQL engine
DuckDB, PostgreSQL
Versioned code lists
Git with CSV files, a spreadsheet with a change log

How the work is assessed

  • AI-off supervised check on twenty record pairs (20%)
  • Graded labs (40%)
  • Decision pack and review (40%)
To pass
70% overall and 60% on the check

Use of AI in the course

AI-off for the check. AI-tutor in the matching and survivorship labs. AI-full for the decision pack; in the stewardship lab participants log where they overrule the model's suggestions.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
