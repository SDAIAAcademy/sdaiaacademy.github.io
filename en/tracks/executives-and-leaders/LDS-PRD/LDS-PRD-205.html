LDS-PRD-205 Prototyping AI Products with Coding Agents

  • Level 200 · Apply
  • Workshop
  • 16 h
  • Audience: practitioner

Track

Executives & Leaders

Stream

LDS-PRD AI Product and Delivery

Level

Level 200 · Apply

Audience

practitioner

Format

Workshop: two days with labs, guided pre-work and a five-user test

Total hours

16 h

Prerequisites

  • Has written a product requirement or user story
  • Runs a terminal command by following written steps

Description

Product and design staff direct a coding agent to build a web prototype that calls a hosted model on synthetic data, add acceptance checks, test it with five users, find where agent-built prototypes mislead, and hand engineering what to keep and discard. No-code tools are USE-FLU-205; engineering with agents is DEV-SWE-201.

Learning outcomes

By the end, the participant can:

  1. Applied

    Prepare a brief and context file stating the question, scope, data, constraints and done criteria.

    Given the case idea and its specification.

    Evidence a brief from which the agent builds a working first version.

  2. Applied

    Use a coding agent to build a prototype that calls a language model, in small verified steps under version control.

    Given a sandboxed workspace, a capped key and synthetic data.

    Evidence a running prototype and a commit per working step.

  3. Applied

    Test the prototype against acceptance checks and a limits checklist for hard-coded paths, exposed secrets, unvetted dependencies, real data and accessibility.

    Given the running prototype.

    Evidence a check log and a ranked limits list.

  4. Performance

    Deliver a hand-over that separates validated learning, specification and evaluation cases from code to discard.

    Given findings from five users and an engineer reviewer.

    Evidence a hand-over pack accepted in a live review.

Topics

What a prototype is for

  • Question-driven prototypes and fidelity
  • Prototype, pilot and product

Directing a coding agent

  • Briefs and context files
  • Small steps, run and check, version control as undo
  • Sandboxes, capped keys and synthetic data

Limits and hand-over

  • Happy-path illusions
  • Secrets, unvetted packages, accessibility and right-to-left gaps
  • Licences of generated assets
  • What engineering keeps

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Coding agent
goose, OpenCode, any commercial coding agent
Sandboxed workspace with version control
a local development container with Git, a free-tier hosted development environment
Model access with a spending cap
a hosted open-weight model, any commercial API

How the work is assessed

  • Supervised check: five risks in an unseen prototype (20%)
  • Graded labs (30%)
  • Capstone prototype and hand-over (35%)
  • Live engineer review (15%)
To pass
70% overall and at least 60% on the check

Use of AI in the course

AI-off for the supervised check and the first brief. AI-full in build labs, where directing the agent is the skill. AI-tutor for the limits review.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
