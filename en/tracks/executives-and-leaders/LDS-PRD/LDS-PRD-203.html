LDS-PRD-203 Human-AI Interaction and Experience Design

  • Level 200 · Apply
  • Intensive
  • 24 h
  • Audience: practitioner

Track

Executives & Leaders

Stream

LDS-PRD AI Product and Delivery

Level

Level 200 · Apply

Audience

practitioner

Format

Intensive: 3 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

24 h

Prerequisites

  • Has designed, specified or usability-tested a digital interface or service
  • Has used an AI assistant and an agent that acts on the user's behalf

Description

Participants design how people work with a bilingual assistant and an appointment-booking agent for a fictional utility. They audit interaction patterns, set expectations from measured capability, show sources and uncertainty, add confirmation and undo for agent actions, design hand-off to a person, and check accessibility and Arabic right-to-left text, ending with a prototype tested with users. Front-end building is DEV-SWE-203.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Describe interaction patterns for assistants and agents and the trust risk each carries.

    Given six products using chat, inline, draft-and-review, approved and background tasks.

    Evidence an annotated pattern table with a risk and mitigation per product.

  2. Applied

    Draft onboarding, source display and uncertainty cues that match measured capability.

    Given evaluation results showing where the assistant fails.

    Evidence annotated screens linking each cue to its evidence.

  3. Applied

    Prepare recovery and escalation flows with confirmation and undo graded by how reversible each agent action is.

    Given six agent actions and the service's hand-off rules.

    Evidence flows covering every action, failure and refusal.

  4. Applied

    Test the prototype against Web Content Accessibility Guidelines (WCAG) criteria with a screen reader and keyboard only.

    Given a prototype with streamed responses.

    Evidence an accessibility report of issues, criteria and fixes.

  5. Applied

    Test Arabic and mixed-direction layouts with numbers, dates, Latin names and code-switched input.

    Given twenty bilingual test scripts.

    Evidence a bidirectional defect log with fixes.

  6. Performance

    Evaluate the design in a moderated usability test measuring task success, over-reliance on seeded errors and recovery time.

    Given five participants and four tasks.

    Evidence a test report with three design changes, defended in a critique.

Topics

Patterns for assistants and agents

  • Conversation, inline, draft-and-review, delegated and background work
  • When free text is the wrong input
  • Autonomy matched to reversibility

Trust calibration

  • Over-reliance and under-use
  • Sources, confidence and stated limits
  • Disclosing AI involvement
  • Memory and data controls users can see
  • Approval prompts people click through

Errors and recovery

  • Wrong, refused and slow responses
  • Confirm, preview and undo
  • Hand-off to a person with context
  • Feedback and corrections as evaluation data

Accessibility and right-to-left design

  • Streamed text, live regions and focus order checked against WCAG
  • Mirrored layouts and bidirectional text
  • Arabic register, dialect and typography

Testing with people

  • Think-aloud sessions
  • Seeded errors to measure over-reliance
  • Task success and recovery time

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Interactive prototyping
Penpot, any design tool with interactive prototypes, an HTML prototype
Accessibility checking
axe-core, WAVE
Screen readers
NVDA, VoiceOver, TalkBack
Language model for realistic responses
a hosted open-weight model, any commercial API

How the work is assessed

  • Supervised check: critique two unseen AI screens (20%)
  • Graded labs (30%)
  • Capstone on a five-criterion rubric (40%)
  • Design critique (10%)
To pass
70% overall and at least 60% on the check and the capstone

Use of AI in the course

AI-off for the supervised check and first sketches of flows. AI-tutor in the labs. AI-full for generating screens and sample responses, with every design decision defended.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
