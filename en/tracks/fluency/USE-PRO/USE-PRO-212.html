USE-PRO-212 AI for Security and IT Operations Staff

  • Level 200 · Apply
  • Workshop
  • 12 h
  • Audience: practitioner

Track

Data & AI Fluency

Stream

USE-PRO Fluency for Professions

Level

Level 200 · Apply

Audience

practitioner

Format

Workshop: two days of labs on one synthetic case, plus a tracked baseline

Total hours

12 h

Prerequisites

  • USE-FLU-201 Working with AI Assistants: Delegate, Describe, Judge, Own
  • Works in IT support, administration or monitoring and runs shell commands

Description

Operations and security staff use AI on one synthetic company network with logs, tickets and runbooks: triaging redacted alerts, catching injected instructions, testing runbooks and generated scripts, and checking AI-made phishing and voice clones. Building AI-assisted detection is DEV-SEC-305.

Learning outcomes

By the end, the participant can:

  1. Applied

    Use an assistant to triage redacted alerts and verify each verdict against the raw events.

    Given twenty unredacted alerts, one carrying an injected instruction.

    Evidence a triage sheet with evidence lines, a redaction record and the injection flagged.

  2. Applied

    Draft a runbook from a closed incident and test each step in a disposable environment.

    Given the incident ticket.

    Evidence a runbook with tested steps, rollback and run log.

  3. Applied

    Test AI-generated administration scripts by reading, static analysis and dry run.

    Given four scripts, two with planted destructive lines.

    Evidence a review record and a corrected script passing lint and dry run.

  4. Applied

    Analyse suspicious messages and calls for AI-made phishing and cloning, then verify and report them.

    Given six emails, a voice clone and a video.

    Evidence a verdict sheet with out-of-band checks and report tickets.

  5. Performance

    Redesign one recurring operations task with AI and measure time and errors on two runs.

    Given the pre-work baseline.

    Evidence a redesign card naming the approval point, reviewed live.

Topics

AI in the operations workflow

  • Confident wrong verdicts and invented flags
  • Accountability for every change

Triage and injection

  • Redacting secrets, or local models instead
  • Evidence lines over verdicts
  • Instructions hidden in logs and tickets

Runbooks and scripts

  • Testing in a disposable environment
  • Read before run: lint and dry run

Social engineering with AI

  • AI-written phishing
  • Voice and video clones
  • Out-of-band verification and reporting

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Local model runner
Ollama, llama.cpp
Log search
grep and jq, OpenSearch, Wazuh
Script analysis
ShellCheck, PSScriptAnalyzer
Disposable environment (provided)
Podman or Docker containers, a snapshot virtual machine

How the work is assessed

  • AI-off check: find destructive script lines and injected log text (20%)
  • Labs (35%)
  • Redesign card (35%)
  • Live review (10%)
To pass
70% overall, and no unredacted secret in any submission

Use of AI in the course

AI-off for the supervised check. AI-tutor in the script lab: it explains commands, never marks faults. AI-full elsewhere; no generated command runs unreviewed outside the sandbox.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
