FND-PRG-105 Computer Systems and Cloud Essentials for AI Work

  • Level 100 · Explain
  • Intensive

  • Audience: beginner

Format

Intensive: 4 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Prerequisites

  • FND-PRG-101 Python Programming for Data and AI
  • FND-PRG-102 Command Line, Git and Reproducible Environments

Description

Participants build a working model of the machine and the cloud beneath data and AI code. They measure how processors, accelerators, memory and storage limit a workload, compare threads and processes, follow an API call from name lookup to response, and run a containerised batch job on a cloud virtual machine with object storage and least-privilege access. Every lab ends with a cost figure. Serving, orchestration and capacity planning follow in DEV-OPS-201, DEV-INF-201 and DEV-INF-302.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Explain the memory hierarchy and how accelerators differ from processors, and identify what limits a workload.

    Given four described workloads, including loading model weights.

    Evidence the limiting resource named correctly for three of four.

  2. Awareness

    Describe the steps between calling an API and receiving its response, from name lookup to status code.

    Given a captured Hypertext Transfer Protocol (HTTP) trace.

    Evidence an annotated trace checked against a reference.

  3. Applied

    Measure a program's processor, memory and disk use, and compare threaded and multi-process versions.

    Given a synthetic text-processing batch job.

    Evidence a measurement table explaining the speed-up obtained.

  4. Applied

    Use an HTTP API from code with authentication, timeouts and retries with back-off.

    Given a mock API that fails and rate-limits on a schedule.

    Evidence a client that finishes within the limit, with a log of each retry.

  5. Applied

    Configure a virtual machine, object storage, a container image and a least-privilege role for a batch job.

    Given a provided training cloud account with a spending cap.

    Evidence a run log, a minimal permissions policy and a teardown record.

  6. Performance

    Plan, size and price a small batch inference job, run it, and explain the gap between estimate and actual.

    Given a small open-weight model, synthetic text and a fixed budget.

    Evidence a sizing note, run logs, the measured cost and a defence.

Topics

Inside one machine

  • Cores, threads and accelerators
  • Memory hierarchy and bandwidth
  • Storage throughput
  • Model memory from parameter count and number format

Operating system essentials

  • Processes, threads and the global interpreter lock
  • Asynchronous input and output

Networks and APIs

  • Addresses, ports and name lookup
  • Transport encryption and certificates
  • Methods, status codes and headers
  • Timeouts, retries and rate limits

Containers and cloud primitives

  • Pushing an image to a registry and running it remotely
  • Compute, object storage and managed services
  • Identity, roles and least privilege
  • Regions, residency and shared responsibility

Cost basics

  • Pricing units for compute, storage, transfer and tokens
  • Idle resources, teardown and budgets

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Resource monitoring
htop, psutil, py-spy
Container engine
Podman, Docker
Cloud account with a spending cap
a provided academic or sovereign cloud tenancy, a training account on any major public cloud
Local runtime for small open-weight models
llama.cpp, Ollama

How the work is assessed

  • Supervised AI-off estimation check (20%)
  • Labs (35%)
  • Capstone sizing note and cost comparison (30%)
  • Defence (15%)
To pass
65% overall, a passed defence, and a teardown record for every cloud lab

Use of AI in the course

AI-off for the first estimate in each lab and the supervised check. AI-tutor for reading logs, errors and documentation. AI-full for capstone scripts, defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
