FND-PRG-103 Data Structures, Algorithms and Complexity

  • Level 100 · Explain
  • Extended
  • 60 h
  • Audience: beginner

Track

Data & AI Foundations

Stream

FND-PRG Programming and Software Practice

Level

Level 100 · Explain

Audience

beginner

Format

Extended: 12 weekly three-hour sessions with labs, graded problem sets and a final project

Total hours

60 h

Prerequisites

  • FND-PRG-101 Python Programming for Data and AI
  • Uses school algebra, including powers and logarithms

Description

Participants implement the core data structures and algorithms in Python, measure them, and connect each to the data and model code they will write later. They build a dynamic array, a hash map, a heap, a search tree and a graph, analyse sorting and search by counting operations and by timing, and explain why a join, a deduplication or a nearest-neighbour lookup is fast or slow. The emphasis is reasoning about time and memory on realistic inputs, not interview puzzles.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Explain big-O notation and identify the cost class of a given piece of code.

    Given ten short functions with nested loops, recursion and library calls.

    Evidence the correct class with a reason for eight of ten in a supervised check.

  2. Awareness

    Compare arrays, linked structures, hash tables, heaps and trees by operation cost and memory layout.

    Given a blank table of operations.

    Evidence a completed table and a note on why contiguous arrays often beat their big-O prediction.

  3. Applied

    Implement a dynamic array, a hash map with collision handling, a binary heap and a binary search tree.

    Given interface specifications and provided checks.

    Evidence passing implementations with timing plots that match the predicted growth.

  4. Applied

    Implement and measure sorting, binary search and graph traversal, and relate the timings to predicted complexity.

    Given synthetic datasets of increasing size.

    Evidence a notebook with operation counts, log-scale timings and an interpretation.

  5. Applied

    Analyse a slow data-processing function and change its structure or algorithm to remove the bottleneck.

    Given a quadratic deduplicate-and-join over synthetic records.

    Evidence before-and-after profiles with identical outputs.

  6. Performance

    Design and build a small in-memory index and defend its structures against a time and memory budget.

    Given a brief such as prefix search over Arabic and English place names.

    Evidence a repository with benchmarks against the budget and a ten-minute defence.

Topics

Cost models

  • Counting operations and big-O
  • Best, average and worst case
  • Amortised cost
  • Recursion, divide and conquer, and simple recurrences

Sequences and hashing

  • Dynamic arrays and memory layout
  • Linked lists and when they lose
  • Hashing, collisions and load factor
  • How Python's dictionaries work

Ordering and searching

  • Comparison sorts and stable sort keys
  • Binary search
  • Heaps and top-k selection

Trees and graphs

  • Search trees and balance
  • Tries for text prefixes
  • Breadth-first and depth-first search
  • Shortest paths with Dijkstra's algorithm

Memory and data code

  • Object overhead and contiguous data
  • Streaming data that does not fit in memory
  • Joins as hashing or sorting
  • Nearest-neighbour search and why indexes approximate
  • Edit distance by dynamic programming

Tools and platforms

Memory measurement
tracemalloc, memray
Reference libraries for checking results
NumPy and NetworkX, igraph

How the work is assessed

  • Supervised AI-off complexity checks in weeks 4, 8 and 11 (30%)
  • Weekly problem sets (25%)
  • Final project and benchmarks (25%)
  • Defence (20%)
To pass
60% overall, at least 60% on the supervised checks, and a passed defence

Use of AI in the course

AI-off for the supervised checks and the first in-lab implementation of each core structure. AI-tutor for problem sets, extensions and debugging hints. AI-full for the final project, defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
