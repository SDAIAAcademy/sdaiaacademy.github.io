FND-PRG-106 Code Reading and Debugging without Assistance

  • Level 100 · Explain
  • Workshop
  • 12 h
  • Audience: beginner

Track

Data & AI Foundations

Stream

FND-PRG Programming and Software Practice

Level

Level 100 · Explain

Audience

beginner

Format

Workshop: two days of drills and a supervised practical

Total hours

12 h

Prerequisites

  • FND-PRG-101 Python Programming for Data and AI
  • Runs terminal commands; Git commands are supplied

Description

Participants practise reading unfamiliar code and finding faults without help, the skills most at risk when practice is delegated to an assistant. Through predict-the-output drills, hand tracing, Parsons problems and seeded-bug hunts in a small data-processing codebase, they learn a repeatable method: reproduce, isolate, hypothesise, test, fix, and add a regression check.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Read unfamiliar code and state its output, including the effects of aliasing, scope and mutation.

    Given printed programs of 20 to 60 lines.

    Evidence a supervised drill with at least 80% correct.

  2. Awareness

    Explain what a traceback or failing assertion reveals about where and what a fault is.

    Given ten error reports from a cleaning script.

    Evidence the faulty line and cause named for seven of ten.

  3. Applied

    Apply the reproduce, isolate, hypothesise, test and fix method to locate defects, keeping a log.

    Given a codebase with seeded defects and no assistant.

    Evidence a log of hypotheses and tests, with a fix and regression check per defect.

  4. Applied

    Use a step debugger, breakpoints and targeted logging to inspect program state.

    Given a program that gives a wrong total on one input file.

    Evidence a recorded session showing the breakpoint that exposed the fault.

  5. Awareness

    Distinguish assistant use that keeps debugging skill, such as asking for explanations, from use that erodes it.

    Given four assistant debugging transcripts.

    Evidence each transcript classified with reasons, matching the reference on three of four.

Topics

Reading and structured practice

  • Predict-the-output and hand tracing
  • Parsons problems with distractor lines
  • Faded worked examples
  • Explaining code aloud
  • Finding entry points and call paths in a multi-file codebase

A debugging method

  • Reproduce and shrink the failing case
  • Isolate by halving input and code
  • Fix, then add a regression check
  • Bisecting history

Tools without assistants

  • Tracebacks and error messages
  • Step debugger and breakpoints
  • Assertions and logging

Assistants afterwards

  • Evidence on skill loss from delegation
  • Verifying a suggested fix

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Step debugger
pdb, the debugger in VS Code or Thonny
Tracing and drill aids
Python Tutor, Runestone Academy exercises
History bisection
git bisect, manual search over tagged versions

How the work is assessed

  • Supervised AI-off practical: trace three programs, then find and fix two seeded defects (70%)
  • Debugging log from the lab (30%)
To pass
60% overall, with at least one defect fixed and covered by a regression check

Use of AI in the course

AI-off for every drill, lab and the practical. In the final session only, after an unaided attempt, participants use an AI-tutor to compare interaction patterns.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
