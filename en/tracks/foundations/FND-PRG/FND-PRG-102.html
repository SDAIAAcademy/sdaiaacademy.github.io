FND-PRG-102 Command Line, Git and Reproducible Environments

  • Level 100 · Explain
  • Intensive
  • 24 h
  • Audience: beginner

Track

Data & AI Foundations

Stream

FND-PRG Programming and Software Practice

Level

Level 100 · Explain

Audience

beginner

Format

Intensive: 3 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

24 h

Prerequisites

  • Writes and runs a short program in Python or another language

Description

Participants set up work that another person can rebuild from a clean machine. They script the shell, use Git with branches, pull requests and review on a shared repository, resolve a merge conflict, lock dependencies, run a project in a container without administrator rights, and keep secrets out of history.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Explain how Git records history as commits, branches and remotes, and what each everyday command changes.

    Given diagrams of a repository and sequences of commands.

    Evidence commit graphs drawn correctly for four of five sequences in a supervised check.

  2. Applied

    Use the shell to inspect and transform files, combining commands with pipes and a short script.

    Given a folder of synthetic log and comma-separated files.

    Evidence a script that produces the requested counts and runs unchanged on a second folder.

  3. Applied

    Apply a branch, pull request and review workflow, including resolving a merge conflict.

    Given a team repository with a protected main branch.

    Evidence a merged pull request with review comments addressed and a resolved conflict in the history.

  4. Applied

    Configure an isolated environment with locked dependencies and run the project in a container without administrator rights.

    Given an analysis project that fails on a second machine.

    Evidence a lock file, a container definition and a clean rebuild that reproduces the expected output.

  5. Applied

    Prepare a repository that keeps secrets out of history, and carry out the response when one leaks.

    Given a project needing an API key, with a seeded leaked key in an old commit.

    Evidence configuration read from the environment, a passing secret scan and a rotation note.

  6. Performance

    Deliver a repository that a peer reproduces on a clean machine using only its README.

    Given the participant's own small project.

    Evidence the peer's reproduction log and fixes for every step the peer could not follow.

Topics

The shell

  • Paths and permissions
  • Pipes, redirection and filters
  • Environment variables and exit codes
  • Remote login with secure shell (SSH) keys

Version control

  • Commits, staging and history
  • Branches, merges and conflicts
  • Pull requests and review etiquette
  • Undoing mistakes

Reproducible environments

  • Virtual environments
  • Declared dependencies and lock files
  • One documented command to rebuild and run
  • Keeping data and outputs out of the code

Containers at user level

  • Images, containers and volumes
  • A short container definition
  • What a container does not isolate

Secrets and hygiene

  • Scanning before each commit
  • After a leak: rotate, then clean history

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Version control and hosting
Git with Forgejo or Gitea, Git with GitLab or GitHub
Environment and lock-file manager
uv, Poetry, pip-tools
Container engine that runs without administrator rights
Podman in rootless mode, Docker in rootless mode
Secret scanning and hooks
gitleaks with pre-commit, the host's built-in secret scanning

How the work is assessed

  • Supervised AI-off check on shell commands and commit graphs (20%)
  • Labs (30%)
  • Peer reproduction of the capstone, on a rubric (40%)
  • Short oral on one failed step (10%)
To pass
65% overall, at least 60% on the supervised check, and a successful reproduction after the follow-up task

Use of AI in the course

AI-off for the first attempt at each lab's core commands and for the supervised check. AI-tutor for extensions, through a repository instruction file telling the assistant to hint, not solve. AI-full for the capstone, defended in the oral.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
