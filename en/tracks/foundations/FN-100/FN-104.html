Prerequisites

  • FN-101 Python for Data and AI Work
  • Writes Python functions that read files and loop over records

Description

Participants answer questions from data and show the answers are right. The case is a fictional courier company with synthetic shipments, hubs, couriers and delivery attempts. In an embedded analytical database they write joins, grouping and window functions, predicting each result first and catching fan-out and NULL errors. In a dataframe library they type, clean, reshape and join raw exports. At the boundary they handle delimited, JSON and columnar files, legacy Arabic encodings, Hijri and Gregorian dates, time zones, and schema checks that stop a bad batch.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Identify the grain and keys of each table and predict the row count of a join before running it.

    Given a six-table courier schema.

    Evidence a grain sheet and ten join predictions, at least eight correct.

  2. Applied

    Implement SQL queries with joins, grouping, common table expressions and window functions that answer operational questions.

    Given twenty questions from the courier's operations team.

    Evidence a query file that matches the hidden reference results on at least sixteen.

  3. Applied

    Prepare an analysis-ready table from raw exports with a dataframe library, handling types, missing values, duplicates, dates and reshaping.

    Given three months of shipment exports with seeded defects.

    Evidence a notebook that reruns from the raw files and a cleaning log that accounts for every dropped or changed row.

  4. Applied

    Apply Arabic text normalisation and encoding repair so that names and addresses match across sources.

    Given customer records in UTF-8 and a legacy code page, with letter variants, diacritics and Arabic-Indic digits.

    Evidence a match-rate table before and after normalisation, with the rules applied.

  5. Applied

    Configure schema and quality checks that reject or quarantine a bad batch with a reason.

    Given a daily file with wrong types, out-of-range timestamps and duplicate keys.

    Evidence a validation run that stops the load and reports each failing rule.

  6. Awareness

    Compare delimited, JSON Lines and columnar formats by size, read speed, types preserved and fitness for exchange.

    Given the same shipment table written in three formats.

    Evidence a measured comparison table with a recommended format per use.

Topics

Relational querying

  • Tables, keys, grain and cardinality
  • Filters, NULL and three-valued logic
  • Joins, fan-out and anti joins
  • Grouping and common table expressions

Window functions

  • Partitions and ordering
  • Ranking, lag and lead
  • Running and moving aggregates
  • Testing a query against known answers

Dataframes

  • Typed loading and nullable types
  • Missing values and duplicates
  • Tidy data: melt and pivot
  • Joins with validated cardinality
  • Eager and lazy engines

Text, dates and encodings

  • UTF-8 and legacy Arabic code pages
  • Arabic letter variants, diacritics, elongation and digits
  • Hijri and Gregorian dates
  • Time zones and offsets

Formats and validation

  • Delimited, JSON Lines and columnar files
  • Declared schemas and range checks
  • Rejecting a load versus quarantining rows
  • Data dictionaries and cleaning logs

How the work is assessed

  • Supervised AI-off check: predict-the-result and write-the-query items in a locked console (30%)
  • Capstone repository: answers against hidden references 30, pipeline reruns from raw files 20, validation rules 20, Arabic text and date handling 15, documentation 15 (50%)
  • Live rerun on the assessor's batch, with failing checks explained (20%)
To pass
70% overall and at least 60% on the AI-off check

Use of AI in the course

AI-off for predictions, the first attempt at each query lab and the supervised check. AI-tutor in the dataframe and format labs. AI-full in the capstone, where every assistant-written query must be tested against a known answer.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
