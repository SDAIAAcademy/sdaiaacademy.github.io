FND-AIC-104 Responsible Data and AI Practice for Builders

  • Level 100 · Explain
  • Workshop
  • 12 h
  • Audience: beginner

Track

Data & AI Foundations

Stream

FND-AIC AI Concepts and Responsible Practice

Level

Level 100 · Explain

Audience

beginner

Format

Workshop: one and a half days with labs and a tracked follow-up task

Total hours

12 h

Prerequisites

  • Has run a small Python project under version control (FND-PRG-102 or equivalent)

Description

Participants make a synthetic build, a complaint-triage assistant that calls a language model, responsible before it is written: they classify its data, decide what may go to an external model service, check licences, turn ethics principles into checks, clean a seeded repository and write the user disclosure. DEV-SEC-201 and DEV-SEC-303 go deeper.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Explain the data protection principles that shape a build, from lawful basis to transfer and breach notice.

    Given a brief for the case-study assistant.

    Evidence the brief annotated principle by principle.

  2. Applied

    Classify project data by sensitivity and decide what may go to an external model service.

    Given a synthetic inventory and a four-level scheme.

    Evidence a register with a handling decision per field.

  3. Applied

    Analyse model and dataset licences, including attribution and non-commercial terms, against a stated use.

    Given four licences and a use description.

    Evidence a register marking each asset permitted, conditional or blocked.

  4. Awareness

    Identify the build check and user disclosure that each AI ethics principle requires.

    Given seven principles and the project plan.

    Evidence a mapping table and a disclosure statement.

  5. Applied

    Apply security hygiene to a repository: remove secrets, pin and audit dependencies, validate model output.

    Given a seeded repository.

    Evidence scan reports before and after, with fixes in the commit history.

Topics

Data protection and classification

  • Personal data in prompts, logs and training
  • Lawful basis, minimisation, retention, transfer
  • Classification and external services
  • Pseudonymisation and its limits

Licences and provenance

  • Open-weight and dataset licences
  • Attribution and use restrictions
  • Ownership of generated content

Ethics principles as build checks

  • Subgroup fairness tests
  • Transparency and disclosure
  • Human oversight and ownership
  • Risk tiers setting the depth of checks

Security hygiene

  • Secrets, keys and dependency pinning
  • Untrusted input, output and logs

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Secret and dependency scanning
gitleaks, OSV-Scanner, pip-audit
Personal data detection
Presidio, regular-expression rules
Licence references
the SPDX licence list, model and dataset cards

How the work is assessed

  • Supervised AI-off scenario check on handling decisions (30%)
  • Responsible build pack with review (70%)
To pass
70% overall, with no highest-sensitivity field misclassified

Use of AI in the course

AI-off for the scenario check and the classification register; AI-tutor for licences and scan output; AI-full for drafting the disclosure, checked against the build pack.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
