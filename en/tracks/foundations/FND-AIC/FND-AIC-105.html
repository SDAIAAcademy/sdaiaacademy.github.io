FND-AIC-105 Classical AI: Search, Planning and Knowledge Representation

  • Level 100 · Explain
  • Intensive
  • 30 h
  • Audience: beginner

Track

Data & AI Foundations

Stream

FND-AIC AI Concepts and Responsible Practice

Level

Level 100 · Explain

Audience

beginner

Format

Intensive: 4 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

30 h

Prerequisites

  • FND-PRG-101 Python Programming for Data and AI
  • Writes Python functions over lists and dictionaries; FND-PRG-103 or FND-MTH-105 helps but is not required

Description

Participants solve problems with the methods that predate machine learning and still run timetables, routes, configurations and rule checks. They implement heuristic search on an open road map, model a timetable for a constraint solver, run a classical planner, and encode eligibility rules in logic to find conflicts, then compare each result with a language-model-only attempt. The course suits career changers bridging to degree-level AI foundations and engineers who give agents solvers and planners as tools.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Describe a problem as states, actions, goal and costs, and distinguish when search, constraints, planning or logic fits it.

    Given six problem statements from transport, scheduling and public services.

    Evidence a formulation sheet with method choices, at least five of six consistent with the reference.

  2. Applied

    Implement uniform-cost and A* search with an admissible heuristic and measure the nodes each expands.

    Given a road graph from open map data and a test harness.

    Evidence passing tests and a table of path cost and nodes expanded.

  3. Applied

    Implement a constraint model of a timetabling problem with hard rules and soft preferences.

    Given a synthetic set of courses, rooms and staff.

    Evidence a feasible timetable confirmed by an independent checker.

  4. Awareness

    Explain how a classical planner derives a plan from action definitions and why each step can be checked.

    Given a small logistics domain.

    Evidence an annotated plan trace with a validator run.

  5. Applied

    Implement eligibility rules in logic and use an inference engine to answer queries and expose conflicts.

    Given a synthetic rulebook of about 20 rules.

    Evidence a rule file, query derivations and a conflict report.

  6. Awareness

    Compare a classical method and a language-model-only attempt for correctness, verifiability, cost and explanation.

    Given the capstone problem.

    Evidence a comparison section backed by checker results.

Topics

Search

  • State spaces and problem formulation
  • Uninformed search, heuristics and A*
  • Local search and simulated annealing
  • Game search and Monte Carlo tree search in brief

Constraint satisfaction

  • Variables, domains, hard and soft constraints
  • Backtracking and propagation
  • SAT and constraint-programming solvers
  • Where integer programming takes over (SPC-MOD-304)

Planning

  • Actions with preconditions and effects
  • Planning domain definition language
  • Plan validation and replanning

Logic and knowledge representation

  • Propositional and first-order logic
  • Forward and backward chaining
  • Ontologies in brief (DEV-DAT-304)

Where classical methods still win

  • Guarantees and audit trails
  • Models that propose and solvers that check
  • Solvers and planners as agent tools

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Graphs and map data
Python with NetworkX, OpenStreetMap extracts
Constraint and SAT solvers
MiniZinc, OR-Tools, PySAT
Classical planner
Fast Downward, another open planner that reads PDDL
Logic and rule engine
SWI-Prolog, clingo

How the work is assessed

  • Supervised AI-off check: trace a search by hand and formulate two problems (30%)
  • Graded labs (30%)
  • Capstone with defence (40%)
To pass
60% overall and at least 50% on the supervised check

Use of AI in the course

AI-off for hand tracing, the first search implementation and the supervised check. AI-tutor in the solver, planner and logic labs. AI-full in the capstone, where a language model is also the baseline.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
