FND-AIC-106 Technical Writing for Data and AI Work

  • Level 100 · Explain
  • Workshop
  • 12 h
  • Audience: beginner

Track

Data & AI Foundations

Stream

FND-AIC AI Concepts and Responsible Practice

Level

Level 100 · Explain

Audience

beginner

Format

Workshop: one and a half days of writing labs and a tracked follow-up review

Total hours

12 h

Prerequisites

  • Has a small data or code project, own or provided, to document

Description

Participants write the documents that data and AI work runs on: a README, a design document, a decision memo, an experiment report and a model or system card. Each starts from a repository, a model comparison or an evaluation log and ends with a peer test; one draft is unassisted, another is revised with an assistant, and every claim is checked.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Identify the reader, purpose and required sections of five common technical document types.

    Given five scenarios with named readers.

    Evidence an outline per scenario matching the reference structure.

  2. Applied

    Draft a README that lets a stranger install, run and check a small project.

    Given an undocumented repository.

    Evidence the README and a peer's run log on a clean environment.

  3. Applied

    Draft a one-page decision memo with options, trade-offs, a recommendation and the conditions that would change it.

    Given a measured comparison of two models on quality, cost and latency.

    Evidence a memo scored on a five-criterion rubric.

  4. Applied

    Prepare an experiment report and a model card that state uncertainty, results by data slice and known limits.

    Given an evaluation run log.

    Evidence a report and card that pass a peer checklist.

  5. Awareness

    Compare an unassisted draft with an assisted revision for accuracy, clarity and invented content.

    Given the participant's two drafts.

    Evidence a revision log of how each claim was checked.

Topics

Writing for a reader

  • Reader, purpose and decision
  • Bottom line first
  • Arabic and English glossaries
  • Uncertainty in plain words
  • Rubric-based peer review

Documents for systems and evidence

  • README, design document, decision record
  • Experiment reports
  • Model and system cards
  • Diagrams as text

Writing with assistance

  • AI-off first drafts
  • Typical errors of assisted revision
  • Verification logs and disclosure
  • Context files for coding agents

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Documents and diagrams as text
Markdown in a Git repository, Mermaid, PlantUML
Prose and style checks
Vale, a spelling and grammar checker
Writing assistant
a locally served open-weight model, an approved general-purpose assistant

How the work is assessed

  • Supervised AI-off memo from a provided result (30%)
  • Documentation set with revision log (60%)
  • Peer review given (10%)
To pass
60% overall and at least 50% on the supervised memo

Use of AI in the course

AI-off for the supervised memo and one first draft. AI-tutor for feedback on structure in the labs. AI-full for the logged assisted revision and for polishing the capstone.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
