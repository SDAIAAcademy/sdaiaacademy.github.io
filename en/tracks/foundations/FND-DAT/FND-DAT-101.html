FND-DAT-101 SQL and Relational Data

  • Level 100 · Explain
  • Intensive
  • 30 h
  • Audience: beginner

Track

Data & AI Foundations

Stream

FND-DAT Data Handling

Level

Level 100 · Explain

Audience

beginner

Format

Intensive: 4 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

30 h

Prerequisites

  • Comfortable with spreadsheets: filters, sorting and simple formulas
  • No programming experience required

Description

Participants query relational data in SQL and check that the answers are right. In an embedded analytical engine on a laptop they move from keys and constraints through joins, grouping and common table expressions to window functions. They predict results before running queries, catch the silent errors that joins and NULLs cause, and test assistant-written SQL against known answers. The capstone answers a stakeholder brief on an unseen dataset.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Explain the relational model: tables, keys, constraints, NULL and the grain of a table.

    Given a six-table synthetic delivery schema.

    Evidence an annotated schema with keys, cardinalities and grain matching the reference.

  2. Awareness

    Identify the output of joins, grouping and NULL comparisons before running them.

    Given small printed tables.

    Evidence supervised AI-off check, eight of ten correct.

  3. Applied

    Write queries with filters, joins, grouping, subqueries and common table expressions that answer business questions.

    Given a synthetic dataset of about a million order lines.

    Evidence a query file passing the automatic checker on 16 of 20 questions.

  4. Applied

    Apply window functions to rank rows, compare periods and compute running and moving totals.

    Given daily order tables.

    Evidence queries matching reference outputs, each partition explained in a comment.

  5. Applied

    Implement a small schema with keys and constraints, load raw files into it and report rejected rows.

    Given extracts with seeded defects.

    Evidence a definition script and a load log accounting for every rejected row.

  6. Awareness

    Identify silent errors in assistant-written SQL, such as join fan-out, wrong grain and missing business rules.

    Given ten generated queries and a revenue rule documented outside the schema.

    Evidence a verification note judging each query, with a test result.

Topics

The relational model

  • Tables, types, keys and constraints
  • Grain and cardinality
  • Normal forms in brief, and why analytical tables are wider
  • Embedded versus client-server engines

Querying one table

  • Filters, sorting, and expressions on text and dates
  • CASE expressions and set operations
  • NULL and three-valued logic
  • Grouping and having

Combining tables

  • Inner, outer, semi and anti joins
  • Join fan-out and double counting
  • Subqueries and common table expressions

Window functions

  • Partitions and ordering
  • Ranking, lag and lead
  • Running and moving aggregates

Building and checking

  • Loading files into constrained tables
  • Insert, update and delete inside a transaction
  • Views that limit what is exposed
  • Reading a query plan and the effect of an index
  • Testing queries against known answers

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Embedded analytical SQL engine
DuckDB, SQLite
Query checking
pytest comparing result sets, the Academy's query grader
Assistant for the text-to-SQL exercises
a locally served open-weight model, any approved assistant

How the work is assessed

  • Lab query files, auto-checked (30%)
  • Timed AI-off check of ten questions (30%)
  • Capstone repository, rubric-scored (30%)
  • Live query adaptation (10%)
To pass
70% overall and at least 60% on the timed check

Use of AI in the course

AI-off in the pre-work drills, the prediction exercises and the timed check. AI-tutor in labs, explaining errors without writing queries. AI-full in the verification lab and the capstone.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
