FND-DAT-103 Data Formats, Interfaces and Quality Checks

  • Level 100 · Explain
  • Workshop
  • 16 h
  • Audience: beginner

Level 100 · Explain

Format

Workshop: two days with labs, a short pre-work task and a tracked follow-up task

Total hours

16 h

Prerequisites

  • FND-DAT-102 Data Wrangling with DataFrames
  • Writes Python functions and handles exceptions (FND-PRG-101 or equivalent)

Description

Participants move data between files, interfaces and tables without losing or corrupting it. They compare delimited, JSON Lines and columnar files, repair encoding and time-zone faults, write a paginated API client with retries, flatten nested JSON and declare a schema whose checks stop a bad batch from loading.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Compare delimited, JSON Lines and columnar files on size, read time and type fidelity.

    Given one dataset in each format.

    Evidence a measured comparison table.

  2. Awareness

    Explain how encodings, byte order marks and time zones corrupt data, and identify each symptom.

    Given six damaged files.

    Evidence a diagnosis correct on five of six.

  3. Applied

    Implement an API client that follows cursor pagination, respects rate limits, retries with backoff and keeps raw responses.

    Given a mock API with injected errors.

    Evidence a run log showing every record retrieved exactly once.

  4. Applied

    Convert nested JSON into typed tables written as partitioned columnar files.

    Given the raw responses.

    Evidence files whose schema matches the declared one.

  5. Applied

    Implement validation checks that stop a load when a batch breaks the declared schema.

    Given batches with seeded defects.

    Evidence a report that catches every defect and passes a clean batch.

Topics

File formats

  • Delimited dialects and quoting
  • JSON (JavaScript Object Notation) and JSON Lines
  • Columnar files, partitions and in-memory interchange

Text and time

  • UTF-8 and legacy Arabic encodings
  • Offsets and Coordinated Universal Time (UTC)
  • Time zones and daylight saving

Interfaces

  • Status codes and errors
  • Offset and cursor pagination
  • Rate limits, retries and backoff
  • Rerunnable loads and checkpoints

Schema and validation

  • Declared types, ranges and keys
  • Failing a load versus quarantining rows
  • Data contracts, which follow in DEV-DAT-204

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Columnar file reading and writing
Apache Arrow with Parquet, DuckDB
HTTP client
httpx, requests
Schema validation
JSON Schema, Pandera
Mock API
an Academy mock service in a container, a local FastAPI server

How the work is assessed

  • Lab outputs, test-checked (40%)
  • Supervised AI-off check (20%)
  • Capstone script and report (30%)
  • Live run (10%)
To pass
70% overall, with the capstone batch loaded or rejected for the correct reasons

Use of AI in the course

AI-off in the pre-work and the supervised check. AI-tutor in labs. AI-full in the capstone, which runs live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
