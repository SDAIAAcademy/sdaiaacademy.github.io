DEV-OPS-302 Operating Language Model Applications: Tracing, Evaluation Gates and Safe Releases

  • Level 300 · Develop
  • Intensive
  • 36 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-OPS Operations and Reliability

Level

Level 300 · Develop

Audience

practitioner

Format

Intensive: 4 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

36 h

Prerequisites

  • DEV-OPS-201 Deploying AI Services: Containers, Serving and Monitoring
  • DEV-LLM-201 Building Applications on Language Models
  • Has written automated checks of model outputs; DEV-EVL-301 is recommended

Description

Participants run a grounded assistant, a synthetic public-services help desk with retrieval and two tools, as a production service. They version prompts, model identifiers, settings, retrieval index and tool schemas as one release unit, trace every request, put evaluation suites into a release gate, ship changes through shadow and canary stages with automatic rollback, configure guardrails, and sample live traffic for online evaluation and human review. Labs use a small open-weight model on a laptop or a free hosted tier. Evaluator design is in DEV-EVL-301 and organisation-wide release criteria in DEV-EVL-401; here participants operate evaluators.

Learning outcomes

By the end, the participant can:

  1. Applied

    Implement versioning of prompts, model identifiers, settings, index and tool schemas as one release unit.

    Given an assistant with scattered configuration.

    Evidence traces in which every response names its release.

  2. Applied

    Instrument model, retrieval and tool calls with spans, token counts, time to first token and time per output token.

    Given a telemetry collector that follows open tracing conventions.

    Evidence a full trace of one request and a latency and cost dashboard.

  3. Performance

    Build a release gate that blocks a change when a critical failure rate rises beyond a stated margin.

    Given an evaluation suite and three candidate changes.

    Evidence gate runs that pass one candidate and block two, with statistical comparisons.

  4. Performance

    Deliver a change through shadow and canary stages with automatic rollback.

    Given a gateway splitting replayed traffic.

    Evidence a release timeline with one automatic rollback.

  5. Applied

    Configure input and output guardrails and measure their false-block and miss rates.

    Given 200 labelled requests in Arabic and English.

    Evidence a report of both rates per language and added latency.

  6. Performance

    Design an online evaluation loop that samples traces, routes uncertain cases to people and feeds failures into the offline suite.

    Given a week of replayed traffic.

    Evidence a running job, an adjudicated review queue and three new regression cases.

Topics

What changes behaviour

  • The release unit
  • Provider model updates and pinned identifiers
  • Knowledge-base refresh as a release

Tracing

  • Spans for model, retrieval, tool and agent calls
  • OpenTelemetry generative AI conventions, still in development
  • Retention and redaction of traces

Gates and releases

  • Critical and tolerated failure modes
  • Paired comparison under a call budget
  • Shadow traffic, canaries and rollback triggers

Guardrails and online evaluation

  • Guardrails inline, evaluators after the fact
  • Calibrated graders on live traces
  • Review queues and new regression cases

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Model access through a chat-completions-compatible endpoint
an open-weight model, hosted or local, any commercial API
Tracing and prompt registry
OpenTelemetry with Langfuse, Arize Phoenix, MLflow
Evaluation harness
Inspect, promptfoo
Gateway and progressive delivery
LiteLLM, Agent Router, Argo Rollouts
Guardrail components
Presidio, an open-weight safety classifier

How the work is assessed

  • Supervised check: find a regression's cause from traces and a release diff (15%)
  • Graded labs (30%)
  • Capstone on a six-criterion rubric (45%)
  • Live defence (10%)
To pass
70% overall and 60% on both the supervised check and the capstone

Use of AI in the course

AI-off for the supervised check. AI-tutor in the labs. AI-full in the capstone, defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
