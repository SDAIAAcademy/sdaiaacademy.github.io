DEV-OPS-304 AI Cost Engineering: Gateways, Routing, Caching and Unit Economics

  • Level 300 · Develop
  • Workshop
  • 16 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-OPS Operations and Reliability

Level

Level 300 · Develop

Audience

practitioner

Format

Workshop: two days with labs and a costed review

Total hours

16 h

Prerequisites

  • DEV-LLM-201 Building Applications on Language Models
  • Reads request traces with token counts; DEV-LLM-303 is recommended

Description

Participants make the cost of AI applications measurable, attributable and smaller without losing quality. From a month of synthetic usage traces for three applications behind one gateway, they model cost per request, attribute spend, set budgets and alerts, tune routing in operation under a quality check, measure caches and report cost per successful outcome. Engine optimisation is in DEV-INF-401; model choice and prompt layout are in DEV-LLM-303.

Learning outcomes

By the end, the participant can:

  1. Applied

    Compute request cost and cost per successful outcome from tokens, tool calls and retries.

    Given usage traces and a price sheet.

    Evidence a cost model reconciled with an invoice within 2%.

  2. Applied

    Configure gateway keys per team, environment tags and spend limits.

    Given a shared gateway and three applications.

    Evidence a showback table and a hard limit that stops an application.

  3. Performance

    Optimise a gateway routing policy so each request class meets its quality floor at lower cost.

    Given three model tiers and a month of replayed, labelled traffic.

    Evidence realised savings and quality per class with intervals, and a tested budget fallback.

  4. Performance

    Evaluate exact, prefix and semantic caches for savings, staleness and cross-tenant leakage.

    Given replayed traffic from two tenants.

    Evidence measured hit rates and a passing isolation test.

  5. Applied

    Prepare a unit-economics report with trend, forecast, energy use and savings options.

    Given the month of traces and a budget owner's questions.

    Evidence a two-page report a peer budget owner can decide from.

Topics

The cost model

  • Prefill, decode and cached tokens
  • Retries, agent steps and long contexts
  • Accelerator hours and utilisation

Attribution and budgets

  • Keys and tags per team
  • Showback before chargeback
  • Spend anomaly alerts
  • Unsettled allocation for agents

Routing and caching

  • Request classes, cascades and fallbacks
  • Measured cache hit rates
  • Staleness and tenant isolation

Reporting value

  • Cost per successful outcome
  • Forecasting spend
  • Energy beside money

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Gateway with budgets and routing
LiteLLM, Agent Router
Usage analysis
DuckDB, pandas
Cache stores
Valkey, PostgreSQL with pgvector
Quality checks and cluster cost allocation
promptfoo or Inspect, OpenCost

How the work is assessed

  • Supervised check: compute costs and cache savings by hand (15%)
  • Graded labs (40%)
  • Capstone memo and defence (45%)
To pass
70% overall and 60% on the supervised check

Use of AI in the course

AI-off for the supervised check. AI-tutor in the labs. AI-full in the capstone, defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
