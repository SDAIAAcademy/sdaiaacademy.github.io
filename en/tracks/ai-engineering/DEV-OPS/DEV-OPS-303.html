DEV-OPS-303 Operating AI Agents: Durable Execution, Sandboxing and Replay

  • Level 300 · Develop
  • Workshop
  • 16 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-OPS Operations and Reliability

Level

Level 300 · Develop

Audience

practitioner

Format

Workshop: two days with labs and an operations shift

Total hours

16 h

Prerequisites

  • DEV-AGT-301 Agentic Systems Engineering: Loops, Context and Harnesses
  • DEV-OPS-302 Operating Language Model Applications: Tracing, Evaluation Gates and Safe Releases
  • DEV-AGT-402, or has run agents on a durable workflow engine

Description

Participants operate a small agent fleet on a provided cluster. They version each agent as one bundle, keep durable sessions alive through crashes and upgrades, test that tools are safe to retry, run sandboxes with quotas and egress policies, replay recorded traces to reproduce incidents, and throttle or stop agents at a gateway. Platform construction is in DEV-AGT-402.

Learning outcomes

By the end, the participant can:

  1. Applied

    Implement an agent bundle that pins model, prompts, tool schemas, skills and harness settings.

    Given an agent changed by an unrecorded skill edit.

    Evidence a versioned bundle and a trace diff naming the edit.

  2. Applied

    Test tool idempotency by injecting crashes, timeouts and duplicate deliveries.

    Given a durable workflow with one tool unsafe to retry.

    Evidence a rerun with no duplicate side effects after the fix.

  3. Performance

    Diagnose an agent failure by replaying its recorded trace against two versions.

    Given a failing session with captured tool responses.

    Evidence a deterministic reproduction and a root-cause note.

  4. Performance

    Decide whether to drain, pin or migrate in-flight sessions for an upgrade, then carry it out.

    Given 20 running sessions and a breaking schema change.

    Evidence a log in which every session finishes or is handed back.

  5. Applied

    Configure per-agent rate and spend limits, tool allowlists and a kill switch.

    Given a gateway in front of models and tools.

    Evidence a runaway agent stopped within a stated time, with audit entries.

Topics

Versioning agents

  • Session, harness and sandbox split
  • The agent bundle
  • In-flight sessions during upgrades

Durable execution

  • Checkpoints and orphaned sessions
  • Idempotency keys and duplicates
  • Approval waits and timeouts
  • Health signals: steps, tool errors, stuck sessions

Sandboxes and controls

  • Warm pools, quotas and egress policies
  • Rate, spend and step budgets
  • Kill switches and runbooks

Replay

  • Recorded tool responses
  • Replay for reproduction and regression

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Durable execution
Temporal, a state-graph framework with a checkpointer
Agent sandbox
Kubernetes agent-sandbox with gVisor, OpenSandbox
Agent gateway
agentgateway, Agent Router
Tracing and fault injection
Langfuse or Arize Phoenix, Toxiproxy or Chaos Mesh

How the work is assessed

  • Supervised check: locate a failure in a workflow history (15%)
  • Graded labs (40%)
  • Operations shift (45%)
To pass
70% overall and 60% on the supervised check

Use of AI in the course

AI-off for the supervised check. AI-tutor in the labs. AI-full in the shift, explained live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
