DEV-OPS-201 Deploying AI Services: Containers, Serving and Monitoring

  • Level 200 · Apply
  • Intensive
  • 30 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-OPS Operations and Reliability

Level

Level 200 · Apply

Audience

practitioner

Format

Intensive: 4 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

30 h

Prerequisites

  • Writes and runs Python scripts from the command line
  • Uses Git and a Python virtual environment, as taught in FND-PRG-102
  • Has called an HTTP API and read a JSON response
  • Loads a saved model in Python and calls it for predictions

Description

Participants take a tabular classifier and a small open-weight language model from a notebook to a service that other people can call. They package each in a container image with pinned dependencies, serve it behind a typed HTTP API with validation and health checks, add structured logs, metrics and alerts, and release a new version through a staged rollout that they reverse when a health signal fails. Labs run on a laptop with 16 GB of memory, or on a provided lab virtual machine where a laptop cannot run containers.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Distinguish batch, online and streaming inference and the signals that matter for each.

    Given four described use cases.

    Evidence a decision table matching the reference on three of four rows.

  2. Applied

    Package a model as a reproducible container image with pinned dependencies and no secrets inside.

    Given a trained tabular model and its notebook.

    Evidence an image that builds from a clean checkout and reproduces the notebook's predictions.

  3. Applied

    Implement a serving endpoint with input validation, timeouts, a concurrency limit and health checks.

    Given the packaged model and a small language model on a local server.

    Evidence a passing contract test suite, including overload and malformed-input cases.

  4. Applied

    Configure structured logs, request metrics and two alerts with documented thresholds.

    Given the service under a provided load script.

    Evidence a dashboard export and an alert that fires on a seeded fault.

  5. Performance

    Deliver a new version through a health-gated staged rollout and roll it back when a signal degrades.

    Given a defective version on a single-node cluster.

    Evidence a run log showing rollback within the stated recovery time.

  6. Applied

    Prepare a runbook with versions, artefact hashes, owner, alerts and rollback steps.

    Given the participant's deployed service.

    Evidence a peer redeploys and rolls back the service from it unaided.

Topics

From notebook to service

  • Batch, online and streaming inference
  • Service contracts
  • Latency, throughput and cost as requirements

Packaging

  • Images, layers and multi-stage builds
  • Pinned dependencies
  • Secrets out of images; image scanning

Serving

  • Typed APIs and input validation
  • Timeouts, retries and concurrency limits
  • A small language model behind a standard chat-completions interface
  • Health, readiness and warm-up

Observability basics

  • Structured logs and correlation identifiers
  • Latency, traffic, errors and saturation
  • Tokens and time to first token
  • Personal data kept out of logs

Releasing

  • Immutable, versioned artefacts
  • Deployments, services and probes on a single-node cluster
  • Rolling and blue-green updates
  • Rollback drills and runbooks

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Containers and a single-node cluster
Podman or Docker, kind or k3s
Serving framework and local model runtime
FastAPI, Ray Serve, llama.cpp server
Metrics, logs and dashboards
OpenTelemetry, Prometheus, Grafana
Image and secret scanning
Trivy, gitleaks

How the work is assessed

  • Supervised check: diagnose three faults from a container file, logs and a dashboard (15%)
  • Graded labs (35%)
  • Capstone on a five-criterion rubric (40%)
  • Live recovery (10%)
To pass
70% overall, 60% on the supervised check, and a completed rollback in the live session

Use of AI in the course

AI-off for the supervised check and the first container file. AI-tutor in the labs. AI-full in the capstone, explained live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
