DEV-LLM-201 Building Applications on Language Models

  • Level 200 · Apply
  • Intensive
  • 36 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-LLM Language Model Application Engineering

Level

Level 200 · Apply

Audience

practitioner

Format

Intensive: 4 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

36 h

Prerequisites

  • Writes and tests Python that calls an HTTP API
  • Explains tokens, context windows and sampling at the depth of FND-AIC-102

Description

Participants build a language model application from the API up: provider-neutral calls, prompts kept as versioned code, structured outputs that validate, tool calling with confirmation before side effects, and answers grounded in documents with citations, all measured on a first evaluation set. One synthetic case study, a bilingual permits help desk with a policy handbook and a case database, runs through all four days.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Distinguish the chat-message, item-list and provider-neutral response shapes of model APIs.

    Given three raw request and response pairs.

    Evidence pairs annotated field by field, checked against a reference.

  2. Applied

    Implement prompts as versioned templates that keep instructions apart from untrusted user text.

    Given four tasks and 20 test inputs.

    Evidence a run log of pass rates across two revisions.

  3. Applied

    Implement structured outputs that validate against a schema, with a bounded retry and a fallback.

    Given 50 labelled synthetic citizen requests.

    Evidence schema-valid rate and field accuracy.

  4. Applied

    Configure tool calling with typed tools, recovery from tool errors and confirmation before state changes.

    Given three tools over a synthetic case database.

    Evidence passing integration tests and ten saved traces.

  5. Applied

    Measure quality, latency and cost per request for three candidate models.

    Given the evaluation set and one gateway.

    Evidence a results table and a justified model choice.

  6. Performance

    Build a grounded answering feature that cites sources and declines when the documents hold no answer.

    Given a synthetic handbook and 30 questions, some unanswerable.

    Evidence correctness, citation accuracy and refusal rate from two runs, defended live.

Topics

Model APIs without lock-in

  • Three API shapes and gateways
  • Sampling, reasoning effort and token limits
  • Streaming, retries and rate limits

Prompts and structured outputs

  • Templates, versions and diffs
  • User and retrieved text as untrusted data
  • Constrained decoding versus validate and retry

Tools

  • Tool schemas and tool errors
  • Confirmation before side effects
  • Fixed workflows before agents

Grounding

  • Prompt versus retrieval on demand
  • Keyword and embedding search over a small corpus
  • Citations and saying no answer exists

Measuring and choosing

  • Error analysis on the first traces
  • A small evaluation set from real tasks
  • Code checks and one model-graded check
  • Open-weight versus hosted models and licences

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Language model access through a provider-neutral endpoint
a locally served open-weight model, a hosted open-weight model on a free tier, any commercial API
Provider-neutral model gateway
LiteLLM, agentgateway
Schema validation and constrained output
Pydantic, Instructor, Outlines
Search over a small corpus
SQLite full-text search, Sentence Transformers with FAISS
Evaluation and tracing
promptfoo, Inspect, Langfuse

How the work is assessed

  • Supervised check without AI assistance (15%)
  • Graded labs (35%)
  • Capstone on a five-criterion rubric (40%)
  • Live defence (10%)
To pass
70% overall, 60% on the capstone and a pass on the supervised check

Use of AI in the course

AI-off for the first raw API call and the supervised check. AI-tutor in the labs. AI-full in the capstone, which the participant defends live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
