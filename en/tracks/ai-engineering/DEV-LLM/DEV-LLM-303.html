DEV-LLM-303 Model Choice, Routing and Inference Economics

  • Level 300 · Develop
  • Workshop
  • 12 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-LLM Language Model Application Engineering

Level

Level 300 · Develop

Audience

practitioner

Format

Workshop: one and a half days with labs and a costed decision memo, with guided pre-work

Total hours

12 h

Prerequisites

  • DEV-LLM-201 Building Applications on Language Models
  • Has compared two configurations of an application on an evaluation set

Description

Participants choose models with numbers. They score open and closed, small and large models at several reasoning settings on their own tasks, design a routing policy with tiers and fallbacks, arrange prompts for cache hits, and compute when self-hosting an open-weight model beats an API. The case study is a synthetic document-review application with a stated volume, quality floor and data-placement rule. Serving optimisation continues in DEV-INF-401 and production cost control in DEV-OPS-304.

Learning outcomes

By the end, the participant can:

  1. Applied

    Measure quality, latency and cost per successful task for four models at two reasoning settings.

    Given the participant's evaluation set.

    Evidence a cost-quality chart.

  2. Performance

    Design a cascade that escalates from a small model to a larger one on validation failure or low confidence, keeping quality above a floor.

    Given the measured results.

    Evidence cascade against single-model results with intervals.

  3. Applied

    Configure prompt and tool layout for prefix caching and measure the effect.

    Given a server that reports cache use.

    Evidence hit rate and cost before and after.

  4. Applied

    Compute the break-even volume between a hosted API and self-hosting.

    Given price, throughput and staffing figures.

    Evidence a cost model with sensitivity analysis.

  5. Performance

    Decide on model choice and hosting for the case-study application.

    Given a data-placement rule.

    Evidence a two-page memo defended live.

Topics

Choosing on own tasks

  • Leaderboards versus own evaluations
  • Licence, residency and deprecation risk
  • Reasoning budgets

Routing and tiers

  • Cascades and difficulty routers
  • Per-stage models
  • Cache cost of switching models

Caching

  • Prefix caching and stable layouts
  • Response caches and their risks

Self-hosting economics

  • Throughput and utilisation
  • Batch versus interactive
  • Break-even

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Model gateway with routing
LiteLLM, agentgateway
Language model access
open-weight models served locally, any commercial API
Evaluation harness
promptfoo, Inspect
Local inference server
vLLM, llama.cpp

How the work is assessed

  • Supervised check without AI assistance: compute cost per successful task (20%)
  • Graded labs (40%)
  • Decision memo with defence (40%)
To pass
70% overall and a pass on the supervised check

Use of AI in the course

AI-off for the supervised check. AI-tutor in the labs. AI-full in the memo, which the participant defends live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
