DEV-LLM-301 Model Adaptation for Applications: Fine-Tuning, Distillation and Small Models

  • Level 300 · Develop
  • Intensive
  • 36 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-LLM Language Model Application Engineering

Level

Level 300 · Develop

Audience

practitioner

Format

Intensive: 4 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

36 h

Prerequisites

  • DEV-LLM-201 Building Applications on Language Models
  • DEV-LLM-202 Applied Natural Language Processing Engineering
  • Reads a PyTorch training loop and diagnoses a loss curve
  • Compares two configurations on an evaluation set with a statistical test (DEV-EVL-301 recommended)

Description

Participants decide when adapting a model is worth it, then do it well. From error analysis of a failing extraction and function-calling feature, they build a tuning set from traces and teacher outputs, train low-rank adapters on a small open-weight model, distil a large model into it, evaluate it against the base and a larger prompted model, and serve it quantised with several adapters. Research-grade post-training is SPC-DLR-306; serving optimisation at scale is DEV-INF-401.

Learning outcomes

By the end, the participant can:

  1. Performance

    Decide whether to prompt, retrieve, fine-tune or distil to fix an application's failures.

    Given an error analysis and limits on cost, latency and data placement.

    Evidence a decision memo linking each failure to an option and its cost.

  2. Applied

    Prepare a tuning dataset with deduplication, decontamination, licence checks and personal-data removal.

    Given 500 synthetic traces and teacher outputs.

    Evidence a dataset card with split statistics.

  3. Applied

    Implement supervised fine-tuning with low-rank adapters on a small open-weight model.

    Given one free or provided accelerator.

    Evidence configuration, loss curves and adapter.

  4. Applied

    Implement distillation of a teacher's behaviour into a student by generating, filtering and training on examples.

    Given a teacher endpoint and a verifier.

    Evidence student and teacher scores and cost per request.

  5. Performance

    Evaluate an adapted model against its base and a larger prompted model on task metrics, general ability and safety behaviour.

    Given a held-out set and a regression suite.

    Evidence paired comparisons with intervals and a regression list.

  6. Performance

    Build a serving setup for a quantised small model with several adapters and measure its latency, throughput and cost.

    Given a laptop or single accelerator.

    Evidence a serving configuration and load-test report.

Topics

When to adapt

  • Prompt, retrieve, tune or distil
  • Tuning changes behaviour more than knowledge
  • What small models do and do not do reliably
  • Open-weight licences and terms of use

Data for tuning

  • Traces, teacher outputs and corrections
  • Chat templates and tool-call formats
  • Deduplication and decontamination

Adapters and distillation

  • Low-rank and quantised adapters
  • Function-calling fine-tuning
  • Teacher generation with verifier filtering

Evaluating adapted models

  • Paired comparison against the base
  • Forgetting and regressions
  • Safety behaviour after tuning
  • Arabic and English slices

Serving small models

  • Quantised formats
  • Several adapters on one base
  • Cost per thousand requests

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Small open-weight models
an instruction-tuned small model, a second small model from another family
Fine-tuning libraries
Transformers with PEFT and TRL, a plain PyTorch training loop
Model evaluation harness
lm-evaluation-harness, Inspect
Inference server
vLLM, SGLang, llama.cpp
Experiment tracking
MLflow, a versioned run log in the repository
Load testing
Locust, k6

How the work is assessed

  • Supervised check without AI assistance: diagnose loss curves and a contaminated split (15%)
  • Graded labs (30%)
  • Capstone (45%)
  • Live defence (10%)
To pass
70% overall, 60% on the capstone and a pass on the supervised check

Use of AI in the course

AI-off for the supervised check. AI-tutor in the labs. AI-full in the capstone, which the participant defends live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
