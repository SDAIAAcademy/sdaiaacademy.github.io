DEV-LLM-203 Retrieval and Knowledge Engineering for Language Model Systems

  • Level 200 · Apply
  • Intensive
  • 36 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-LLM Language Model Application Engineering

Level

Level 200 · Apply

Audience

practitioner

Format

Intensive: 4 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

36 h

Prerequisites

  • DEV-LLM-201 Building Applications on Language Models
  • Writes SQL with joins and grouping

Description

Participants build the retrieval layer of a language model system: lexical, dense and hybrid search with reranking over a bilingual corpus, an agent that chooses among search tools, a memory file kept across sessions, statistical answers through a semantic layer instead of free text-to-SQL, and filtering by the requester's permissions. The case study is a synthetic ministry knowledge base with a statistics warehouse. Retrieval evaluation in depth is in DEV-EVL-303, building semantic models in DEV-DAT-202, indexing pipelines in DEV-DAT-302 and graph retrieval in DEV-DAT-304.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Distinguish lexical, dense, hybrid, multi-vector and agentic retrieval and the query types each suits.

    Given ten sample queries.

    Evidence a decision table matching the reference on eight rows.

  2. Applied

    Implement hybrid retrieval with rank fusion and a cross-encoder reranker.

    Given the bilingual corpus and 100 labelled queries.

    Evidence recall and ranking scores at ten per configuration and language.

  3. Applied

    Configure an agent to choose among file listing, keyword, semantic and SQL search and to page large results.

    Given 20 multi-document questions.

    Evidence traces with correctness and tool calls per question.

  4. Applied

    Implement assistant access to a warehouse through a provided semantic layer, with query validation, row limits and role checks.

    Given 40 questions with reference answers and ten unsafe requests.

    Evidence answer accuracy and a log of blocked queries.

  5. Applied

    Implement permission filtering so retrieval returns only passages the requester may see.

    Given access labels for three roles.

    Evidence no leaked passage across 60 tests.

  6. Performance

    Build a knowledge assistant over documents, structured data and a memory file, and defend each choice with measurements.

    Given a cost budget per question.

    Evidence results from two runs and a live defence.

Topics

Search fundamentals

  • BM25 and inverted indexes
  • Approximate nearest-neighbour indexes
  • Rank fusion and reranking
  • Arabic morphology in lexical search

Preparing a corpus

  • Chunking by structure
  • Metadata, dates and deduplication
  • Long context versus retrieval

Agentic search and memory

  • The cheapest tool that works first
  • Query rewriting and decomposition
  • Offloading large results to files
  • Memory files and wikis: bloat and staleness

Structured data

  • Schema grounding
  • Semantic layers and governed metrics
  • Validating generated SQL

Access and trust

  • Permission filters before ranking
  • Retrieved text as untrusted input
  • Citations and source dates

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Lexical and vector search
SQLite full-text search, OpenSearch, pgvector, Qdrant, LanceDB
Embedding and reranking models
open-weight multilingual models through Sentence Transformers, any embedding API
Analytical engine
DuckDB, PostgreSQL
Semantic layer
Cube Core, Apache Ossie definitions
Agent tool interface
Model Context Protocol servers, tool calls in any agent framework
Retrieval metrics
ranx, pytrec_eval

How the work is assessed

  • Supervised check without AI assistance: rank a small set and compute recall by hand (15%)
  • Graded labs (35%)
  • Capstone (40%)
  • Live defence (10%)
To pass
70% overall, 60% on the capstone and a pass on the supervised check

Use of AI in the course

AI-off for the first BM25 implementation and the supervised check. AI-tutor in the other labs. AI-full in the capstone, which the participant defends live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
