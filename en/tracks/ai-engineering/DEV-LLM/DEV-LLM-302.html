DEV-LLM-302 Arabic and Multilingual Language Applications

  • Level 300 · Develop
  • Intensive
  • 30 h
  • Audience: practitioner

Level 300 · Develop

Format

Intensive: 3 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

30 h

Prerequisites

  • DEV-LLM-201 Building Applications on Language Models
  • DEV-LLM-202 Applied Natural Language Processing Engineering
  • Reads Modern Standard Arabic, or works in a pair with someone who does

Description

Participants make a language model application work for Arabic speakers as well as it does in English. They measure what tokenisation costs in Arabic, normalise text and identify dialects, handle code-switching and romanised Arabic, compare Arabic-first and multilingual open models, and build and calibrate their own Arabic test set with cultural criteria. The case study is a synthetic citizen-service assistant used in Modern Standard Arabic, three dialects and mixed language. Annotation operations at scale are DEV-EVL-304; Arabic speech is DEV-MLE-302.

Learning outcomes

By the end, the participant can:

  1. Applied

    Measure how tokeniser fertility changes cost, usable context and chunk sizes for standard and dialectal Arabic across target models.

    Given a parallel corpus and three target models.

    Evidence tokens per word, cost per task and usable context per model.

  2. Applied

    Implement normalisation, romanised-Arabic detection and dialect identification.

    Given labelled user messages.

    Evidence unit tests and accuracy by dialect.

  3. Applied

    Test retrieval and prompting strategies for dialectal and code-switched queries.

    Given 60 mixed queries.

    Evidence results per strategy and dialect.

  4. Performance

    Design an application test set covering standard Arabic, dialects, code-switching and cultural items.

    Given annotation guidelines and two annotators.

    Evidence a test set with a datasheet and agreement statistic.

  5. Performance

    Evaluate Arabic-first and multilingual open models on public benchmarks and on the custom set, and explain disagreements.

    Given three open models.

    Evidence per-slice results with contamination caveats.

  6. Performance

    Build a model-graded check for cultural appropriateness and calibrate it against native-speaker labels.

    Given 100 labelled outputs.

    Evidence true-positive and true-negative rates on held-out data.

Topics

Arabic as data

  • Morphology, diacritics and orthographic variation
  • Romanised Arabic and bidirectional text
  • Numerals, names and Hijri dates

Tokenisation and dialects

  • Fertility and context budgets
  • Dialect identification
  • Arabic-English mixing in queries

Open Arabic models as cases

  • Arabic-first open-weight models such as ALLaM
  • Multilingual models
  • Context limits and licences

Benchmarks and cultural evaluation

  • Arabic knowledge, exam and instruction-following benchmarks
  • Contamination and translated test sets
  • Cultural rubrics and grader calibration
  • Bias across dialects

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Arabic text processing
CAMeL Tools, Farasa
Open model access
Arabic-first and multilingual open-weight models served locally, any commercial API
Tokenisers
Hugging Face tokenizers, tiktoken
Evaluation harness
lm-evaluation-harness, LightEval, Inspect
Annotation
Label Studio, a spreadsheet with an agreement script

How the work is assessed

  • Supervised check without AI assistance: normalise and label mixed Arabic text (15%)
  • Graded labs (30%)
  • Capstone (45%)
  • Live defence (10%)
To pass
70% overall, 60% on the capstone and a pass on the supervised check

Use of AI in the course

AI-off for the supervised check and for native-speaker labelling. AI-tutor in the labs. AI-full in the capstone, which the participant defends live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
