DEV-SWE-204 Testing and Verification of AI-Assisted Code

  • Level 200 · Apply
  • Workshop
  • 16 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-SWE Software Engineering for AI Builders

Level

Level 200 · Apply

Audience

practitioner

Format

Workshop: two days with labs and a short build project, with guided pre-work

Total hours

16 h

Prerequisites

  • FND-PRG-104 Software Testing, Code Review and Documentation
  • Has used a coding agent

Description

Participants build the checks that decide whether agent-written code is accepted. On a synthetic, mostly agent-written fee-calculation library, they write and protect acceptance tests before delegating, add property-based and mutation testing, wire code, dependency and secret scanning into continuous integration, and size review effort to agent volume. Application-level security is DEV-SEC-201.

Learning outcomes

By the end, the participant can:

  1. Applied

    Prepare acceptance tests before delegating and protect them from agent edits.

    Given a feature request and a coding agent.

    Evidence a seeded attempt to edit a protected test, blocked by a hook or pipeline.

  2. Applied

    Implement property-based tests that find defects example tests miss.

    Given a date and fee module with seeded edge-case defects.

    Evidence properties exposing two defects with shrunk counterexamples.

  3. Applied

    Measure suite strength with mutation testing and kill surviving mutants.

    Given a suite with high line coverage.

    Evidence mutation scores before and after, survivors justified.

  4. Applied

    Configure code, dependency and secret scanning and triage findings.

    Given seeded unsafe patterns, a vulnerable dependency and a planted key.

    Evidence a triage file with true findings fixed and false positives justified.

  5. Performance

    Build a verification pipeline that accepts a correct agent change and rejects faulty ones.

    Given one correct and four faulty unseen changes.

    Evidence pipeline logs and a review plan with reviewer hours per risk tier.

Topics

Tests as the contract

  • Test-first delegation
  • Characterisation tests before agent refactoring
  • Protected tests and hooks
  • Agents that skip, weaken or hard-code tests

Stronger tests

  • Properties and shrinking
  • Mutation testing: why coverage is not strength

Security of generated code

  • Common flaws in generated code
  • Static analysis and secret detection
  • Dependencies, licences and invented package names

Review capacity

  • Review depth by risk tier
  • Small, stacked changes
  • Agent review as a first pass only

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Test runner and property-based testing
pytest, Hypothesis, fast-check
Mutation testing
mutmut, Stryker
Static, dependency and secret scanning
Semgrep, Bandit, OSV-Scanner, Gitleaks
Continuous integration
Forgejo Actions, GitLab CI, GitHub Actions

How the work is assessed

  • AI-off check: find the defect and missing test in three diffs (20%)
  • Labs (35%)
  • Capstone pipeline (30%)
  • Live defence (15%)
To pass
60% overall, and the pipeline accepts the correct change and rejects at least three of four faulty ones

Use of AI in the course

AI-off for the supervised check and first properties in lab 2. AI-tutor in labs 3 and 4. AI-full in lab 1 and the defended capstone.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
