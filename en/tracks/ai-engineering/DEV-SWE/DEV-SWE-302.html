DEV-SWE-302 Agent-Ready Engineering Organisations: Parallel Agents, Review and Governance

  • Level 300 · Develop
  • Workshop
  • 16 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-SWE Software Engineering for AI Builders

Level

Level 300 · Develop

Audience

practitioner

Format

Workshop: two days with labs and a short build project, with guided pre-work

Total hours

16 h

Prerequisites

  • DEV-SWE-201 Software Engineering with Coding Agents
  • DEV-SWE-204 Testing and Verification of AI-Assisted Code
  • Reviews work in a team repository with continuous integration

Description

Participants set up how a team works with coding agents. On a synthetic repository with twelve open issues, they run background agents in parallel, version and evaluate the shared harness of context files, skills and hooks, set permission tiers and release lanes, size review queues to capacity, and measure delivery honestly.

Learning outcomes

By the end, the participant can:

  1. Applied

    Configure parallel background agents on isolated workspaces with a merge and conflict policy.

    Given a backlog of twelve issues.

    Evidence run logs and a merged history with every merge passing checks.

  2. Applied

    Configure permission tiers, sandboxing and an egress allowlist for team agents.

    Given an issue carrying an injected instruction.

    Evidence tests in which forbidden actions and the exfiltration attempt are blocked.

  3. Performance

    Design a versioned team harness with an owner, a changelog and a regression task set.

    Given two candidate harness versions.

    Evidence an evaluation run comparing them, with a recommendation.

  4. Performance

    Design release lanes and a review-queue policy that route changes by risk and fit reviewer capacity.

    Given a synthetic month of pull-request events.

    Evidence a queue simulation showing wait times and expected escaped defects.

  5. Performance

    Evaluate claims about agent productivity using delivery measures with stated uncertainty.

    Given logs from before and after an agent rollout.

    Evidence a one-page memo on lead time, change failure rate, rework, review latency and token spend.

Topics

Parallel agents

  • Steer, queue and notify
  • Worktrees and containers per task
  • Agents per reviewer

The harness as a product

  • Ownership and versioning
  • Evaluating harness changes
  • Removing instructions models no longer need

Permissions and lanes

  • Approval fatigue
  • Sandboxes, egress control and audit trails
  • Agentic, supervised and assisted lanes

Review and measurement

  • Risk-tiered queues
  • Oversight in name only
  • Why throughput counts mislead
  • Token spend per merged change

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Coding agents with background modes
OpenCode, goose, Claude Code, Codex
Isolation and configuration
git worktrees, dev containers, AGENTS.md, Agent Skills
Analysis and simulation
pandas, SimPy

How the work is assessed

  • AI-off check: interpret delivery and queue data (15%)
  • Labs (35%)
  • Capstone playbook (30%)
  • Live defence (20%)
To pass
60% overall and at least 60% on the capstone

Use of AI in the course

AI-off for the supervised check. AI-full in labs and the defended capstone, with the participant answerable for each merged change.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
