DEV-DAT-202 Analytics Engineering and Semantic Layers

  • Level 200 · Apply
  • Intensive
  • 30 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-DAT Data Engineering and Architecture

Level

Level 200 · Apply

Audience

practitioner

Format

Intensive: 4 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

30 h

Prerequisites

  • DEV-DAT-201 Modern Data Engineering
  • Uses Git to branch, commit and open a review

Description

Participants take over the analytics of a fictional online marketplace whose three dashboards report three different net-revenue figures. They define metrics once as tested code, build a semantic model of joins, dimensions and access rules over a dimensional layer, and rebuild two dashboards as version-controlled code. They then measure how often a language model answers 60 business questions correctly against the raw schema and through the semantic layer. Metric and dashboard design for analysts is SPC-ANL-203.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Explain how a semantic layer differs from a dimensional model and from a business intelligence (BI) tool's internal model.

    Given four short architecture descriptions.

    Evidence a comparison matching the reference on three of four.

  2. Applied

    Implement metric definitions as code, including ratios, time grains and filters, with tests that reconcile them to source totals.

    Given three conflicting definitions of net revenue.

    Evidence a metrics file with a decision note per metric and passing tests.

  3. Applied

    Configure a semantic model with entities, joins, dimensions and row-level access rules.

    Given the marketplace marts and two user roles.

    Evidence semantic queries returning the reference figures for each role.

  4. Applied

    Prepare dashboards as code that read only from the semantic layer and ship through review.

    Given a repository with continuous integration.

    Evidence a merged change in which one metric edit updates both dashboards.

  5. Applied

    Measure the execution accuracy of natural-language querying with and without the semantic layer.

    Given 60 questions with reference answers and a fixed model.

    Evidence a report with accuracy by question type, error categories and intervals.

  6. Performance

    Decide which questions may be routed to natural-language querying, and under which safeguards.

    Given the evaluation and a stated tolerance for wrong figures.

    Evidence a decision memo defended in review.

Topics

Metrics as code

  • Layered models reviewed through continuous integration
  • Simple, ratio, cumulative and derived metrics
  • Grain, time spines and fan-out traps
  • Reconciliation tests, documentation and ownership

Semantic models

  • Entities, joins and dimensions
  • Access rules and classification-aware fields
  • Pre-aggregation, caching and query cost
  • Open interchange specifications and portability

Dashboards as code

  • Version-controlled definitions
  • Certified versus exploratory content

Natural-language querying

  • Text-to-SQL failure modes
  • Context from semantic layer, glossary and examples
  • Execution accuracy and safeguards

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Transformation framework
SQLMesh, dbt
Semantic layer and interchange format
Cube Core, the transformation framework's semantic layer, Apache Ossie (incubating) definitions
Analytical engine
DuckDB, PostgreSQL
Dashboards as code
Apache Superset with versioned exports, Markdown-and-SQL report generators
Language model under test, behind a standard chat API
a locally served open-weight model, a hosted model on a free tier
Continuous integration
GitHub Actions, GitLab CI

How the work is assessed

  • Supervised AI-off check: write and debug metric SQL with fan-out traps (20%)
  • Graded labs (30%)
  • Capstone repository and decision memo on a five-criterion rubric (50%)
To pass
70% overall and at least 60% on both the check and the capstone

Use of AI in the course

AI-off for the supervised check and the reconciliation lab. AI-tutor in the other labs; the model in the querying lab is the system under test. AI-full in the capstone, defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
