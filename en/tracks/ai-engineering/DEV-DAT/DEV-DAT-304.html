DEV-DAT-304 Knowledge Graphs and Ontology Engineering

  • Level 300 · Develop
  • Workshop
  • 16 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-DAT Data Engineering and Architecture

Level

Level 300 · Develop

Audience

practitioner

Format

Workshop: two days with labs and a short graded build

Total hours

16 h

Prerequisites

  • Has designed a normalised relational schema (DEV-DAT-301 or equivalent)
  • Has called a language model API from Python

Description

Participants build a knowledge graph from two synthetic registries and a set of Arabic and English documents. They resolve duplicate entities, write an ontology from competency questions with public vocabularies, validate it with shape constraints, admit language-model-extracted facts only after validation and with provenance, and compare graph-grounded with text-only retrieval on multi-hop questions.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Distinguish Resource Description Framework (RDF) graphs, property graphs and relational models, and state when each fits.

    Given three use cases.

    Evidence a decision note matching the reference on two of three cases.

  2. Applied

    Apply entity resolution with blocking, scoring and clustering, and measure its precision and recall.

    Given 5,000 records with Arabic transliteration variants.

    Evidence clusters, precision and recall figures and a review queue.

  3. Performance

    Design an ontology and shape constraints that answer competency questions.

    Given ten competency questions.

    Evidence a clean validation report and one passing query per question.

  4. Applied

    Implement language-model extraction of facts into the graph with validation and source provenance.

    Given 200 documents.

    Evidence accepted facts with source spans, a rejection log and sampled precision.

  5. Performance

    Evaluate graph-grounded against text-only retrieval and recommend one.

    Given 40 multi-hop questions with answers and a text-only baseline.

    Evidence accuracy, cost and latency per question with a recommendation.

Topics

Graph models

  • Triples, identifiers and property graphs
  • SPARQL, Cypher and ISO Graph Query Language
  • When a relational model is enough

Entity resolution

  • Arabic transliteration and normalisation
  • Blocking, scoring, clustering and human review

Ontology engineering

  • Competency questions
  • Reusing SKOS, schema.org and PROV-O
  • Shapes Constraint Language (SHACL) validation

Using graphs

  • Validated extraction with provenance
  • Graph-grounded retrieval and paths as explanations
  • Ontology versioning as sources change

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Ontology and RDF store
Protégé, Apache Jena Fuseki, RDFLib
Property graph database
Apache AGE, Neo4j Community Edition
Validation and entity resolution
pySHACL, Splink, Zingg
Extraction model
a local open-weight model, any hosted API

How the work is assessed

  • Supervised check on graph models and a SPARQL query (20%)
  • Graded labs (40%)
  • Short build and review (40%)
To pass
70% overall and a pass on the supervised check

Use of AI in the course

AI-off for the supervised check and the first ontology draft. AI-tutor in the other labs. AI-full in the short build, defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
