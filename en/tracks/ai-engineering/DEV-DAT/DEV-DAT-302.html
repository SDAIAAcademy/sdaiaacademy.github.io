DEV-DAT-302 Data Infrastructure for AI

  • Level 300 · Develop
  • Intensive
  • 36 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-DAT Data Engineering and Architecture

Level

Level 300 · Develop

Audience

practitioner

Format

Intensive: 4 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

36 h

Prerequisites

  • DEV-DAT-201 Modern Data Engineering
  • Has called an embedding or language model API from Python

Description

Participants build the data layer that language model applications and agents read from, and run it as a pipeline rather than a one-off index. On a synthetic bilingual municipal corpus with a change feed, they embed incrementally, carry source permissions onto every chunk, propagate deletions, gate personal data, migrate embedding models and expose governed tables to an agent through a protocol server. Parser choice is DEV-LLM-204, search quality DEV-LLM-203, retrieval evaluation DEV-EVL-303 and graphs DEV-DAT-304.

Learning outcomes

By the end, the participant can:

  1. Applied

    Implement an incremental pipeline that parses, chunks and embeds documents and reprocesses only what changed.

    Given 2,000 Arabic and English documents with a feed of edits and deletions.

    Evidence a second run log touching only changed documents, and no orphaned chunks.

  2. Applied

    Configure a parsing stage that routes by document class, falls back to deterministic extraction and quarantines failures.

    Given three document classes, including scanned forms.

    Evidence a routing rule and a successful replay of quarantined documents.

  3. Performance

    Design an index whose chunks and vectors trace to source, version and permissions, and migrate it to a new embedding model.

    Given a 50-question retrieval check set.

    Evidence a dual-index migration run with check-set scores before and after cut-over.

  4. Performance

    Build permission-aware indexing that copies source access rules onto chunks and filters before ranking.

    Given group-based access lists and seeded leak tests.

    Evidence a passing leak suite, including after a permission is revoked at source.

  5. Applied

    Measure personal-data detection before indexing and set a redaction rule per entity type.

    Given planted Arabic and English names, identifiers and addresses.

    Evidence recall per entity type and a residual-risk note.

  6. Performance

    Build a protocol server that gives an agent read-only, scoped access to governed tables and metrics.

    Given a provided catalogue of classified tables and a semantic layer.

    Evidence an agent transcript with refused out-of-scope requests and the matching audit log.

Topics

Unstructured data as a pipeline

  • Change feeds and idempotent reprocessing
  • Parsing routes and deterministic fallback
  • Chunking as a versioned transform
  • Quarantine and replay

Embeddings and indexes as derived data

  • Multilingual embedding choice
  • Vectors in a relational database, table format, search service or object store
  • Hybrid index refresh and dual-index migration

Permissions, deletion and lineage

  • Source access lists to chunk labels
  • Filtering before ranking
  • Erasure that reaches derived data

Personal data and external services

  • Detectors and what they miss
  • Redaction and pseudonymisation at indexing
  • Data sent to external model services
  • Prompt and trace logs as governed data

Governed agent access

  • Protocol servers over a catalogue and semantic layer
  • Read-only tools, scopes and audit logs
  • When a plain API or command-line tool is enough

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Document parsing
Docling, Unstructured
Vector and hybrid search storage
PostgreSQL with pgvector, LanceDB, Qdrant
Embedding models
a local open-weight multilingual model, any hosted embedding API
Orchestration and lineage
Dagster, Apache Airflow, OpenLineage
Personal-data detection
Presidio, custom rule detectors
Protocol server
Model Context Protocol SDKs, FastMCP

How the work is assessed

  • Supervised check on index design and log reading (15%)
  • Graded labs (35%)
  • Capstone and defence (50%)
To pass
70% overall, 60% on the capstone and a pass on the supervised check

Use of AI in the course

AI-off for the supervised check. AI-tutor in the first three labs. AI-full in the last two labs and the capstone, with transcripts kept and the result defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
