DEV-DAT-201 Modern Data Engineering

  • Level 200 · Apply
  • Intensive
  • 36 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-DAT Data Engineering and Architecture

Level

Level 200 · Apply

Audience

practitioner

Format

Intensive: 4 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

36 h

Prerequisites

  • FND-DAT-101 SQL and Relational Data
  • FND-PRG-102 Command Line, Git and Reproducible Environments
  • Writes Python scripts that read and write files

Description

Participants build one batch pipeline end to end for a fictional trading company whose margin report nobody trusts. They query raw extracts with analytical SQL, load an API and a database change feed incrementally, and model a star schema with a slowly changing supplier dimension. Tested transformations and an agreed data contract run under an orchestrator, and the result lands in an open table format that a second engine reads. All data is synthetic and deterministic. Log-based capture and streaming continue in DEV-DAT-203; contract versioning and observability in DEV-DAT-204.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Distinguish transactional, warehouse, lake and lakehouse platforms and the workloads each serves.

    Given five described workloads.

    Evidence a placement table matching the reference on four of five.

  2. Applied

    Analyse raw extracts with window functions, deduplication and incremental predicates in analytical SQL.

    Given extracts with duplicates and late records.

    Evidence a notebook reproducing ten reference figures.

  3. Applied

    Implement idempotent incremental loads from an API and a change feed, applying merges with type 2 history.

    Given a paginated API and a repeated run of the same load.

    Evidence run logs with identical counts and history after the repeat.

  4. Applied

    Implement a dimensional model as version-controlled transformations with tests and documentation.

    Given staging tables and the margin requirement.

    Evidence passing tests and generated documentation showing lineage.

  5. Applied

    Draft a data contract in an open standard and enforce it in the build.

    Given a consumer's requirements and a seeded breaking change.

    Evidence a contract file and a build that fails on the change.

  6. Performance

    Build an orchestrated pipeline into an open table format that recovers from failure by re-running.

    Given an injected mid-run failure.

    Evidence run history with the failure, a clean retry and a second engine reading the snapshot.

Topics

Platform shapes and analytical SQL

  • Transactional versus analytical systems; extract, load, transform (ELT)
  • Layered raw, cleaned and served zones
  • Window functions and incremental predicates
  • Columnar files and partitioning

Ingestion and change

  • Schema drift and idempotent loads
  • Change data capture (CDC), merge and slowly changing dimensions
  • Single-node first, distributed when measured
  • Classifying fields and dropping what is not needed

Modelling, transformation and contracts

  • Grain, facts and dimensions
  • Tests, environments and state-aware builds
  • Open contract standards
  • Verifying agent-written transformations

Orchestration and table formats

  • Retries, backfills and data-aware scheduling
  • Snapshots, schema evolution, time travel and compaction
  • Catalogues and multi-engine reads

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Single-node analytical engine
DuckDB, Polars
Ingestion
dlt, plain Python with stored load state
Transformation framework and dataframe checks
SQLMesh, dbt, Pandera
Data contract specification
Open Data Contract Standard (ODCS), contract checks compiled to SQL tests
Orchestrator
Dagster, Apache Airflow, Kestra
Open table format and catalogue
Apache Iceberg with a REST catalogue, Delta Lake, DuckLake
Distributed engine (demonstration)
Apache Spark, Trino

How the work is assessed

  • Supervised AI-off check: SQL and merge logic on short excerpts (20%)
  • Graded labs (30%)
  • Capstone repository on a five-criterion rubric with defence (50%)
To pass
70% overall and at least 60% on both the check and the capstone

Use of AI in the course

AI-off for the supervised check and the first SQL lab. AI-tutor in the other labs. AI-full in the capstone, where the participant reviews and defends any agent-written code.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
