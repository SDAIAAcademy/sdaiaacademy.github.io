DEV-PHY-201 Sensors, Perception and Compute for Physical AI

  • Level 200 · Apply
  • Workshop
  • 16 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-PHY Physical AI and Robotics Engineering

Level

Level 200 · Apply

Audience

practitioner

Format

Workshop: two lab days on a shared sensor kit and a tracked follow-up task

Total hours

16 h

Prerequisites

  • Writes Python with NumPy on Linux
  • Uses rotation matrices and Gaussian noise (FND-MTH-101, FND-MTH-103)
  • Has run a pretrained image model

Description

On a kit with a colour camera, a depth camera, an inertial measurement unit (IMU) and a single-board computer, participants measure sensor noise, calibrate the camera-IMU pair, record synchronised streams, fuse inertial data into an orientation estimate and run a quantised detector within a latency budget, ending with a node that reports object positions in 3D.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Explain how cameras, depth sensors and inertial units measure, and the main error sources of each.

    Given recordings from four sensors.

    Evidence an error table checked against a reference.

  2. Applied

    Calibrate camera intrinsics and the camera-IMU extrinsics and time offset.

    Given a target recording and an accepted error threshold.

    Evidence a calibration report with reprojection error under the threshold.

  3. Applied

    Implement synchronised recording and an inertial orientation filter with consistent frames.

    Given a public visual-inertial sequence with ground truth.

    Evidence a replayable log and an error plot against ground truth.

  4. Applied

    Measure the end-to-end latency of a quantised detector on embedded compute, stage by stage.

    Given a latency budget.

    Evidence per-stage latency percentiles and the change that met the budget.

  5. Performance

    Build a real-time node that reports 3D positions of one object class from colour and depth images.

    Given the calibrated kit and a stated rate.

    Evidence a running node with measured rate, latency and position error.

Topics

Sensors and their errors

  • Pinhole model, distortion and shutters
  • Stereo, structured-light, time-of-flight and lidar depth
  • IMU bias, noise and drift

Calibration, time and frames

  • Target-based calibration
  • Camera-IMU extrinsics and time offset
  • Timestamps, synchronisation and transforms

Fusion

  • Complementary and Kalman filters
  • Back-projecting detections with depth
  • Visual-inertial odometry and mapping in brief

Real-time perception on embedded compute

  • Latency budgets from motion to decision
  • Quantised models in an interchange format
  • Dropped frames and thermal throttling

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Middleware and logging
ROS 2 with MCAP logs, Python with Rerun
Calibration and geometry
OpenCV, Kalibr
Edge inference runtime
ONNX Runtime, OpenVINO, LiteRT
Sensor kit (provided)
accelerator board with stereo camera, GPU module with time-of-flight camera

How the work is assessed

  • Supervised check without AI: interpret a calibration report and an IMU plot (20%)
  • Graded labs (40%)
  • Capstone with live demonstration (40%)
To pass
70% overall, 60% on the supervised check, and a capstone within budget

Use of AI in the course

AI-off for the supervised check and first calibration; AI-tutor in labs; AI-full in the capstone, explained live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
