Prerequisites

  • AE-301 Applied Natural Language Processing Engineering

Badge

Helps prepare for the SDAIA AI Engineering badge, Expert level.

Description

Participants build and evaluate applications that see, listen and speak, with Arabic as the main case. For the fictional Heritage Trails Authority they extract grounded fields from visitor and ranger photos with vision-language models, benchmark open-weight speech recognisers on dialects and code-switched speech, test synthesised read-back, and assemble a bilingual voice booking line with turn-taking, interruption and tool calls within a latency budget. They test it with simulated callers and choose between open-weight and hosted, cascaded and speech-to-speech designs on measured quality, latency and cost. Photos are public-domain or synthetic; calls use synthetic voices and public speech corpora.

Learning outcomes

By the end, the participant can:

  1. Applied

    Implement image applications with vision-language models that return validated structured fields grounded in the image.

    Given 60 visitor and ranger photos with reference fields and boxes.

    Evidence an extraction pipeline with field accuracy and grounding scores on the test set.

  2. Performance

    Evaluate speech recognisers on Arabic dialects and code-switched speech with explicit normalisation rules.

    Given two open-weight recognisers and a sliced set of public and synthetic clips.

    Evidence an error-rate report by dialect and channel with intervals and the normalisation rules used.

  3. Performance

    Build a bilingual voice agent that handles turn-taking, interruption and confirmed tool calls within a latency budget.

    Given a booking tool and a budget for time to first audio.

    Evidence a running agent with per-stage latency traces from twenty scripted calls.

  4. Performance

    Diagnose failure modes specific to image and audio inputs, including invented objects, text produced on silence and instructions hidden in images.

    Given seeded failing inputs for each modality.

    Evidence a failure log with causes and a mitigation tested for each mode.

  5. Performance

    Design a multimodal test set and an end-to-end evaluation with simulated callers.

    Given the full booking and reporting system.

    Evidence a test set with a coverage table across modality, dialect and task, and graded results.

  6. Performance

    Decide between open-weight and hosted, cascaded and speech-to-speech designs on quality, latency and cost per call.

    Given measured results for two pipelines.

    Evidence a one-page decision record with the measurements and a script that a reviewer re-runs to the same figures.

Topics

Vision-language models in applications

  • Visual tokens, resolution and cost
  • Structured extraction from photos
  • Grounding with boxes and points
  • Frames from video
  • Instructions hidden in images

Speech recognition

  • Recogniser families and multilingual encoders
  • Arabic normalisation of diacritics, letter variants and numerals
  • Dialects, code-switching and telephone audio
  • Streaming, voice activity detection, diarisation and text on silence

Synthesis and voice agents

  • Read-back of names, numbers and dates
  • Cascaded, speech-to-speech and full-duplex designs
  • End-of-turn detection and interruption
  • Latency budgets and tool calls during speech

Evaluation

  • Multimodal test sets
  • Error rates with intervals by slice
  • Simulated callers
  • Cost per call

Responsible voice and image handling

  • Voice and faces as personal data
  • Consent, retention and minimisation
  • Disclosure of synthetic voices

Day by day

Four sessions a day. Each session presents the concepts with a demonstration, then ends in a lab.

#SessionLab
Day 1 Seeing
1.1How a vision-language model seesMeasure tokens, latency and accuracy for one question at three image resolutions
1.2Structured extraction from photosExtract validated incident fields from 30 photos with an open-weight and a hosted model
1.3Grounding answers in pixelsScore returned boxes against references and flag answers about objects that are not there
1.4Arabic text and hidden instructionsRead Arabic signage images, compute character error rate and test an image carrying an injected instruction
Day 2 Listening
2.1From waveform to textRun two open-weight recognisers on 50 clips and compute word error rates
2.2Normalisation decides the error rateApply Arabic normalisation rules to provided transcripts and recompute the error rates
2.3Dialects and code-switchingSlice error rates by dialect and by code-switched speech and add intervals
2.4Streaming and silenceStream recognition with voice activity detection and catch text produced on silent segments
Day 3 Speaking
3.1Synthesis and read-backSynthesise booking confirmations and run a short listening test on names, numbers and dates
3.2Cascaded versus speech-to-speechTrace per-stage latency of a cascaded agent and compare time to first audio with provided traces of a speech-to-speech session
3.3Turn-taking and interruptionTune end-of-turn detection on scripted calls and count false cut-ins and missed turns
3.4Tool calls during speechAdd a booking tool to a provided agent that confirms key fields aloud and measure the added latency
Day 4 Evaluating and choosing
4.1Multimodal test setsBuild a 60-item test set across image, audio and dialects with a coverage table
4.2Simulated callersRun 20 simulated calls against a provided agent and grade task success and transcript errors
4.3Choosing by quality, latency and costCompare open-weight and hosted pipelines on provided measurements and draft the decision record
4.4Voice, faces and consentWrite the data-handling note for recordings and photos and the synthetic-voice disclosure callers hear

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Vision-language model access
an open-weight model on a notebook GPU, a hosted model through a chat-completions style endpoint
Open-weight speech recognition
Whisper-family models, wav2vec-family encoders
Voice activity detection and diarisation
Silero VAD, pyannote.audio
Speech synthesis and speech-to-speech
an open-weight text-to-speech model, any hosted real-time speech model
Voice agent framework
Pipecat, LiveKit Agents
Error-rate scoring
jiwer, a custom scorer with Arabic normalisation
Public data
Mozilla Common Voice, public-domain image collections
Evaluation harness
Inspect, pytest with custom scorers

How the work is assessed

  • Supervised check without AI assistance: compute error rates under two normalisation rules and diagnose three failing inputs (20%)
  • Capstone repository scored on a rubric: image pipeline 20, speech evaluation 25, voice agent 25, test set and simulation 20, decision record 10 (60%)
  • Live defence with a call or image the assessor supplies (20%)
To pass
70% overall and at least 60% on the capstone rubric

Use of AI in the course

AI-off for the supervised check and the day 2 normalisation lab. AI-tutor in the other labs: the assistant hints and does not write pipelines or scorers. AI-full in the capstone, which the participant defends live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
