Badge

Helps prepare for the SDAIA AI Engineering badge, Assistant level.

Description

Participants build and evaluate a tabular prediction model the way an engineer would ship it. On synthetic appointment data from a fictional clinic network they frame the prediction, prepare features inside a pipeline, set a baseline, move to regularised linear models and boosted trees, choose a validation scheme that matches time and patient grouping, find and remove planted leakage, pick metrics and a threshold from the cost of each error, analyse errors by slice, and compare two models with an interval rather than a single score. Every result is reproduced from a script with a fixed seed.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Distinguish random, grouped and time-ordered validation and state which one each described prediction task requires.

    Given five short task descriptions with their data-collection process.

    Evidence a table with the chosen scheme and a one-line reason per task, matching the reference on at least four of five.

  2. Applied

    Prepare a feature pipeline that imputes, encodes and scales inside cross-validation so that no statistic is computed on held-out rows.

    Given the clinic appointment table with missing values, dates and high-cardinality categories.

    Evidence a pipeline script that runs end to end with a fixed seed and passes a provided leakage test.

  3. Applied

    Implement a baseline, a regularised linear model and a gradient-boosted tree model and score each on the same validation splits.

    Given the prepared features and a time-ordered split.

    Evidence a results table with the mean and spread over folds for the three models.

  4. Applied

    Analyse a dataset for target leakage and train-test contamination and remove each problem found.

    Given the appointment data with three planted leaks: a column recorded after the visit, repeated patients across splits and a future aggregate.

    Evidence a leakage audit note naming each leak, how it was found and the score before and after removal.

  5. Applied

    Compute ranking, threshold and calibration metrics and choose an operating threshold from a stated cost of each error type.

    Given validation probabilities and the clinic's cost table for missed no-shows and needless reminder calls.

    Evidence a precision-recall curve, a calibration plot and the chosen threshold with its expected cost.

  6. Applied

    Analyse errors by subgroup and slice to find where the model fails, then test one data or feature change aimed at the worst slice.

    Given validation predictions joined to clinic, age band and booking channel.

    Evidence an error table for at least three slices and the measured effect of the change on every slice.

  7. Performance

    Evaluate whether a challenger model beats the baseline using a paired comparison with a confidence interval and a stated minimum effect.

    Given two trained models, the validation folds and a minimum improvement set by the clinic.

    Evidence a one-page comparison memo whose numbers a reviewer reproduces from the repository.

Topics

Framing a prediction task

  • Target, unit and moment of prediction
  • The decision the prediction serves
  • Cost of each error type
  • Rule-based and majority baselines

Data preparation and features

  • Missing values and imputation
  • Encoding categories
  • Scaling
  • Date, lag and history features
  • Pipelines that fit only on training folds
  • Data checks before training

Model families

  • Linear and logistic regression with regularisation
  • Decision trees
  • Bagging and random forests
  • Gradient boosting
  • Bias and variance
  • Hyperparameter search
  • Feature importance and its limits

Validation and leakage

  • Holdout and k-fold
  • Grouped and time-ordered splits
  • Nested search
  • Kinds of leakage
  • Keeping a test set untouched

Metrics and thresholds

  • Confusion matrix, precision, recall and F1
  • ROC and precision-recall curves
  • Class imbalance and class weights
  • Calibration
  • Cost-based thresholds
  • Regression metrics

Error analysis and comparison

  • Slicing and subgroup error
  • Bootstrap intervals
  • Paired comparison of models
  • Minimum effect of interest
  • Multiple comparisons

Reproducible results

  • Seeds and locked environments
  • Re-running from a clean clone
  • A model card stub

Day by day

Four sessions a day. Each session presents the concepts with a demonstration, then ends in a lab.

#SessionLab
Day 1 Frame and prepare
1.1A prediction is a decision at a momentWrite the target, unit and prediction time for the no-show task and mark which columns are known at that time
1.2Baselines before modelsBuild a majority-class and a simple rule baseline and score both on a holdout
1.3Features in a pipelineAssemble imputation, encoding and scaling into one pipeline and run it inside cross-validation
1.4Time, lags and historyAdd three history features computed only from past appointments and pass a provided time-travel test
Day 2 Models and validation
2.1Linear models and regularisationFit logistic regression at five regularisation strengths and plot validation score against strength
2.2Trees and boostingTrain a random forest and a gradient-boosted model and compare training and validation scores
2.3The validation scheme decides the scoreScore one model under random, patient-grouped and time-ordered splits and explain the gap
2.4Hunting leakageFind the three planted leaks with timestamps, duplicate checks and feature importance
Day 3 Metrics and errors
3.1Metrics that match the decisionCompute precision, recall and F1 at three thresholds and the area under the precision-recall curve
3.2Calibration and thresholdsDraw a calibration plot, calibrate the boosted model and choose the threshold with the lowest expected cost
3.3Error analysis by sliceBreak errors down by clinic, age band and booking channel and name the worst slice
3.4Fixing one failureTest one feature or data change aimed at the worst slice named in a supplied error table and report its effect on all slices
Day 4 Compare and report
4.1Is the challenger betterRun a paired bootstrap over validation folds and report the difference with a 95% interval
4.2Searching without fooling yourselfRun a small hyperparameter search with nested validation and compare it with the untuned model
4.3Regression in the same framePredict waiting time with the same pipeline and report mean absolute error against a median baseline
4.4Reproducible results and a model cardLock the environment, re-run from a clean clone and draft the model card, then choose the capstone dataset

How the work is assessed

  • Supervised entry quiz and exit check of fundamentals without AI assistance: metrics computed by hand, choosing a validation scheme, spotting leakage in a described dataset (20%)
  • Capstone repository scored on a five-criterion rubric: framing and baseline 15, pipeline and validation 25, leakage audit 20, metrics, threshold and error analysis 25, comparison and reproducibility 15 (60%)
  • Live defence in which the participant re-runs the comparison and explains a result the assessor selects (20%)
To pass
70% overall, with at least 60% on the capstone rubric and at least 60% on the supervised check

Use of AI in the course

AI-off for the entry quiz, the exit check and the first attempt at each day's core step (pipeline, split, metric). AI-tutor for lab extensions: the course assistant hints and explains but does not write the code. AI-full in the capstone, which the participant defends live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
