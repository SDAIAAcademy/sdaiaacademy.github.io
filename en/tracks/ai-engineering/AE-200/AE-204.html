Badge

Helps prepare for the SDAIA AI Engineering badge, Assistant level.

Description

Participants build and change software by directing coding agents while staying accountable for every merged line. On the booking-service repository of a fictional government digital-services unit, they read and debug code by hand, write a specification and a plan before delegating, make the repository agent-ready with a short context file, a skill and test commands, run an agent with scoped permissions in an isolated worktree, review its changes by risk, add property-based and mutation tests, scan generated code and dependencies for vulnerabilities, and gate everything in continuous integration. One assessed checkpoint is done without AI.

Learning outcomes

By the end, the participant can:

  1. Applied

    Analyse an unfamiliar code base by hand to trace a request path and locate the cause of a failing test.

    Given the booking-service repository, one failing test and no AI assistance.

    Evidence a written trace and a fix that makes the test pass in a supervised session.

  2. Applied

    Draft a specification with acceptance criteria and a plan of small, verifiable steps before delegating work to an agent.

    Given a feature request written by a non-technical product owner.

    Evidence a specification file and a plan that the assessor checks against the merged change.

  3. Applied

    Configure a repository for agent work with a short context file, one reusable skill, scoped permissions and commands for tests and linting.

    Given the booking repository and an open-source or commercial coding agent.

    Evidence a configuration commit and an agent transcript showing the agent running the tests before it proposes a change.

  4. Applied

    Test agent-written code with unit, property-based and mutation tests and report what the original tests missed.

    Given an agent-produced pull request that changes a pricing rule.

    Evidence a test report with the mutation score before and after and each surviving mutant explained.

  5. Applied

    Apply a risk-based review checklist to agent pull requests, including security scanning of the change and its dependencies.

    Given three pull requests with seeded defects, one vulnerable dependency and one hard-coded secret.

    Evidence review comments that find at least four of the five seeded problems, with a merge, revise or reject decision for each.

  6. Applied

    Configure continuous integration that runs tests, type checks, security scans and a dependency audit on every change.

    Given a repository with no pipeline.

    Evidence a pipeline run that fails on a seeded vulnerable change and passes after the fix.

  7. Performance

    Deliver a feature through the specify, plan, execute and verify cycle with an agent and defend each design decision to a reviewer.

    Given a new feature request, the configured repository and a fixed time box.

    Evidence a merged pull request with specification, agent transcript, tests and a change note, defended live.

Day by day

Four sessions a day. Each session presents the concepts with a demonstration, then ends in a lab.

#SessionLab
Day 1 Read, specify, plan
1.1How a coding agent worksAnnotate a recorded agent transcript, marking each search, edit and test step and the one wrong turn
1.2Reading code by hand (assessed AI-off checkpoint)Trace a booking request through the code and find the cause of a failing test without assistance
1.3From request to specificationTurn a product owner's feature request into a specification with five acceptance criteria
1.4Plans an agent can followBreak a supplied specification into small steps, each with a check that proves it is done
Day 2 Make the repository agent-ready
2.1Context files that stay shortWrite a context file of under 100 lines with build, test and style commands and run an agent against it
2.2Skills and hooksPackage a recurring task, adding an API endpoint, as a skill and add a hook that runs the linter after each edit
2.3Permissions, sandboxes and secretsRun the agent in a separate worktree with network access limited to the model endpoint and no read access to the secrets file, and confirm both limits
2.4Executing in small stepsHave the agent implement two plan steps from a supplied plan, stopping for review after each
Day 3 Verify and review
3.1Tests as the contractWrite acceptance tests first and have the agent make them pass without editing them
3.2Property-based and mutation testingAdd property tests to the pricing rule and run mutation testing to find untested behaviour
3.3Reviewing by riskReview three agent pull requests with a risk checklist and decide merge, revise or reject
3.4Security of generated codeScan the changes and dependencies, find the seeded vulnerability and secret, and fix both
Day 4 Integrate and deliver
4.1Continuous integration as the gateBuild a pipeline with tests, type checks, a security scan and a dependency audit
4.2Debugging a regressionLocate a regression with tests and bisection first, then compare your diagnosis with the agent's
4.3Explaining a changeWrite a pull request description and a change note a maintainer can review in five minutes
4.4Team rules for agent useDraft the team's agent-use rules: autonomy levels, review tiers and what never goes to an agent, then choose the capstone feature

How the work is assessed

  • Supervised AI-off checkpoint on day 1 and exit check: code reading, tracing and a hand fix (25%)
  • Capstone repository or pull request scored on a five-criterion rubric: specification and plan 20, agent configuration and permissions 15, tests and mutation score 25, review and security findings 20, pipeline and change note 20 (55%)
  • Live defence in which the participant explains a diff the assessor selects and predicts what a failing test will report (20%)
To pass
70% overall, with at least 60% on the AI-off checkpoint and at least 60% on the capstone rubric

Use of AI in the course

AI-off for the day 1 code-reading checkpoint, the exit check and the first attempt at the regression lab. AI-tutor for the first attempt at the specification, test and review labs. AI-full with a coding agent in the execution labs and the capstone, where the participant owns every merged line and defends it live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
