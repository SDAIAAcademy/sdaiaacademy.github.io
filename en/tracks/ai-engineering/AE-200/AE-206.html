Description

Participants find out where time and memory go between raw data and a served prediction, and fix the largest cost first. For a fictional agritech company they profile a data pipeline and a training step, estimate memory from weights, activations, optimiser state and the key-value cache, apply mixed precision, batching, quantisation and pruning, export a model to a portable runtime, and benchmark latency, throughput and quality with repeated runs and intervals. Labs run on a laptop CPU, with an optional free notebook GPU, and every speed-up must be measured and checked for loss of quality.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Explain how compute, memory capacity and memory bandwidth limit training and inference, and identify which one binds for a described workload.

    Given four workload descriptions with model size, batch size and hardware figures.

    Evidence a worked estimate for each workload that matches the reference within a stated margin.

  2. Applied

    Measure where time goes in a data pipeline and a training step with profilers and timers, and remove the largest bottleneck.

    Given a slow training script for the leaf-image model.

    Evidence a before-and-after profile and a measured speed-up with the change explained.

  3. Applied

    Compute the memory needed for weights, activations, optimiser state and the key-value cache and check each estimate against measured peak memory.

    Given a small vision model and a small language model at three batch sizes and context lengths.

    Evidence an estimate table next to measured peaks, with each difference explained.

  4. Applied

    Apply mixed precision, batching and compilation and report their effect on speed, memory and accuracy.

    Given the training and inference scripts and a fixed test set.

    Evidence a results table with time per step, throughput, peak memory and accuracy for each setting.

  5. Applied

    Apply post-training quantisation and pruning, export the model to a portable runtime and compare size, latency and quality with the original.

    Given the trained classifier, a small language model and a held-out evaluation set.

    Evidence a comparison table of size, median and tail latency and quality loss with an interval.

  6. Applied

    Prepare a benchmark that controls warm-up, repetitions, batch size and input mix, and report percentiles with confidence intervals.

    Given two model variants and a target laptop.

    Evidence a benchmark script and report that another participant re-runs within 10% of the reported median.

  7. Performance

    Optimise a model and its serving path to meet a stated latency and memory budget on a target device while keeping quality within an agreed tolerance.

    Given a budget set by the company for its farm-office laptops and a quality floor on the held-out set.

    Evidence an optimisation log ordered by measured impact and a final benchmark that meets the budget or explains the gap.

Day by day

Four sessions a day. Each session presents the concepts with a demonstration, then ends in a lab.

#SessionLab
Day 1 Measure first
1.1Compute, memory and bandwidthEstimate arithmetic intensity for two layers, predict which is memory-bound, then time both
1.2Timers, profilers and noiseTime one inference 100 times, plot the distribution and show how warm-up and background load change it
1.3Profiling a training stepProfile one training step and rank data loading, forward pass, backward pass and optimiser time
1.4Fixing an input-bound pipelineAdd parallel loading, caching and a faster image format and measure the change in step time
Day 2 Memory and training efficiency
2.1Where memory goesEstimate and measure peak memory for weights, activations and optimiser state at three batch sizes
2.2Mixed precisionTrain with and without reduced precision and compare time per step and validation accuracy
2.3Accumulation and checkpointingFit a larger effective batch in fixed memory with gradient accumulation and activation checkpointing
2.4Compilation and fusionCompile the model and measure the first-call cost and the steady-state speed-up
Day 3 Inference and compression
3.1Latency, throughput and batchingServe the classifier at batch sizes from 1 to 64 and plot latency against throughput
3.2Language model inference on a laptopMeasure time to first token and tokens per second for a small model at three context lengths and size its key-value cache
3.3QuantisationQuantise the classifier to 8-bit, load supplied 8-bit and 4-bit files of the language model, and measure size, speed and quality loss on a fixed question set
3.4Pruning or a smaller modelPrune the classifier, fine-tune briefly and compare with a smaller architecture trained from scratch
Day 4 Export and benchmark
4.1Export to a portable runtimeExport the classifier to an exchange format, run it in a portable runtime and check that outputs match within tolerance
4.2A benchmark you can trustWrite a benchmark with warm-up, repetitions and a fixed input mix and report percentiles with intervals
4.3Quality must surviveEvaluate each compressed variant on the held-out set with a paired comparison against the original, by crop type
4.4Budgets and trade-offsFrom a supplied results table, choose the variant that meets the latency and memory budget, justify it in one paragraph and choose the capstone model

How the work is assessed

  • Supervised entry quiz and exit check without AI assistance: memory and bandwidth estimates by hand, reading a profile, choosing what to optimise first (20%)
  • Capstone repository scored on a five-criterion rubric: baseline profile 20, changes ordered by measured impact 25, quality re-evaluation 20, benchmark method 20, reproducibility 15 (60%)
  • Live defence in which the participant re-runs the benchmark and explains a result the assessor selects (20%)
To pass
70% overall, with at least 60% on the capstone rubric and at least 60% on the supervised check

Use of AI in the course

AI-off for the supervised checks and for the first attempt at every memory and bandwidth estimate. AI-tutor in the profiling and compression labs: the course assistant explains outputs and hints at the next measurement. AI-full in the capstone, which the participant defends live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
