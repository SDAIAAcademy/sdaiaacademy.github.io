Description

Participants decide when adapting a model is worth it and then do it well. For a fictional chamber of commerce whose bilingual registration requests must stay on its own servers, a prompted small open-weight model fails at field extraction and tool calls. They sort the failures, set a stronger prompted baseline, build a tuning set from traces, staff corrections and filtered teacher outputs, train low-rank adapters, distil a larger model's tool-call behaviour, evaluate against the base and a larger prompted model, and serve the result quantised with several adapters. AE-301 introduces adapters on an encoder; post-training at scale is AE-406.

Learning outcomes

By the end, the participant can:

  1. Applied

    Analyse the failures of a prompted model and assign each failure class to prompting, retrieval, tuning or distillation.

    Given 100 bilingual requests run through the small model and a larger reference model.

    Evidence a decision table with counts per failure class and the chosen approach.

  2. Applied

    Prepare a tuning dataset from traces, corrections and teacher outputs, with template rendering, verifier filtering, deduplication, decontamination and personal-data removal.

    Given 500 synthetic traces, staff corrections and a teacher model.

    Evidence a dataset with its card and an overlap report against the test set.

  3. Applied

    Configure and train low-rank adapters on a 16-bit and a 4-bit base model within the memory of one free-tier GPU.

    Given a small open-weight model and the tuning set.

    Evidence training logs, the adapter and a memory and time comparison.

  4. Performance

    Evaluate the adapted model against the base and a larger prompted model with paired statistics, language slices, regression and safety checks.

    Given a held-out bilingual test set and a general-ability check.

    Evidence an evaluation report with intervals and the regressions found.

  5. Performance

    Deploy a quantised small model with several adapters and measure throughput, latency and cost per thousand requests.

    Given one accelerator and a target request rate.

    Evidence a load-test report with the serving configuration.

  6. Performance

    Decide whether to ship the adapted model, weighing quality, cost, licence terms and data placement.

    Given the evaluation and load-test results.

    Evidence a one-page decision memo defended live.

Topics

When to adapt

  • Prompt, retrieve, tune or distil
  • Tuning changes behaviour more than knowledge
  • Narrow tasks small models suit and multi-step work they do not
  • Licences and acceptable-use terms
  • Cost and placement of each option

Data for tuning

  • Traces and staff corrections
  • Teacher generation with verifier filtering
  • Chat templates and tool-call formats
  • Deduplication, decontamination and personal data

Adapters and distillation

  • Low-rank and quantised adapters
  • Rank, learning rate and schedule
  • Distilling a behaviour from a larger model

Evaluating adapted models

  • Paired comparison with the base and a larger model
  • Arabic and English slices
  • Forgetting and regressions
  • Safety behaviour after tuning

Serving small models

  • Quantised weight formats
  • Several adapters on one base model
  • Throughput and cost per thousand requests

Day by day

Four sessions a day. Each session presents the concepts with a demonstration, then ends in a lab.

#SessionLab
Day 1 Decide whether to adapt
1.1Prompt, retrieve, tune or distilRun the small and the reference model on 100 requests and sort failures into knowledge, format and behaviour
1.2The baseline tuning must beatImprove the prompt with schema hints and examples and freeze the score as the baseline
1.3Licences and terms of open-weight modelsCompare licence and acceptable-use terms of three small models and record which may be adapted and deployed
1.4Cost and placement of the optionsEstimate tuning, serving and per-request cost for a large hosted model versus a tuned small model on-premises
Day 2 Data for tuning
2.1Tuning data from traces and correctionsTurn 500 synthetic traces and staff corrections into chat-format examples
2.2Teacher generation and verifier filteringGenerate 300 examples with a larger model and filter them with schema and rule checks
2.3Chat templates and tool-call formatsRender examples with the model's template and fix three formatting faults that would harm training
2.4Deduplication, decontamination and personal dataRemove near-duplicates and test-set overlap and scan the set for personal data
Day 3 Train adapters and distil
3.1Low-rank adaptersTrain an adapter on the supplied set in a free notebook GPU and read the loss curves
3.2Quantised adapters and memoryTrain the same adapter on a 4-bit base and compare memory, time and score with a supplied 16-bit run
3.3Settings that matterRead a supplied sweep of rank and learning rate, run one more setting and choose on the validation set
3.4Distilling a behaviourRun a short distillation of the larger model's filtered tool calls into the student and compare it with a supplied corrections-only adapter
Day 4 Evaluate and serve
4.1Paired evaluation against the baseCompare tuned, base and larger prompted models on Arabic and English slices with a paired bootstrap
4.2Regressions and safety after tuningRun general-ability and refusal checks on a supplied adapter and list what got worse
4.3One base, several adaptersServe a quantised base with two adapters and load-test throughput
4.4Cards and the decision memoDraft the dataset card, model card and decision memo, then choose the capstone task

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Small open-weight models
an instruction-tuned small model, a small model from a second family, an Arabic-capable open-weight model
Fine-tuning libraries
Transformers with PEFT and TRL, a plain PyTorch training loop
Model evaluation harness
Inspect, lm-evaluation-harness
Inference server with adapter support
vLLM, SGLang, llama.cpp
Experiment tracking
MLflow, a run log committed to the repository
Load testing
Locust, k6
Compute
a free notebook GPU, Academy GPU hours

How the work is assessed

  • Supervised entry and exit checks without AI assistance on adaptation choices, data faults and memory arithmetic (20%)
  • Capstone repository on a five-criterion rubric: adaptation decision 15, data quality 25, training 15, evaluation 30, serving and cost 15 (60%)
  • Live defence of the decision memo (20%)
To pass
70% overall and at least 60% on the capstone rubric

Use of AI in the course

AI-off for the supervised checks and the first failure analysis. AI-tutor in the labs: the assistant explains library calls and errors but does not write the data pipeline. AI-full in the capstone, which the participant defends live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
