Description

Participants build one batch pipeline end to end for Qafila, the fictional trading company of the Academy's data engineering course, whose margin report nobody trusts. They query raw extracts with analytical SQL, ingest an API and a database change feed incrementally, clean with dataframes, model a star schema with a slowly changing supplier dimension, write tested transformations and a data contract, orchestrate them, and land the result in an open table format that a second engine reads. Day four adds distributed processing, streaming and governance.

Learning outcomes

By the end, the participant can:

  1. Applied

    Analyse raw transactional extracts with analytical SQL, including window functions and incremental predicates.

    Given three months of synthetic orders, shipments and prices in columnar files.

    Evidence queries that reproduce the reference monthly margin and a note on two defects found.

  2. Applied

    Implement incremental ingestion from an API and a change feed, keeping supplier history as a slowly changing dimension.

    Given a paginated API and a feed with updates and deletes.

    Evidence loads that add no duplicates on re-run and correct validity ranges.

  3. Performance

    Design a dimensional model at a stated grain and build it as tested, version-controlled transformations.

    Given the finance team's five margin questions.

    Evidence a star schema, passing tests and a rebuild that skips unchanged models.

  4. Performance

    Build an orchestrated pipeline with a data contract, quality gates, retries and backfills that fails safely when an upstream feed breaks.

    Given a supplier feed that changes its schema without notice.

    Evidence a run log showing the violation caught, the mart left unrefreshed and a backfill after the fix.

  5. Applied

    Configure an open table format with partitioning, schema evolution and time travel, and read it from a second engine.

    Given the margin mart and one schema change.

    Evidence identical results from two engines and a query against an earlier snapshot.

  6. Applied

    Classify every field under the national classification levels and apply minimisation, masking and access rules.

    Given the customer and supplier tables.

    Evidence a classification register and a masked view that passes access tests.

Topics

Platform shapes and analytical SQL

  • Transactional and analytical systems; extract, load, transform (ELT)
  • Lakehouse, layered refinement and columnar files

Ingestion and change

  • Schema drift and idempotent loads
  • Change data capture (CDC), merge and slowly changing dimensions
  • Single node first, distributed when measured

Modelling, transformation and contracts

  • Grain, facts and dimensions
  • Tests, environments and state-aware builds
  • Data contracts in an open standard
  • Verifying agent-written transformations

Orchestration, scale and streaming

  • Assets, retries and backfills
  • Lineage as events
  • Open table formats: snapshots, schema evolution, deletion vectors, compaction
  • Logs and queues, delivery guarantees, watermarks

Governance in the pipeline

  • Classification levels; Restricted, which older texts call Confidential
  • Minimisation and masking under the Personal Data Protection Law (PDPL)
  • Erasure requests against history tables and snapshots
  • National Data Management Office (NDMO) quality and architecture controls

Day by day

Four sessions a day. Each session presents the concepts with a demonstration, then ends in a lab.

#SessionLab
Day 1 Store and query
1.1Platform shapesPlace ten Qafila workloads in transactional, warehouse or lakehouse layers and justify each
1.2Analytical SQL on a single nodeQuery the raw extracts in place and reproduce the monthly margin without AI assistance
1.3Window functionsCompute running margin, supplier price changes and each customer's first and last order
1.4Columnar files and partitioningConvert the extracts to partitioned columnar files and measure query time and bytes read
Day 2 Ingest and clean
2.1Ingesting from APIsLoad the paginated supplier API incrementally and show that a re-run adds no duplicates
2.2Declarative ingestion pipelinesRebuild the load with an ingestion library, absorb a new column and inspect the load state
2.3Change data capture, merge and historyApply a feed of updates and deletes and keep supplier history as a slowly changing dimension
2.4Cleaning with dataframesClean currencies, units and Arabic supplier names and log every rule applied
Day 3 Model and test
3.1Dimensional modellingDraw the margin star schema at order-line grain and check it against the five finance questions
3.2Transformations as codeBuild staging and mart models as version-controlled SQL with two environments and a state-aware rebuild
3.3Data quality tests and contractsWrite tests and a contract for the supplier feed, break the feed on purpose and watch the gate hold
3.4OrchestrationSchedule the pipeline as assets, force a failure, retry it and backfill one month
Day 4 Scale and production
4.1Open table formatsWrite the mart to an open table format, evolve its schema and query an earlier snapshot from a second engine
4.2Distributed processing when measuredRun the heaviest transformation on a distributed engine in local mode and compare run time and memory with the single-node engine
4.3Streaming fundamentalsConsume shipment events from a local single-broker log, handle late arrivals with a watermark and reconcile with the batch result
4.4Governance with PDPL and NDMOClassify every field, mask customer contact data and test that the analyst role cannot read it

How the work is assessed

  • Supervised entry and exit checks of SQL and modelling without AI assistance (20%)
  • Capstone repository on a six-criterion rubric: correctness of the mart 25, ingestion and history 20, tests and contract 20, orchestration and recovery 15, table format and governance 10, reproducibility 10 (60%)
  • Live defence of one modelling decision (20%)
To pass
70% overall and at least 60% on the capstone rubric

Use of AI in the course

AI-off for the supervised checks and the first SQL lab. AI-tutor in the other labs: the assistant hints but does not write models or tests. AI-full in the capstone, where any agent-written transformation must pass the participant's own tests and be explained in the defence.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
