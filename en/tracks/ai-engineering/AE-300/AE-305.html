AE-305 Operating Machine Learning and Language Model Systems

Prerequisites

  • AE-205 Deploying AI Services: Containers, Serving and Monitoring
  • AE-203 Building Applications on Language Models
  • Builds a container image and a continuous-integration workflow
  • Reads an evaluation report with pass rates and intervals
  • Has built a tool-calling agent, as in AE-302 or equivalent

Badge

Helps prepare for the SDAIA AI Engineering badge, Associate level.

Description

Participants run three systems of a fictional electricity distribution company in production: a fault-risk classifier retrained on monthly batches with planted drift, a field-crew assistant with retrieval and two tools, and an outage-ticket agent. They version everything that changes behaviour as one release unit, build pipelines with validation and promotion gates, release through canary stages with automatic rollback, trace requests, monitor drift and online quality, and keep the agent alive through crashes and runaway loops. Evaluators come ready-made from AE-303.

Learning outcomes

By the end, the participant can:

  1. Applied

    Prepare a release manifest that versions data, code, configuration, model, prompt, retrieval index and tool schemas as one unit.

    Given two runs of the three systems that behave differently.

    Evidence a manifest and the unrecorded change found between the runs.

  2. Performance

    Build a retraining pipeline, started by a drift or schedule trigger, with data validation and a promotion gate that compares challenger and champion overall and by region.

    Given monthly feeder batches, one of them corrupt and one drifted.

    Evidence a triggered run that promotes on the drifted batch and stops on the corrupt one, with registry lineage.

  3. Performance

    Deliver language model changes through an evaluation gate and a canary stage with an automatic rollback trigger.

    Given a prompt edit, a model swap and an index refresh, one of which regresses.

    Evidence logs showing two releases shipped and one rolled back on a stated metric.

  4. Applied

    Configure request tracing, drift monitors and online evaluation with a review queue, and tune alert thresholds.

    Given a replayed month of traffic with two planted shifts.

    Evidence a dashboard, alert rules and a note on shifts found and false alarms removed.

  5. Performance

    Diagnose an agent incident by replaying recorded traces and fix it with idempotent tools, durable state or a budget.

    Given a recorded failure of the ticket agent.

    Evidence the failure reproduced, a fix and a new regression case.

  6. Applied

    Measure cost per successful outcome and resource use for each system and set budget alerts.

    Given a month of token, compute and outcome logs.

    Evidence a cost table by system and team, with alert rules.

Topics

The release unit

  • What changes behaviour
  • Registries and lineage
  • Pinned provider model identifiers
  • Maturity from manual to automated

Pipelines and delivery

  • Data validation and contracts
  • Champion, challenger and subgroup gates
  • Shadow, canary and rollback triggers
  • Knowledge-base refresh and retraining as releases

Observation

  • Spans for model, retrieval, tool and agent calls
  • Drift, skew and delayed labels
  • Online evaluation, retention and redaction

Operating agents

  • Session log, harness and sandbox as separate parts
  • Checkpoints and idempotency keys
  • Replay as a regression suite
  • Budgets, kill switches and runbooks

Cost signals

  • Cost per successful outcome
  • Cache hit rate and utilisation
  • Showback by team

How the work is assessed

  • Supervised entry and exit checks without AI assistance: reading a pipeline log and a trace, and choosing a rollback trigger (20%)
  • Capstone repository on a five-criterion rubric: pipelines and gates 25, delivery and rollback 20, observability 20, agent operations 20, runbook and reproducibility 15 (60%)
  • Live defence with an injected fault (20%)
To pass
70% overall and at least 60% on the capstone rubric

Use of AI in the course

AI-off for the supervised checks. AI-tutor in the labs: the assistant explains logs and hints but does not write pipeline or alert definitions. AI-full in the capstone, which is defended live against an injected fault.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
