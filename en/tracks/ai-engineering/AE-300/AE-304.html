AE-304 Retrieval and Knowledge Engineering for Language Model Systems

  • Intensive
  • 26 h
  • Audience: practitioner

Prerequisites

Badge

Helps prepare for the SDAIA AI Engineering badge, Associate level.

Description

Participants build and measure the retrieval layer of a language model system for a fictional university: bilingual regulations, study plans with tables, scanned Arabic circulars and an enrolment statistics warehouse. Starting from a graded test set, they build lexical, dense, hybrid and reranked search with Arabic normalisation, parse and chunk documents by structure, filter by date and role, give an agent search tools and a small knowledge graph, and answer statistical questions through a semantic layer instead of free text-to-SQL.

Learning outcomes

By the end, the participant can:

  1. Applied

    Prepare a retrieval test set with graded relevance judgements and compute standard ranking metrics for each language.

    Given 60 Arabic and English queries over the corpus.

    Evidence a versioned test set and a report of recall at 10, reciprocal rank and discounted cumulative gain by language.

  2. Applied

    Implement lexical, dense, hybrid and reranked search with Arabic normalisation and compare them on quality and latency.

    Given the corpus and the test set.

    Evidence a results table with ranking metrics and 95th-percentile latency per method.

  3. Applied

    Analyse parsing and chunking choices by scoring two parsers and two chunking schemes.

    Given 30 scanned and digital pages with tables.

    Evidence a parsing score per page type and a retrieval comparison with a recommendation.

  4. Performance

    Build retrieval that never returns a document the requester may not see or a superseded rule.

    Given role labels and effective dates on every chunk.

    Evidence a passing suite of leak and staleness tests.

  5. Performance

    Design an agentic search component that chooses among search tools and a small knowledge graph within a context budget.

    Given 15 multi-step questions, a graph of linked course rules and a token budget.

    Evidence traces and a comparison with single-shot search on accuracy, tool calls and tokens.

  6. Performance

    Evaluate free text-to-SQL against a semantic layer with validated SQL and decide which to ship.

    Given 20 statistical questions with reference answers.

    Evidence execution accuracy for both and a one-page decision memo.

Topics

Measuring retrieval

  • Graded relevance and pooling
  • Recall at k, reciprocal rank and discounted gain
  • Slicing by language and query type

Search methods

  • Inverted indexes and BM25
  • Arabic normalisation and light stemming
  • Multilingual embeddings and approximate nearest-neighbour indexes
  • Rank fusion and cross-encoder reranking

Preparing a corpus

  • Parsing right-to-left text and tables
  • Small specialised parsing models against general vision models
  • Chunking by structure
  • Effective dates and deduplication

Agentic search and knowledge

  • The cheapest tool that works first
  • Iterative search and query decomposition
  • Paging and offloading large results
  • Knowledge graphs for multi-hop questions

Structured data, access and trust

  • Schema grounding and semantic layers
  • Validating generated SQL
  • Permission filters before ranking
  • Retrieved text as untrusted input

Day by day

Four sessions a day. Each session presents the concepts with a demonstration, then ends in a lab.

#SessionLab
Day 1 Measure and search
1.1Retrieval is measured on its ownJudge graded relevance for 40 bilingual queries and score a provided baseline
1.2Lexical search and Arabic textRun BM25 with and without Arabic normalisation and compare recall on Arabic and dialect queries
1.3Dense retrieval and embedding choiceEmbed a 300-page sample with two open multilingual models, load the supplied full indexes and compare quality, index size and latency
1.4Hybrid search and rerankingFuse lexical and dense rankings, add a reranker and report the gain against the added latency
Day 2 Prepare the corpus
2.1Parsing is a separate problemScore two parsers on 30 pages against reference text and tables
2.2Chunking by structureChunk study plans by headings and by fixed windows and compare retrieval on table questions
2.3Dates, versions and duplicatesAdd effective dates and deduplication and test 15 questions whose answer changed in a newer circular
2.4Permissions in the indexTag chunks with role and classification and run leak tests from a student account
Day 3 Agentic search and knowledge
3.1Search as tools for an agentExpose file listing, keyword and vector search as tools and trace the agent's choices on 15 questions
3.2Multi-step questionsCompare single-shot and iterative search on ten multi-hop questions
3.3Paging and offloadingOffload large search results to files and measure tokens and accuracy
3.4Knowledge graphs for linked factsBuild a small graph of courses, prerequisites and rules and answer ten relationship questions with and without it
Day 4 Structured data and diagnosis
4.1Questions over a warehouseRun free text-to-SQL on 20 statistical questions and measure execution accuracy
4.2Semantic layers and validated SQLAnswer the same questions through governed metrics with SQL validation and compare
4.3Cost, latency and freshnessMeasure cost per question, tail latency and re-index time after one circular changes
4.4Diagnosing failures by componentAttribute 20 failures to parsing, retrieval, ranking or generation and fix the weakest component

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Lexical search
SQLite full-text search, OpenSearch, PostgreSQL full-text search
Vector index
pgvector, Qdrant, LanceDB, FAISS
Embedding and reranking models
open-weight multilingual models through Sentence Transformers, any embedding API
Document parsing and character recognition
Docling, Unstructured, Tesseract, an open-weight document vision model
Arabic text processing
CAMeL Tools, PyArabic
Analytical engine and semantic layer
DuckDB, PostgreSQL, Cube Core, metric definitions kept as version-controlled SQL views
Graph store
NetworkX, Neo4j
Retrieval metrics
ranx, pytrec_eval

How the work is assessed

  • Supervised entry and exit checks without AI assistance: ranking metrics by hand and a chunking decision (20%)
  • Capstone repository on a five-criterion rubric: retrieval quality and test set 25, corpus preparation 20, access and freshness tests 20, agentic or structured-data component 20, reproducibility 15 (60%)
  • Live defence of one design decision (20%)
To pass
70% overall and at least 60% on the capstone rubric

Use of AI in the course

AI-off for the supervised checks and the day-one relevance judgements. AI-tutor in the other labs: the assistant hints but does not write retrieval or evaluation code. AI-full in the capstone, which is defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
