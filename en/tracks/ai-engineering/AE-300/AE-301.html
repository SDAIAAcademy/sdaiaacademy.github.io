Badge

Helps prepare for the SDAIA AI Engineering badge, Associate level.

Description

Participants build the language layer of a customer-service system for a fictional regional water utility whose messages arrive in Modern Standard Arabic, Gulf dialect, Arabic written in Latin script and English. They trace text through tokenisers, embeddings and attention, build semantic search, route messages and extract account fields three ways (a classical baseline, a prompted generative model and a fine-tuned encoder), adapt a model with low-rank adapters in free notebook memory, and ship the chosen model as a small service with a model card. Every choice rests on scores by dialect, latency and cost.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Explain how tokenisation, embeddings and attention turn Arabic and English text into model inputs, and where script, diacritics and dialect break that pipeline.

    Given 50 parallel messages and three tokenisers.

    Evidence a one-page note with token counts per language and two failures traced to their cause.

  2. Applied

    Implement semantic search over a bilingual message archive and measure it for each language variety.

    Given 2,000 synthetic messages and 40 labelled queries.

    Evidence a table of recall at 10 for each of the four varieties.

  3. Applied

    Implement schema-validated extraction of account numbers, districts and complaint types from free text, masking personal fields before text reaches a hosted model.

    Given 200 messages with gold fields.

    Evidence field-level precision and recall, a log of validation failures and a passing masking test.

  4. Applied

    Apply low-rank adapter fine-tuning to an encoder within a fixed memory budget and compare it with full fine-tuning.

    Given a routing set split by customer and a free notebook GPU.

    Evidence training logs, trainable-parameter counts and test scores for both runs.

  5. Performance

    Decide among a classical baseline, a prompted generative model and a fine-tuned encoder for message routing.

    Given eight departments, a held-out test set and a latency budget.

    Evidence a table of macro F1, F1 by dialect, CPU latency and cost per thousand messages, with a defended recommendation.

  6. Performance

    Deliver the chosen model as a tested service with a model card that states its limits by language variety.

    Given a smoke-test set.

    Evidence a running service that passes the smoke test and a model card with results by dialect and a hand-off rule.

Topics

Representing text

  • Subword tokenisers and token cost per language
  • Normalising alef, hamza, ta marbuta and diacritics
  • Dialect and Arabic in Latin script
  • Embeddings and vector indexes

Models for decisions

  • Attention, encoders and decoders
  • Baselines first
  • Classification and token-classification heads
  • A prompted model as a zero-shot classifier

Generation in applications

  • Sampling and consistency
  • Structured outputs with validation
  • Grounding in a rule corpus (depth in AE-304)
  • Choosing by quality, latency, cost and licence

Adapting and shipping

  • Splits without leakage
  • Full fine-tuning against low-rank and quantised adapters
  • CPU latency, a small API and a demo
  • Model cards with subgroup results

Day by day

Four sessions a day. Each session presents the concepts with a demonstration, then ends in a lab.

How the work is assessed

  • Supervised entry and exit checks without AI assistance: tokenisation, metrics and leakage (20%)
  • Capstone repository on a five-criterion rubric: three-way comparison 25, extraction 20, adaptation 20, service and model card 20, reproducibility 15 (60%)
  • Live defence of the model choice (20%)
To pass
70% overall and at least 60% on the capstone rubric

Use of AI in the course

AI-off for the supervised checks and the day-one baseline lab. AI-tutor in the other labs: the assistant hints but does not write training or evaluation code. AI-full in the capstone, which is defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
