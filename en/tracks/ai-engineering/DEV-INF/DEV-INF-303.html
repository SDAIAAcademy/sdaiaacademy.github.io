DEV-INF-303 Edge and On-Device AI: Small Models and Neural Processors

  • Level 300 · Develop
  • Intensive
  • 30 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-INF Infrastructure, Performance and Architecture

Level

Level 300 · Develop

Audience

practitioner

Format

Intensive: 3 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

30 h

Prerequisites

  • DEV-INF-201 Machine Learning Systems on One Machine
  • Has trained and evaluated a small neural network with a deep learning framework
  • Builds a simple web page with JavaScript, or completes the provided pre-work

Description

Participants move small language and vision models onto laptops, single-board computers, phones and the browser. They decide when on-device inference is worth it, quantise and convert models, run them on neural processing units and other on-device accelerators, measure speed, memory, energy and heat, and build a browser application with a server fallback. Labs use open-weight models, public data and provided boards.

Learning outcomes

By the end, the participant can:

  1. Applied

    Analyse whether on-device, browser, hybrid or server inference fits a case on privacy, latency, connectivity and cost.

    Given four described cases, one with personal data.

    Evidence a justified decision table matching the reference on at least three cases.

  2. Applied

    Prepare a small language model and a vision model for a device by quantising, converting and checking parity.

    Given two open-weight models and a held-out task set.

    Evidence a parity report giving task accuracy for each format.

  3. Applied

    Measure latency, peak memory, energy per inference and thermal throttling under sustained load.

    Given a provided board, a power meter and a fixed protocol.

    Evidence a report of five repeated runs with a throttling curve.

  4. Performance

    Optimise a model for a neural processing unit or GPU delegate by diagnosing unsupported operators.

    Given a vision model that runs slowly on the accelerator.

    Evidence before and after profiles with the delegated operator share and latency.

  5. Performance

    Build a browser application that runs a small model locally with a server fallback.

    Given a starter interface and an Arabic and English task set.

    Evidence a deployed page with measured first load, tokens per second and fallback rate.

  6. Performance

    Deliver an on-device application that meets a latency, memory and accuracy budget and defend its trade-offs.

    Given a use case from a provided list.

    Evidence a repository and measurement report, defended live on the device.

Topics

When and why on device

  • Privacy, residency and data minimisation
  • Offline, latency and per-request cost
  • Hybrid device and server patterns

Small models and formats

  • Small language models tested on own tasks
  • Efficient vision backbones and detectors
  • Weight-only and full-integer quantisation
  • Quantised file formats and parity tests

Runtimes and accelerators

  • Mobile and embedded inference runtimes
  • Neural processing unit delegates and fallbacks
  • Browser inference on WebGPU and built-in model interfaces

Measurement and operations

  • On-device benchmark protocol
  • Energy, battery and thermal limits
  • Updating and protecting models on devices

Tools and platforms

These are examples. Any equivalent tool may be used instead.

On-device runtime
ExecuTorch, LiteRT, ONNX Runtime
Local language model runtime
llama.cpp, LiteRT-LM
Browser inference
WebLLM, ONNX Runtime Web with WebGPU, built-in browser AI interfaces
Target hardware
participant laptop, provided Raspberry Pi-class board with an accelerator module, own phone, optional
Measurement
USB power meter, runtime profilers

How the work is assessed

  • Supervised check on placement choices and quantised memory arithmetic without AI assistance (15%)
  • Graded labs (35%)
  • Capstone repository and measurement report (40%)
  • Live defence on the device (10%)
To pass
70% overall, with at least 60% on the capstone and on the supervised check

Use of AI in the course

AI-off for the supervised check. AI-tutor in labs. AI-full in the capstone, demonstrated and defended live on the device.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
