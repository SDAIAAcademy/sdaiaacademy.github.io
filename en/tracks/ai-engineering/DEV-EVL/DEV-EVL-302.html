DEV-EVL-302 Evaluating Agents: Trajectories, Simulation and Consistency

  • Level 300 · Develop
  • Workshop
  • 16 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-EVL Evaluation and Quality Engineering for AI Systems

Level

Level 300 · Develop

Audience

practitioner

Format

Workshop: two days with labs and a short evaluation project, with guided pre-work

Total hours

16 h

Prerequisites

  • DEV-EVL-301 Evaluation-Driven Development for Language Model Applications
  • Has built a tool-calling agent, for example in DEV-AGT-301
  • Computes a proportion and its confidence interval

Description

Participants evaluate a tool-using agent for a synthetic travel-booking service. They grade the sandbox's final state and the transcript, drive dialogues with a simulated user holding a hidden goal, repeat tasks to measure consistency and cost per completed job, and repair evaluations that mislead.

Learning outcomes

By the end, the participant can:

  1. Applied

    Implement final-state outcome checks and transcript checks on tool use, side effects and policy.

    Given a resettable booking environment and 20 tasks.

    Evidence a grader suite that reports results per check.

  2. Applied

    Configure a simulated user with a persona, a hidden goal and a stop rule, and measure its fidelity.

    Given 20 dialogues reviewed by hand.

    Evidence goal-leak and off-script rates.

  3. Applied

    Compute one-success and every-success rates over k trials with small-sample intervals, and the cost per completed job.

    Given five trials per task within a call budget.

    Evidence a results table with task-level intervals.

  4. Performance

    Diagnose and repair an agent evaluation that gives a misleading score.

    Given seeded state leakage, an exploitable grader and an ambiguous task.

    Evidence an audit note citing transcripts, and a corrected run.

  5. Performance

    Build capability and regression suites for an agent and defend which metric should gate its release.

    Given a stated tolerance for failed jobs.

    Evidence both suites with measured results.

Topics

Grading agents

  • State, tool, side-effect and policy checks
  • Several valid paths, not one reference trajectory
  • Capability versus regression suites

Simulated users and environments

  • Persona, hidden goal, stop rule and goal leakage
  • Mock tools with resettable state

Consistency and cost

  • Pass at k versus pass to the power k (75% per trial: about 42% for three of three)
  • Task-level intervals; cost and turns per completed job

When evaluations mislead

  • State leaking between trials
  • Agents reading answer keys or version history
  • Infrastructure noise and ambiguous tasks

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Agent evaluation harness
Inspect, pytest with a custom trial runner
Resettable task environment
a containerised mock service with reset, an OpenEnv-style environment interface
Language model access through an OpenAI-compatible endpoint
a locally served open-weight model, any commercial API

How the work is assessed

  • Supervised AI-off check on grading and consistency arithmetic (20%)
  • Graded labs (40%)
  • Capstone and review (40%)
To pass
70% overall and at least 60% on the capstone

Use of AI in the course

AI-off for the supervised check. AI-tutor in the labs. AI-full in the capstone, defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
