DEV-AGT-301 Agentic Systems Engineering: Loops, Context and Harnesses

  • Level 300 · Develop
  • Intensive
  • 40 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-AGT Agentic Systems

Level

Level 300 · Develop

Audience

practitioner

Format

Intensive: 4 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

40 h

Prerequisites

  • DEV-LLM-201 Building Applications on Language Models
  • Writes and tests Python that calls an HTTP API and validates a JSON response against a schema
  • Has built a small application that sends prompts to a language model and parses structured output
  • Uses Git and runs code in a container from the command line

Description

Participants build an agent the way the field now builds them: a model in a loop that calls typed tools inside a sandbox, with most of the engineering in the harness around it. They write the loop from scratch, treat context as a budget, add memory files, skills and Model Context Protocol servers, compare agent frameworks with their own harness, put human approval gates into a state graph, and finish with an agent that is traced, evaluated and contained. One synthetic case study runs through all four days, and the capstone is a research agent over a synthetic document corpus.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Distinguish a fixed workflow, a single agent in a loop and a multi-agent design, and state which one a given task needs.

    Given five task descriptions, each with its environment, available tools and success criteria.

    Evidence a decision table with a one-line justification per task that matches the reference on at least four of five rows.

  2. Applied

    Implement an agent loop from scratch that calls typed tools, handles tool errors and stops on explicit completion criteria.

    Given a provider-neutral model endpoint, three tool schemas and no agent framework.

    Evidence a script that completes at least eight of the ten reference tasks within the step budget, with one saved transcript per run.

  3. Applied

    Measure and reduce context use with compaction, offloading of large tool results to files and progressive disclosure of skills.

    Given an agent that exceeds its context budget on long tasks.

    Evidence a before-and-after report of tokens per task, task success and, where the endpoint reports it, cache hit rate on the same task set.

  4. Applied

    Configure a protocol server and a skill so that an agent discovers and uses them without changes to the agent's code.

    Given a synthetic document store and a written operating procedure.

    Evidence a passing integration test and a trace that shows discovery, activation and use.

  5. Performance

    Build a state-graph agent with checkpoints and a human approval gate before every irreversible action.

    Given a case-study workflow with one high-risk step and a stated risk threshold.

    Evidence a run log showing the pause, the approval or rejection, and resumption from a checkpoint after a forced restart.

  6. Performance

    Evaluate an agent with transcript and outcome graders over repeated trials and report consistency and cost per completed task.

    Given a 20-task suite and a fixed budget of model calls.

    Evidence an evaluation report with pass rates, success in all of k trials, cost per completed task and the three most frequent failure modes.

  7. Performance

    Defend the containment design of an agent that combines private data, untrusted content and a possible exfiltration path.

    Given a threat scenario chosen by the assessor.

    Evidence a written containment plan and a live run in which a seeded prompt injection fails to move data out of the sandbox.

Topics

From model to agent

  • Three API shapes: chat messages, item lists and provider-neutral responses
  • Structured outputs with validation
  • Typed tool schemas and tool errors
  • The agent loop written from scratch
  • Completion criteria and step budgets

Context engineering

  • Context as a budget
  • Retrieval for agents: the cheapest tool that works first
  • Compaction, resets and offloading tool results to files
  • Cache-aware layout of prompts and tools
  • Instruction bloat and how to avoid it

Memory, skills and protocols

  • Repository context files and the nearest-file rule
  • Skills loaded in stages
  • Memory files: write, consolidate, retrieve, forget
  • Model Context Protocol: hosts, clients, servers, tools and resources
  • Agent-to-agent delegation at concept level

Harness anatomy

  • Tools, context, state and feedback as the harness
  • Agent frameworks and hosted agents compared with an own loop
  • Loop engineering and verification inside the loop
  • Removing scaffolding when a newer model no longer needs it

Graphs and human gates

  • State graphs, checkpoints and interrupts
  • Approval at defined risk thresholds
  • Approval prompts nobody reads
  • Subagents for isolation; when multiple agents pay

Evaluating agents

  • Tasks, trials, graders, transcripts and outcomes
  • Success in at least one versus all of k trials
  • Capability suites and regression suites
  • A smoke evaluation in continuous integration

Securing and shipping agents

  • The agentic application risk list from the Open Worldwide Application Security Project (OWASP)
  • Private data, untrusted content and exfiltration: remove one leg
  • Sandboxes, egress control and least-privilege tools
  • Tracing with the OpenTelemetry generative AI conventions, still in development
  • Serving an agent behind an API

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Language model access through an OpenAI-compatible or provider-neutral endpoint
a locally served open-weight model, a hosted open-weight model on a free tier, any commercial API
Agent framework with state graphs and checkpoints
LangGraph, Pydantic AI with its graph library, Microsoft Agent Framework workflows
Agent software development kit for the framework comparison
smolagents, OpenAI Agents SDK, Google Agent Development Kit
Protocol server software development kit
official Model Context Protocol Python SDK, FastMCP, official TypeScript SDK
Trace collection and viewer
OpenTelemetry with Langfuse, Arize Phoenix, MLflow tracing
Evaluation harness
Inspect, promptfoo, pytest with custom graders
Execution sandbox
Docker or Podman containers with no network by default, OpenSandbox
API service wrapper
FastAPI, Starlette

How the work is assessed

  • Supervised check without AI assistance: read a transcript and trace a context budget by hand (10%)
  • Graded labs (35%)
  • Capstone repository scored on a five-criterion rubric (45%)
  • Live defence of the containment design (10%)
To pass
70% overall, at least 60% on the capstone rubric and a pass on the supervised check

Use of AI in the course

AI-off for the first from-scratch agent loop and for the supervised check. AI-tutor in the other labs. AI-full in the capstone, which the participant owns and defends live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
