DEV-MLE-203 Feature, Training-Data and Labelling Pipelines

  • Level 200 · Apply
  • Workshop
  • 16 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-MLE Machine Learning Engineering

Level

Level 200 · Apply

Audience

practitioner

Format

Workshop: 2 days with labs and a short tracked follow-up task

Total hours

16 h

Prerequisites

  • DEV-MLE-201 Machine Learning Engineering: Baselines, Validation and Pipelines
  • Writes analytical SQL with joins and window functions

Description

Participants build the data side of a production model on a synthetic payments event log. They assemble training sets with point-in-time joins, define features once for training and serving, catch training-serving skew, and run a model-assisted labelling flow with human review and versioned labels.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Explain how point-in-time errors, stale features and training-serving skew enter a prediction system.

    Given a data-flow diagram of a fraud-scoring service.

    Evidence the diagram marked with entry points and the checks that catch them.

  2. Applied

    Implement an as-of join that uses only feature values available at each label's time.

    Given event logs, labels and late-arriving records.

    Evidence a build script and metrics compared with a naive join.

  3. Applied

    Configure shared feature definitions with offline materialisation and online retrieval.

    Given a feature store and three feature definitions.

    Evidence a test showing identical values from both paths.

  4. Applied

    Test a deployed model for training-serving skew by comparing logged and recomputed features.

    Given a service with seeded skew in null handling and time zones.

    Evidence a skew report with cause and a regression test.

  5. Performance

    Build a labelling flow that samples by model uncertainty, pre-labels, routes to human review and versions the labels.

    Given a pool of synthetic dispute notes and a small open-weight model.

    Evidence a label snapshot with provenance and the share of pre-labels reviewers changed.

Topics

Features and point-in-time correctness

  • Entities, keys and event time
  • Batch, streaming and on-request features
  • Offline and online stores, freshness and backfills
  • As-of joins and late-arriving data

Training-serving skew

  • Causes: duplicated code, defaults, versions
  • Logging served features
  • Skew checks; monitoring is DEV-OPS-301

Labelling flows

  • Choosing what to label next
  • Model pre-labels and anchoring bias
  • Label provenance and versioning; guidelines and agreement are DEV-EVL-304

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Feature store
Feast, open table format with SQL as-of joins
Analytical SQL engine
DuckDB, Polars
Labelling and review interface
Label Studio, a notebook review queue
Data versioning
DVC, lakeFS

How the work is assessed

  • Supervised AI-off check on three join queries (10%)
  • Graded labs (50%)
  • Capstone with review (40%)
To pass
70% overall, and the capstone's point-in-time test passes on re-run

Use of AI in the course

AI-off for the join check. AI-tutor in labs. AI-full in the capstone, explained live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
