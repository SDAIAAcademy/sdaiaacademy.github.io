DEV-SEC-305 AI for Security Operations

  • Level 300 · Develop
  • Workshop
  • 16 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-SEC Security and Privacy Engineering for AI

Level

Level 300 · Develop

Audience

practitioner

Format

Workshop: two days with labs and a short build project

Total hours

16 h

Prerequisites

  • Reads security alerts, logs and incident tickets
  • Writes Python and has called a language model API

Description

On a lab network with synthetic telemetry and vulnerable applications, participants build and measure AI assistance for security operations: alert triage scored against analyst labels, detection rules tested on recorded attacks, model-assisted review of code and configuration beside static analysers, and generated fuzzing harnesses. They defend the tools against attacker text in logs and keep containment behind human approval. Staff use of AI tools is USE-PRO-212.

Learning outcomes

By the end, the participant can:

  1. Performance

    Build an alert-triage assistant that ranks and summarises alerts with cited evidence.

    Given a day of labelled synthetic alerts.

    Evidence precision at the top of the queue against the existing ordering.

  2. Applied

    Test model-drafted detection rules before deployment.

    Given recorded attacks and a day of benign logs.

    Evidence detection and false-alarm counts per rule.

  3. Applied

    Measure model-assisted code and configuration review and generated fuzzing harnesses against static analysis.

    Given a vulnerable application and its manifests.

    Evidence verified true and false findings per method.

  4. Applied

    Test a security assistant against injection hidden in log fields and tickets.

    Given poisoned events.

    Evidence a test report and a fix.

  5. Performance

    Design the handling of AI-generated findings from verification to approved containment.

    Given an incident scenario.

    Evidence a runbook tested in a tabletop walk-through.

Topics

Help and harm

  • Invented findings and confident errors
  • Attacker-controlled text in telemetry
  • Gain against an unaided baseline

Detection and triage

  • Enrichment and ranking with cited evidence
  • Detection rules in an open format

Review and discovery

  • Model review beside static analysers
  • Fuzzing harness generation
  • Reproducing a crash before reporting

Safe handling

  • Human approval for containment
  • Sensitive telemetry and model placement
  • Authorised scope and coordinated disclosure

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Language model access
a locally served open-weight model, a hosted model for public code
Log analytics
Wazuh, OpenSearch
Detection rules
Sigma, YARA
Static analysis
Semgrep, CodeQL, Checkov
Fuzzing
AFL++, Atheris
Technique knowledge base
MITRE ATT&CK, MITRE ATLAS

How the work is assessed

  • Supervised check: triage five alerts unaided (25%)
  • Labs (35%)
  • Capstone and walk-through (40%)
To pass
60% overall and four of five supervised verdicts correct

Use of AI in the course

AI-off in the supervised triage, keeping an unaided baseline; AI-tutor in labs 1 and 2; AI-full afterwards, with every finding verified.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
