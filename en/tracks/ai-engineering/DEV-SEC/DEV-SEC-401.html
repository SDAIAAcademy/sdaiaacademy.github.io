DEV-SEC-401 Security Architecture for AI Platforms

  • Level 400 · Evaluate
  • Intensive
  • 24 h
  • Audience: specialist

Track

AI Engineering

Stream

DEV-SEC Security and Privacy Engineering for AI

Level

Level 400 · Evaluate

Audience

specialist

Format

Intensive: 3 teaching days and a design review day, with guided pre-work and a tracked follow-up task

Total hours

24 h

Prerequisites

  • DEV-SEC-301 Securing Language Model and Agent Applications
  • Has designed or reviewed a production service used by several teams
  • Reads OAuth flows and access-control policies

Description

Participants design and review the security architecture of a shared platform on which many teams run assistants and agents against an organisation's data. For a fictional ministry platform they set an identity for every agent and the person it acts for, least privilege across tools, stores and indexes derived from data classification, isolation tiers matched to code trust and sensitivity, action-level monitoring with kill switches, and the assurance evidence auditors ask for. They critique a rival design and defend a reference architecture before a panel. Building these parts is DEV-AGT-402; sovereign placement is DEV-INF-405.

Learning outcomes

By the end, the participant can:

  1. Performance

    Design an identity model that binds every agent action to an agent, a delegating person and a scoped grant.

    Given three delegation chains.

    Evidence token flows with lifetimes and revocation paths.

  2. Performance

    Design least-privilege access across tools, stores and indexes derived from data classification.

    Given a classified data inventory.

    Evidence a policy model with tests of denied flows.

  3. Performance

    Decide isolation tiers by code trust, tenant and data sensitivity.

    Given five workload profiles and a cost limit.

    Evidence a decision record with trade-offs.

  4. Performance

    Design action monitoring that detects unsafe tool-call sequences.

    Given recorded traces with seeded misuse.

    Evidence detection rules with measured detection and false-alarm rates.

  5. Applied

    Prepare a control map to an AI controls framework and national controls.

    Given the reference architecture.

    Evidence a map with evidence per control and listed gaps.

  6. Performance

    Review two competing platform security designs and recommend one.

    Given two design documents.

    Evidence a written review defended before a panel.

Topics

Threat model of a shared platform

  • Cross-tenant leakage and confused deputies
  • Shared prompt caches and indexes as tenant channels
  • Cascading failures and rogue agents
  • Insider and supplier threats

Identity for agents

  • Workload identity and attestation
  • Token exchange at every hop
  • Never deciding access from nested actor claims
  • Consent, revocation and immature standards

Least privilege across tools and data

  • Classification-driven policy
  • Permission-aware retrieval and index partitioning
  • Toxic flows: private data, untrusted content, exits

Isolation tiers

  • Container, user-space kernel and micro virtual machine
  • Confidential computing
  • Egress architecture and credential proxies

Monitoring and assurance

  • Action-level audit trails
  • Kill switches and blast radius
  • Control frameworks and evidence packs
  • Decision records

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Policy engine
Open Policy Agent, Cedar, OpenFGA
Workload identity and token exchange
SPIFFE and SPIRE, Keycloak
Isolation runtimes
gVisor, Kata Containers, Firecracker
Agent and protocol gateway
agentgateway, Agent Router
Trace analysis
OpenTelemetry with Jaeger, OpenSearch
Control frameworks
Cloud Security Alliance AI Controls Matrix, ISO/IEC 42001 Annex A, NIST AI 600-1

How the work is assessed

  • Supervised check: find flaws in a delegation design (20%)
  • Design labs (30%)
  • Reference architecture and panel defence (50%)
To pass
70% overall and a pass from the panel

Use of AI in the course

AI-off in the supervised check; AI-tutor in labs; AI-full for the reference architecture, defended unaided before the panel.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
