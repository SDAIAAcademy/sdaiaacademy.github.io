DEV-SEC-304 AI Supply Chain Security: Signing, Bills of Materials and Provenance

  • Level 300 · Develop
  • Workshop
  • 12 h
  • Audience: practitioner

Track

AI Engineering

Stream

DEV-SEC Security and Privacy Engineering for AI

Level

Level 300 · Develop

Audience

practitioner

Format

Workshop: one and a half days with labs and an adoption review

Total hours

12 h

Prerequisites

  • Builds container images and edits a continuous integration pipeline
  • Has loaded an open-weight model from a hub

Description

Participants secure the path by which models, datasets and dependencies reach production. On a pipeline pulling an open-weight model and a public dataset, they catch a tampered file and an unsafe format, sign and verify a manifest of hashed model files, generate a machine-learning bill of materials, store models as registry artefacts and fail builds on unacceptable licences. Supplier governance is LDS-AIG-203; release gating is DEV-OPS-401.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Explain where models, datasets, packages, prompts, tools and skills enter an AI system and the attack at each point.

    Given a pipeline diagram.

    Evidence an annotated diagram with six entry points.

  2. Applied

    Test downloaded model files for unsafe serialisation and tampering before loading.

    Given artefacts with two planted problems.

    Evidence a scan report and a converted safe copy.

  3. Applied

    Prepare a machine-learning bill of materials with model, dataset and licence provenance.

    Given the case-study service.

    Evidence a file that passes schema validation.

  4. Performance

    Build a pipeline that signs model manifests and blocks unsigned, modified or badly licensed artefacts.

    Given continuous integration and a licence policy.

    Evidence passing and failing runs with logs.

  5. Performance

    Evaluate a third-party model's supply-chain evidence and decide whether to adopt it.

    Given an unseen model, card and dataset.

    Evidence a one-page decision defended live.

Topics

Attack surface

  • Entry points from weights to skills
  • Poisoned and mislabelled artefacts
  • Code execution on model load

Provenance

  • Model and dataset cards as evidence
  • Bills of materials in open formats
  • Build provenance attestations

Signing and registries

  • Signing a manifest of hashed files
  • Models as registry artefacts
  • Verification at admission

Licences

  • Licences and acceptable-use terms
  • Licence policy as code
  • Re-checking upstream changes

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Model signing
OpenSSF Model Signing, Sigstore cosign
Bill of materials tooling
CycloneDX ML-BOM, SPDX, Syft
Model file scanning
ModelScan, fickling
Model registry
a container registry holding ModelPack artefacts, MLflow
Policy as code
Open Policy Agent, Kyverno

How the work is assessed

  • Supervised check: mark attacks on an unseen pipeline (20%)
  • Labs (40%)
  • Adoption review (40%)
To pass
60% overall and a working gate in lab 4

Use of AI in the course

AI-off in the supervised check; AI-tutor in labs; AI-full in the adoption review, defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
