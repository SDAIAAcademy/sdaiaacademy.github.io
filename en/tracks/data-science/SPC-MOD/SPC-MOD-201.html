SPC-MOD-201 Machine Learning for Tabular Data: Baselines and Validation

  • Level 200 · Apply
  • Intensive
  • 36 h
  • Audience: practitioner

Track

Data Science

Stream

SPC-MOD Machine Learning and Modelling

Level

Level 200 · Apply

Audience

practitioner

Format

Intensive: 4 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

36 h

Prerequisites

  • FND-AIC-101 How Machine Learning Works
  • FND-DAT-102 Data Wrangling with DataFrames
  • Computes and reads a bootstrap interval

Description

Participants answer a prediction question on tabular data the way an independent reviewer will check it. They climb a baseline ladder, tune gradient-boosted trees under a fixed budget, test an automated or pretrained challenger on the same folds, choose validation that mirrors use, audit for leakage, break errors down by subgroup and write a model card. Data are public or synthetic, with repeated entities and dates that defeat naive splits. Production pipelines are DEV-MLE-201.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Identify the leakage type and the fitting validation scheme in short modelling cases.

    Given ten cases with grouped, temporal or independent data.

    Evidence a classification sheet, at least eight of ten matching the reference.

  2. Applied

    Apply a baseline ladder from a constant predictor to tuned gradient-boosted trees, logging every run.

    Given a public dataset with a framed target, metric and tuning budget.

    Evidence a results table with fold-level scores and bootstrap intervals.

  3. Applied

    Implement validation that matches the data structure and measure how far a random split overstates performance.

    Given synthetic data with repeated customers over twelve months.

    Evidence a notebook comparing random, grouped and time-ordered estimates.

  4. Applied

    Test an automated or pretrained challenger against the tuned champion under identical folds and budget.

    Given a challenger chosen from the tool list.

    Evidence a table of paired differences, run time and licence terms.

  5. Applied

    Analyse held-out errors by subgroup with intervals that reflect slice size.

    Given predictions with synthetic demographic attributes.

    Evidence a slice report naming the worst slices and their uncertainty.

  6. Performance

    Audit another analyst's modelling notebook and decide whether its reported score can be trusted.

    Given a notebook with seeded leakage and validation faults.

    Evidence an audit memo with each fault re-measured and a corrected estimate.

Topics

Framing and baselines

  • Target, unit and moment of prediction
  • Metrics tied to the cost of errors
  • Class imbalance and decision thresholds
  • Constant, rule and regularised linear baselines

Boosted trees and challengers

  • Key settings, early stopping and tuning budgets
  • Automated search and post-hoc ensembling
  • Pretrained tabular models: row limits and licences

Validation and leakage

  • Stratified, grouped and time-ordered splits
  • Nested tuning and an untouched test set
  • Imputation, scaling and target encoding fitted inside folds
  • Leakage types and feature availability at prediction time

Error analysis and documentation

  • Slicing by subgroup and operating condition
  • Small slices and honest intervals
  • Model cards and verification notes for AI-assisted code

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Analysis language and notebooks
Python with Jupyter or marimo, R with Quarto
Machine learning library with splitters
scikit-learn, tidymodels
Gradient-boosted trees
LightGBM, XGBoost, CatBoost
Automated or pretrained challenger
AutoGluon, TabPFN under its licence
Run tracking
MLflow, a versioned run log

How the work is assessed

  • Supervised AI-off check on validation and leak spotting (20%)
  • Graded labs (35%)
  • Capstone repository on a rubric (45%)
To pass
65% overall and at least 60% on the capstone

Use of AI in the course

AI-off for the supervised check and the leakage lab. AI-tutor in other labs. AI-full in the capstone, with a verification note, defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
