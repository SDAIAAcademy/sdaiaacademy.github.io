DS-408 Analytics Products: Semantic Layers and Conversational Analytics

  • Level 400 · Evaluate
  • Intensive
  • 26 h
  • Audience: specialist

Track

Data Science

Stream

Level

Level 400 · Evaluate

Audience

specialist

Format

Intensive: 4 teaching days of four sessions and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

26 h

Prerequisites

  • DS-307 Metrics, Semantic Models and Dashboards
  • Writes SQL over a star schema, including window functions
  • Has defined metrics in a semantic layer or a BI calculation language

Badge

Helps prepare for the SDAIA Data Science badge, Expert level.

Description

Participants build the analytics product of the fictional Qamar Telecom, whose 300 managers want to ask questions in Arabic and English about usage, billing, collections and complaints. They define metrics once as tested code with owners, design a semantic layer with conformed time, tariff history and access rules by region and classification, expose it to tools and agents, and evaluate a conversational assistant on certified questions, ending with a policy on which questions the assistant may answer. DS-307 covers single-area metrics, dashboards and a first agent test; this course designs the layer across business areas and governs the assistant.

Learning outcomes

By the end, the participant can:

  1. Performance

    Design a semantic layer with entities, grain, conformed time and governed metrics for several business areas.

    Given the company's marts, a tariff history and Hijri and fiscal calendars.

    Evidence model files whose reconciliation tests pass against source totals.

  2. Applied

    Implement metric definitions as code with owners, tests and change control.

    Given three conflicting definitions of the collection rate.

    Evidence metric files and one change taken through review in continuous integration.

  3. Applied

    Configure row-level access and field masking in the semantic layer according to data classification.

    Given three user roles and the national classification levels.

    Evidence access tests that pass for each role and catch a seeded leak.

  4. Performance

    Evaluate a conversational assistant on certified questions, measuring accuracy, stability, wrong but plausible answers and the contribution of each kind of semantic context.

    Given 60 bilingual questions with certified answers and a fixed model.

    Evidence a report from a harness a reviewer can re-run.

  5. Performance

    Decide which question types the assistant may answer and under which safeguards.

    Given the evaluation results and a stated tolerance for wrong figures.

    Evidence a routing policy with a decision record.

  6. Performance

    Review the design of a peer's analytics product for correctness, portability and governance.

    Given a peer's semantic model and evaluation.

    Evidence design review notes with findings ranked by risk.

Topics

Metrics as products

  • One definition, one owner, tests
  • Ratio, cumulative and derived metrics
  • Certification, versioning and deprecation

Semantic layer design

  • Conformed dimensions across business areas
  • Pre-aggregation, caching and query cost
  • Classification-aware access rules
  • Open interchange specifications

Conversational analytics

  • Certified question sets by area and difficulty
  • Which context helps: synonyms, descriptions, examples
  • Execution accuracy and wrong but plausible answers
  • Stability across repeated runs

Shipping and governing

  • Serving metrics to tools and agents
  • Showing the metric, filters and grain behind each figure
  • Routing by measured risk

Day by day

Four sessions a day. Each session presents the concepts with a demonstration, then ends in a lab.

#SessionLab
Day 1 Metrics as products
1.1One metric, three ownersReconcile the collection rate as finance, collections and customer care define it and agree one certified definition
1.2Metrics as code with testsImplement five metrics, including a ratio and a cumulative metric, with reconciliation tests
1.3Ownership and change controlWrite the change process for a metric and take one change through review
1.4Certification and deprecationVersion and deprecate metrics in a 40-metric catalogue and list the reports that still use a deprecated one
Day 2 Design the semantic layer
2.1Conformed dimensions across areasModel subscribers, lines, bills and complaints with conformed customer and time dimensions and fix a cross-area fan-out
2.2Performance and costAdd pre-aggregations for the ten most-asked metrics and measure query latency before and after
2.3Access rulesAdd row-level rules by region, mask Restricted fields and test with three roles
2.4PortabilityExport the model to an open interchange format and query it from a second engine
Day 3 Test the assistant
3.1A certified set for a platformExtend the supplied certified set to cover each business area and difficulty level, including questions the assistant must refuse
3.2Which context helpsRemove synonyms, descriptions and examples one at a time from the supplied configuration and re-score each variant with the supplied scorer
3.3A scoring harnessBuild a harness that reports execution accuracy and the rate of wrong but plausible answers
3.4Ask it againRun each question three times and measure how often the answers agree
Day 4 Ship and govern
4.1Serving metrics to tools and agentsExpose the semantic layer through an API or protocol server with role-scoped credentials
4.2Safeguards that show their workMake the assistant cite the metric and filters used and refuse uncertified metrics
4.3Which questions may go to the assistantSet a routing policy from the evaluation and a stated tolerance for wrong figures
4.4Design reviewPresent the product design to a peer panel and log the decisions taken

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Transformation framework
SQLMesh, dbt
Semantic layer and metric definitions
MetricFlow, Cube Core, Apache Ossie (Open Semantic Interchange) files
Analytical engine
DuckDB, PostgreSQL
Access for tools and agents
a Model Context Protocol server, a REST API over the semantic layer
Language model through a chat-completions style endpoint
a locally served open-weight model, a free hosted model
Evaluation harness
pytest with custom assertions, promptfoo, Inspect

How the work is assessed

  • Supervised check of modelling and metric fundamentals without AI assistance (20%)
  • Capstone rubric: semantic model and metrics 30, access rules 15, assistant evaluation 30, routing policy 15, reproducibility 10 (60%)
  • Live design review and defence (20%)
To pass
70% overall and at least 60% on the capstone rubric

Use of AI in the course

AI-off for the supervised check and the first metric reconciliation on day 1. AI-tutor in the labs. AI-full in the capstone, coding agents included, with the design and evaluation defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
