SPC-DLR-306 Post-Training I: Fine-Tuning, Preference Optimisation and Distillation

  • Level 300 · Develop
  • Extended
  • 60 h
  • Audience: specialist

Track

Data Science

Stream

SPC-DLR Deep Learning and Model Development

Level

Level 300 · Develop

Audience

specialist

Format

Extended: 10 weeks part-time, one lecture and one long lab a week, four graded assignments, a supervised test and a post-training capstone

Total hours

60 h

Prerequisites

  • SPC-DLR-303 Building a Language Model from Scratch
  • Has fine-tuned a pretrained network and read its loss curves
  • Runs a model evaluation with a harness; DEV-EVL-301 or SPC-TRU-301 is recommended

Description

Participants take a small open-weight base model through instruction tuning, preference optimisation and distillation, writing each loss themselves before using a library. They build datasets with correct chat templates and loss masks, compare full fine-tuning with low-rank adapters (LoRA), train a reward model and a direct preference optimisation (DPO) run, distil a larger open model into a smaller one, merge checkpoints, and measure what each step adds and costs, including forgetting and safety regressions. Reinforcement learning is SPC-DLR-401; application-level adaptation is DEV-LLM-301.

Learning outcomes

By the end, the participant can:

  1. Applied

    Prepare instruction and preference datasets with chat templates, loss masking, decontamination and licence checks.

    Given permissively licensed public sources and synthetic Arabic and English examples.

    Evidence a dataset card and passing template tests.

  2. Performance

    Build supervised fine-tuning runs with full-parameter and low-rank adapter variants and decide between them.

    Given a small open-weight base model and a fixed accelerator budget.

    Evidence a comparison of quality, memory and forgetting with a justified choice.

  3. Performance

    Build a reward model and a DPO run from their loss functions.

    Given a preference dataset and a library implementation for reference.

    Evidence matching losses, reward accuracy on held-out pairs and judged win rates.

  4. Applied

    Apply sequence-level and logit-level distillation from a larger teacher to a smaller student.

    Given an open teacher whose licence permits distillation.

    Evidence a table comparing student, teacher and a supervised-only baseline.

  5. Applied

    Apply weight-merging methods to combine checkpoints tuned for different skills.

    Given two fine-tuned checkpoints.

    Evidence scores of each merge method on both skills.

  6. Performance

    Evaluate an adapted model for improvements, forgetting, instruction following and safety regressions.

    Given a held-out suite, a model grader validated against human labels, and language slices.

    Evidence a report with uncertainty and a recommendation to adopt or reject.

Topics

Supervised fine-tuning

  • Base and instruction models; chat templates
  • Loss masking and sequence packing
  • Full fine-tuning, LoRA and quantised adapters
  • Catastrophic forgetting

Preference optimisation

  • Pairwise reward models
  • Reinforcement learning from human feedback (RLHF) in outline
  • Direct preference methods and variants
  • Over-optimisation against a reward

Distillation

  • Logit, sequence-level and on-policy distillation
  • Distilling reasoning traces
  • Licence terms on teacher outputs

Merging

  • Linear and spherical interpolation
  • Task arithmetic, TIES and DARE
  • When merging helps

Evaluating adapted models

  • Held-out capability suites
  • Validated model graders
  • Refusal and safety regressions
  • Contamination and language slices

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Tensor framework
PyTorch, JAX
Post-training and adapter libraries, used after own implementations
TRL with PEFT adapters, own training loop with hand-written adapters
Checkpoint merging
mergekit, own task-arithmetic code
Fast sampling for generation and evaluation
vLLM, SGLang, llama.cpp
Evaluation harness
Inspect, lm-evaluation-harness

How the work is assessed

  • Four assignments with loss-function tests (30%)
  • Supervised test without AI assistance on losses, templates and evaluation design (20%)
  • Capstone report and review (50%)
To pass
60% on the supervised test and 70% overall

Use of AI in the course

AI-off for the supervised test and the first implementation of each loss. AI-tutor in the labs. AI-full in the capstone for data and evaluation code, disclosed and defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
