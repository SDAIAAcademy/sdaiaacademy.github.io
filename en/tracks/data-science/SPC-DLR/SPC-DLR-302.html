SPC-DLR-302 Deep Learning from First Principles

  • Level 300 · Develop
  • Extended
  • 80 h
  • Audience: specialist

Track

Data Science

Stream

SPC-DLR Deep Learning and Model Development

Level

Level 300 · Develop

Audience

specialist

Format

Extended: 12 weeks part-time, two sessions a week (concepts, then a supervised lab), weekly build modules, two supervised tests and a reproduction capstone

Total hours

80 h

Prerequisites

  • SPC-DLR-301 Mathematics for Model Builders
  • Writes object-oriented Python and NumPy code
  • Has trained a classical model and reported held-out metrics, at the depth of FND-AIC-101

Description

Participants build deep learning from the bottom up, then test what they believe about it. They extend their scalar engine from SPC-DLR-301 into a small NumPy tensor library with broadcasting, layers and optimisers, and train a convolutional network with it. They then use a standard framework to train convolutional, recurrent and transformer models on public data, transfer hyperparameters across widths, probe a self-supervised encoder and run controlled ablations over several seeds. Production training pipelines are DEV-MLE-202.

Learning outcomes

By the end, the participant can:

  1. Performance

    Build a tensor library with automatic differentiation, layers, losses and optimisers on the SPC-DLR-301 engine.

    Given selected module skeletons with automated tests and no deep learning framework.

    Evidence a library that passes every module test and trains a convolutional network to a stated accuracy.

  2. Applied

    Implement and train multilayer, convolutional, recurrent and transformer models in a standard framework.

    Given public image and text datasets and a fixed accelerator budget.

    Evidence training logs that reach each reference result within a stated tolerance.

  3. Applied

    Apply schedules, normalisation, initialisation and width-aware hyperparameter transfer when tuning a model.

    Given a width sweep of small transformers.

    Evidence plots of how the best learning rate moves with width under standard and width-aware settings.

  4. Performance

    Diagnose why a training run fails or underperforms and fix the cause.

    Given seeded faults in initialisation, normalisation, learning rate and data loading.

    Evidence a log naming each cause, the check that confirmed it and the fix.

  5. Applied

    Measure the quality of learned representations with linear probes and nearest-neighbour retrieval.

    Given a self-supervised encoder and a supervised baseline.

    Evidence a probe table with intervals over seeds.

  6. Performance

    Design and run a controlled ablation that tests a claim about architecture, optimisation or generalisation.

    Given a stated hypothesis, three or more seeds per arm and a compute limit.

    Evidence a report with effect sizes, uncertainty and a conclusion the data supports.

Topics

Automatic differentiation and frameworks

  • Reverse mode on tensors
  • Broadcasting and its gradients
  • Saved activations and memory

Optimisation and scaling rules

  • Momentum, AdamW, warm-up and decay
  • Initialisation and normalisation
  • Hyperparameter transfer across width
  • Newer optimisers as claims to test

Architectures and inductive bias

  • Residual and convolutional networks
  • Recurrent and state-space models in one session
  • Attention and the transformer block

Generalisation

  • Regularisation and augmentation
  • Overparameterisation and double descent
  • Distribution shift and calibration

Representation learning

  • Contrastive and masked self-supervision
  • Linear probes and embedding geometry
  • Transfer to new tasks

Experimental practice

  • Debugging on a CPU before spending accelerator hours
  • Seeds, variance and intervals
  • Experiment tracking

How the work is assessed

  • Weekly build modules with automated tests, pass or fail (20%)
  • Two supervised tests without AI assistance (35%)
  • Graded labs (15%)
  • Capstone report and oral (30%)
To pass
All build modules passed, 60% on the supervised tests and 70% overall

Use of AI in the course

AI-off for first attempts at the build modules and for the supervised tests. AI-tutor in the framework labs. AI-full in the capstone, disclosed, with every experimental choice defended unaided.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
