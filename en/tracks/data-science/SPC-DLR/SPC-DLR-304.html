SPC-DLR-304 Training Systems for Large Models

  • Level 300 · Develop
  • Extended
  • 60 h
  • Audience: specialist

Track

Data Science

Stream

SPC-DLR Deep Learning and Model Development

Level

Level 300 · Develop

Audience

specialist

Format

Extended: 10 weeks part-time, one lecture and one long lab a week on a provided multi-GPU node, four graded assignments, a supervised test and a performance capstone

Total hours

60 h

Prerequisites

  • SPC-DLR-303 Building a Language Model from Scratch
  • Explains processes, memory hierarchy and caches, at the depth of FND-PRG-105
  • Reads simple C or array-kernel code

Description

Participants make a language model train faster and larger on the hardware they have. They account for floating-point operations (FLOPs), memory and communication before running anything, profile a training step, write a fused attention kernel and test it against a reference, fit a larger model into memory with mixed precision and activation checkpointing, and build sharded data parallelism from collective primitives, tracking model FLOPs utilisation (MFU) throughout. Labs debug on CPU processes, then run on a provided multi-GPU node. Fleet operation at scale is DEV-INF-402.

Learning outcomes

By the end, the participant can:

  1. Applied

    Compute the arithmetic, memory and communication cost of a training configuration and predict its step time with a roofline model.

    Given published accelerator specifications.

    Evidence a resource sheet set beside measured step time and peak memory.

  2. Applied

    Analyse a profiler trace of a training step, attributing time to kernels, transfers, data loading and communication.

    Given a reference script for a small transformer.

    Evidence an annotated trace naming the three largest bottlenecks.

  3. Performance

    Build a fused attention kernel with tiling and an online softmax.

    Given a kernel language, a reference implementation and a test harness.

    Evidence passing correctness tests and time and memory benchmarks across sequence lengths.

  4. Performance

    Build data-parallel training with sharded optimiser state from collective communication primitives.

    Given several worker processes, first on CPU and then on GPUs.

    Evidence loss curves matching a single-device run and a scaling-efficiency table.

  5. Performance

    Optimise end-to-end training throughput under a fixed memory limit without changing results beyond a stated tolerance.

    Given a reference script and the provided node.

    Evidence MFU, peak memory and loss-parity plots before and after.

  6. Applied

    Analyse tensor, pipeline, sequence and expert parallelism plans for a model too large for one node.

    Given an analytical simulator and an interconnect specification.

    Evidence a one-page plan with memory per device, communication time and expected utilisation.

Topics

Resource accounting

  • FLOPs and memory per training step
  • Arithmetic intensity and the roofline model
  • Model FLOPs utilisation

Profiling and benchmarking

  • Timers, synchronisation and warm-up
  • Profiler traces
  • Variance and honest benchmarks

Kernels

  • GPU execution model and memory hierarchy
  • Tiling and fusion
  • Compilers against hand-written kernels

Precision and memory

  • Low-precision formats including 8-bit floating point
  • Loss scaling
  • Activation checkpointing, accumulation and offloading

Distributed training

  • Collective operations and their cost
  • Data parallelism and sharded state
  • Tensor, pipeline, sequence and expert parallelism
  • Checkpointing and restart

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Tensor framework and distributed runtime
PyTorch distributed, JAX with sharding, DeepSpeed
GPU kernel language
Triton, CUDA C++
Profilers and trace viewers
the framework profiler, Nsight Systems, Perfetto
Analytical performance model
MLSys·im, a spreadsheet roofline model
Compute
a provided node with several GPUs, CPU worker processes for debugging

How the work is assessed

  • Four assignments with correctness and speed tests (35%)
  • Supervised test without AI assistance on resource arithmetic and parallelism (20%)
  • Capstone report and review (45%)
To pass
Correctness tests passed on every assignment, 60% on the supervised test and 70% overall

Use of AI in the course

AI-off in the supervised test and for the first version of the attention kernel. AI-tutor in the other labs. AI-full in the capstone, where every speed claim needs a trace the participant explains.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
