SPC-DLR-401 Post-Training II: Reinforcement Learning for Language Models

  • Level 400 · Evaluate
  • Extended
  • 60 h
  • Audience: specialist

Track

Data Science

Stream

SPC-DLR Deep Learning and Model Development

Level

Level 400 · Evaluate

Audience

specialist

Format

Extended: 10 weeks part-time, one seminar and one long lab a week on a provided multi-GPU node, four graded assignments, a supervised test and a reproduction capstone

Total hours

60 h

Prerequisites

  • SPC-DLR-306 Post-Training I: Fine-Tuning, Preference Optimisation and Distillation
  • Explains policy gradients and value baselines at the depth of an introductory reinforcement learning course such as SPC-GEN-304
  • Runs containers and writes unit tests

Description

Participants train language models with reinforcement learning (RL) against rewards that can be checked. They write a policy-gradient loop with group-relative advantages and a divergence penalty, build verifiers for maths, code and structured outputs, train a small open model to reason, and find and close the reward hacks it discovers. They measure accuracy against test-time compute and train on verified agent trajectories from a sandboxed coding environment. Every result is compared at equal compute with a supervised or distillation baseline.

Learning outcomes

By the end, the participant can:

  1. Performance

    Build an RL training loop for a language model with group-relative advantages, clipping and a divergence penalty.

    Given a toy arithmetic task and a library implementation for reference.

    Evidence tests and reward curves that agree with the reference.

  2. Performance

    Design verifiable reward functions for maths, code and format tasks that reject known exploits.

    Given tasks with reference answers and unit tests.

    Evidence a verifier test suite including adversarial cases written by another participant.

  3. Performance

    Diagnose reward hacking and pathologies such as length inflation, format gaming and entropy collapse, and fix them.

    Given rollout samples and training metrics.

    Evidence an incident note with samples from before and after the fix.

  4. Performance

    Evaluate test-time compute strategies and choose an allocation for a fixed inference budget.

    Given a trained model and a verifier.

    Evidence accuracy-against-compute curves with intervals for sampling, voting, reranking and longer reasoning.

  5. Performance

    Decide whether RL, fine-tuning on filtered samples or distillation gives the largest improvement on a task at equal compute.

    Given a fixed accelerator budget.

    Evidence a decision memo with the controlled comparison.

  6. Applied

    Prepare verified agent trajectories from a sandboxed environment and use them for rejection-sampling fine-tuning.

    Given a containerised coding environment with tests.

    Evidence a trajectory dataset card and task success over several trials before and after training.

Topics

RL for language models

  • Policy gradients, baselines and advantages
  • Clipping, divergence control and critic-free estimators
  • Rollout and training systems

Rewards

  • Verifiable rewards for maths, code and formats
  • Outcome, process and learned reward models, and their limits
  • Reward hacking and specification gaming

Reasoning training

  • Cold start with supervised data
  • Curricula and difficulty filtering
  • Whether written reasoning reflects the computation

Test-time compute

  • Best-of-n, voting and verifier reranking
  • Sequential refinement and budget control
  • Compute-optimal allocation and reporting

Learning from agent trajectories

  • Environments, sandboxes and task contracts
  • Trajectory curation and credit assignment
  • Multi-turn RL with tools

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Rollout generation
vLLM, SGLang
RL training
own implementation, TRL
Code-execution sandboxes
containers with gVisor isolation, Docker or Podman with networking disabled
Evaluation harness
Inspect, lm-evaluation-harness
Compute
a provided multi-GPU node with a per-participant budget, CPU runs for debugging

How the work is assessed

  • Four assignments with tests (30%)
  • Supervised test without AI assistance (15%)
  • Reproduction capstone report (40%)
  • Panel defence (15%)
To pass
60% on the supervised test, 70% overall and a pass on the panel defence

Use of AI in the course

AI-off for the supervised test and the first policy-gradient implementation. AI-tutor in the labs. AI-full in the capstone, research agents included, with the participant accountable for every claim.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
