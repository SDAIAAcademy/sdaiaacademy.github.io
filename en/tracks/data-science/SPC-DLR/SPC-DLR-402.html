SPC-DLR-402 Efficient Deep Learning: Compression, Quantisation and Long Context

  • Level 400 · Evaluate
  • Extended
  • 60 h
  • Audience: specialist

Track

Data Science

Stream

SPC-DLR Deep Learning and Model Development

Level

Level 400 · Evaluate

Audience

specialist

Format

Extended: 10 weeks part-time, one lecture and one long lab a week, four graded assignments, a supervised test and a compression capstone

Total hours

60 h

Prerequisites

  • SPC-DLR-302 Deep Learning from First Principles
  • SPC-DLR-303 Building a Language Model from Scratch
  • Profiles a training or inference step and reads the trace (SPC-DLR-304 recommended)
  • Has run logit-level distillation (SPC-DLR-306 recommended)

Description

Participants make models smaller, faster and able to read longer inputs, and measure what each method costs in quality. They prune convolutional and transformer models, quantise weights, activations and the key-value cache to 8 and 4 bits after and during training, distil a compressed student, extend a model's context window, and train a small mixture-of-experts (MoE) layer. Each change is judged on a quality, latency and memory frontier measured on real hardware. Serving engineering is DEV-INF-401; on-device deployment is DEV-INF-303.

Learning outcomes

By the end, the participant can:

  1. Applied

    Apply magnitude, structured and semi-structured (N:M) pruning, and measure accuracy against sparsity and real speed-up.

    Given a convolutional network and a small transformer trained on public data.

    Evidence accuracy and measured latency curves, with an explanation of where speed-up appears.

  2. Performance

    Build a post-training quantisation pipeline with calibration, per-channel and group scaling, and outlier handling.

    Given a small open language model and 8-bit and 4-bit targets.

    Evidence task quality, memory and latency set against a published method.

  3. Performance

    Diagnose quality loss after compression by locating sensitive layers and outliers, and repair it with mixed precision or quantisation-aware training.

    Given a compressed model that fails a quality threshold.

    Evidence a sensitivity map and a repaired model that meets the threshold.

  4. Performance

    Build a long-context extension of a small model and evaluate it beyond single-fact retrieval tests.

    Given a small open model with rotary positions and a target several times its training length.

    Evidence accuracy-by-length curves on retrieval, multi-step and long-document tasks.

  5. Applied

    Implement a mixture-of-experts layer with routing and a load-balancing loss.

    Given a small transformer and a fixed compute budget.

    Evidence expert-use statistics and quality against a dense model at equal active compute.

  6. Performance

    Design a compression plan for a target device or budget and defend it with a measured frontier.

    Given a memory and latency target.

    Evidence the plan, the frontier and the quality loss by task and language.

Topics

Measuring efficiency

  • Latency, throughput, memory and energy
  • Quality, latency and memory frontiers
  • Memory-bound decoding and what hardware accelerates

Pruning and distillation

  • Magnitude, structured and N:M sparsity
  • Distilling compressed students
  • Neural architecture search in brief

Quantisation

  • Integer and low-bit floating formats
  • Calibration, group scaling and outliers
  • Quantisation-aware training
  • Key-value cache quantisation

Long context

  • Cost of attention with length
  • Positional interpolation and rotary scaling
  • Sliding-window, sparse and linear attention, and state-space hybrids
  • Testing long context honestly

Sparse experts

  • Routing, load balancing and capacity
  • Active against total parameters
  • Consequences for serving

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Tensor framework
PyTorch, JAX
Quantised runtimes and formats
llama.cpp, ONNX Runtime, ExecuTorch
Efficient attention kernels
FlashAttention, the framework's fused attention operator
Evaluation and measurement
lm-evaluation-harness, the framework profiler
Hardware
a laptop CPU, a provided GPU, a Raspberry Pi class board

How the work is assessed

  • Four assignments with quality and speed checks (30%)
  • Supervised test without AI assistance (20%)
  • Capstone report and defence (50%)
To pass
60% on the supervised test and 70% overall

Use of AI in the course

AI-off for the supervised test and the first quantisation implementation. AI-tutor in the labs. AI-full in the capstone, with every measurement reproduced live on request.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
