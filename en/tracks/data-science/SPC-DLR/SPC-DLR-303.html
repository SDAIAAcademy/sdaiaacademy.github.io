SPC-DLR-303 Building a Language Model from Scratch

  • Level 300 · Develop
  • Extended
  • 80 h
  • Audience: specialist

Track

Data Science

Stream

SPC-DLR Deep Learning and Model Development

Level

Level 300 · Develop

Audience

specialist

Format

Extended: 12 weeks part-time, one lecture and one long lab a week, five graded assignments, a supervised test and an end-to-end training capstone

Total hours

80 h

Prerequisites

  • SPC-DLR-302 Deep Learning from First Principles
  • Writes and debugs PyTorch or JAX training code
  • Uses the command line, version control and a remote machine, at the depth of FND-PRG-102

Description

Participants write every part of a small decoder-only language model themselves, without model libraries: a byte-level byte-pair encoding (BPE) tokeniser trained on Arabic and English text, the transformer, the optimiser and training loop, and decoding with a key-value (KV) cache. After debugging on a CPU they train a model end to end on public text within a fixed accelerator budget, evaluate it and publish it with a model card. Training systems are SPC-DLR-304, data pipelines SPC-DLR-305 and post-training SPC-DLR-306.

Learning outcomes

By the end, the participant can:

  1. Performance

    Build a byte-level BPE tokeniser and compare its compression across languages.

    Given public Arabic and English text and a target vocabulary size.

    Evidence a tokeniser that passes reference tests and a table of bytes per token by language.

  2. Performance

    Build a decoder-only transformer and its training loop from tensor operations.

    Given unit tests against reference outputs.

    Evidence passing component tests and a loss curve that overfits one batch, then trains stably.

  3. Applied

    Compute parameters, operations and memory for a configuration, and choose a model size and token count within budget.

    Given a fixed number of accelerator hours.

    Evidence a resource sheet whose predicted step time and memory match the measured run within 20%.

  4. Applied

    Implement sampling strategies and a KV cache for generation.

    Given the trained model and a fixed prompt set.

    Evidence a benchmark of speed with and without the cache and of output diversity by strategy.

  5. Performance

    Diagnose instability in language model training from logged loss, gradient norms and activation statistics.

    Given seeded runs with loss spikes and divergence.

    Evidence a note naming each cause and the change that removed it.

  6. Performance

    Evaluate a trained small language model on held-out loss, benchmarks and samples, and document its limits.

    Given a published reference model of similar size.

    Evidence a model card with bits per byte, scores with intervals, a contamination check and failure modes.

Topics

Tokenisation

  • Unicode and Arabic script normalisation
  • Training and applying BPE
  • Vocabulary size and unequal token costs across languages

The transformer

  • Causal multi-head and grouped-query attention
  • Rotary positions
  • Pre-normalisation and gated feed-forward layers

Training

  • Next-token cross-entropy
  • AdamW, warm-up and cosine schedules
  • Clipping, accumulation, mixed precision and checkpoints
  • Resource accounting before a run

Decoding

  • Temperature, top-k and nucleus sampling
  • The KV cache
  • Batched generation

Evaluation

  • Perplexity and bits per byte
  • Benchmarks scored by likelihood
  • Contamination checks
  • Reading samples critically

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Tensor framework
PyTorch, JAX
Reference implementations for checking, not copying
nanochat, code of open from-scratch textbooks
Public text corpora
Arabic and English Wikipedia dumps, Common Crawl samples, small synthetic story corpora
Evaluation harness
lm-evaluation-harness, Inspect
Compute
Academy GPU hours with a per-participant budget, a laptop CPU for debugging

How the work is assessed

  • Five assignments with automated component tests (25%)
  • Supervised test without AI assistance (20%)
  • Capstone repository and model card (40%)
  • Oral defence (15%)
To pass
All component tests passed, 60% on the supervised test and 70% overall

Use of AI in the course

AI-off, including autocomplete, for model components and the supervised test. AI-tutor for debugging in labs. AI-full for capstone tooling such as data scripts and plots; the model code stays the participant's own.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
