SPC-ANL-203 Metrics, Semantic Models and Dashboards

  • Level 200 · Apply
  • Intensive
  • 30 h
  • Audience: practitioner

Track

Data Science

Stream

SPC-ANL Analysis and Business Intelligence

Level

Level 200 · Apply

Audience

practitioner

Format

Intensive: 4 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

30 h

Prerequisites

  • FND-DAT-101 SQL and Relational Data
  • SPC-ANL-201 Exploratory Analysis and Visualisation
  • Writes SQL with joins, grouping and window functions

Description

Participants turn business questions from a synthetic service organisation into governed metrics, each with a definition, formula, grain, filters, owner and tests. They build a star-schema semantic model over a small warehouse, define metrics once in an open specification, and design a dashboard that answers the questions with few charts and loads within a time budget. They then acceptance-test a conversational analytics agent on certified questions and report where it returns wrong but plausible numbers. Metrics as tested pipeline code are DEV-DAT-202; deep platform tuning is SPC-ANL-303.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Explain where inconsistent numbers arise between metric definitions, semantic models and dashboards.

    Given two reports that disagree on one measure.

    Evidence a diagnosis naming the definitional cause.

  2. Applied

    Draft metric definitions with formula, grain, filters, time logic, owner and known limits.

    Given ten business questions and a data dictionary.

    Evidence catalogue entries that pass a peer review checklist.

  3. Applied

    Implement a dimensional semantic model with conformed dimensions and metrics defined once.

    Given a synthetic warehouse with a slowly changing dimension.

    Evidence a model returning reference values for twenty test queries.

  4. Applied

    Design a dashboard for a named audience and decision, choosing layout, comparisons and drill paths.

    Given the metric catalogue and an audience brief.

    Evidence a dashboard and one-page rationale scored on a rubric.

  5. Applied

    Measure dashboard load time and reduce it through aggregation, filters or model changes.

    Given a slow dashboard and its query log.

    Evidence before-and-after timings with the change explained.

  6. Performance

    Evaluate a conversational analytics agent against governed metrics and decide whether it is fit for a stated use.

    Given forty questions with certified answers.

    Evidence a memo with accuracy by question type, wrong but plausible examples and a go or no-go decision.

Topics

Metrics

  • Ratios, rates, distinct counts and snapshots
  • Grain, time windows and calendars
  • Metric trees from goal to driver
  • Owners, certification and change control

Semantic models

  • Star schemas and slowly changing dimensions
  • Join paths and fan-out errors
  • Metrics in an open interchange specification
  • Synonyms and descriptions as context for AI

Dashboard design and performance

  • Audience, decision and update cycle
  • Comparisons with targets, prior periods and peers
  • Freshness, as-of dates and data-quality flags
  • Accessibility and right-to-left layouts
  • Task-based testing with intended users
  • Pre-aggregation and load-time budgets

Conversational analytics

  • From question to query
  • Certified question sets
  • Wrong grain, wrong filter, invented metric
  • Human review before use

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Analytical SQL engine
DuckDB, PostgreSQL
Semantic layer and metric definitions
MetricFlow, Cube Core, Apache Ossie (Open Semantic Interchange) definitions
Dashboard tool
Apache Superset, Metabase, Power BI, Tableau
Conversational agent under test
an open-weight model with a text-to-SQL harness, a platform's built-in assistant

How the work is assessed

  • Supervised check without AI: a metric definition and a number conflict (20%)
  • Graded labs (30%)
  • Capstone and defence (50%)
To pass
70% overall and at least 60% on the capstone

Use of AI in the course

AI-off for the supervised check and first metric definitions. AI-tutor in modelling and dashboard labs. AI-full in the capstone; the agent under test is evaluated, not used as a helper.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
