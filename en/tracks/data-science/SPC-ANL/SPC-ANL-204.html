SPC-ANL-204 Data Acquisition, Preparation and Quality for Analysis

  • Level 200 · Apply
  • Intensive
  • 30 h
  • Audience: practitioner

Track

Data Science

Stream

SPC-ANL Analysis and Business Intelligence

Level

Level 200 · Apply

Audience

practitioner

Format

Intensive: 4 teaching days and a capstone day, with guided pre-work and a tracked follow-up task

Total hours

30 h

Prerequisites

  • FND-DAT-101 SQL and Relational Data
  • FND-DAT-102 Data Wrangling with DataFrames
  • Has fitted a simple linear regression and read its coefficients
  • Calls a paginated API from Python (FND-DAT-103 or equivalent)

Description

Participants assemble an analysis dataset from an API, open-data files and an internal extract. They record provenance and licences, link records across sources with and without shared keys, and clean the result with validation rules that rerun on every build. They show how missing data and measurement error move a headline estimate. They label a free-text column with a language model, measure agreement with a human-coded sample and stability across reruns, and use that sample to correct the estimate the labels feed. Pipeline gates and data contracts are DEV-DAT-204; text modelling in depth is SPC-MOD-303.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Describe missing-data mechanisms and types of measurement error, and the bias each can introduce.

    Given six described data problems.

    Evidence a matched table, at least five of six correct.

  2. Applied

    Prepare a provenance record for each source with origin, coverage, licence, refresh date and limits.

    Given an API, open-data files and an internal extract.

    Evidence a provenance file that passes a checklist.

  3. Applied

    Implement record linkage across sources, with cardinality tests, reconciliation counts and a clerical review of uncertain matches.

    Given sources with duplicate and missing keys and variant Arabic name spellings.

    Evidence a notebook that fails on unexpected fan-out, and a match-error estimate from the reviewed sample.

  4. Applied

    Configure validation rules for types, ranges, uniqueness, completeness and cross-field consistency.

    Given the joined dataset and its dictionary.

    Evidence a passing rule suite and a rejected-records report.

  5. Applied

    Analyse how complete-case analysis, imputation and a sensitivity range change a headline estimate.

    Given data missing under a known mechanism.

    Evidence a table of estimates with an interpretation.

  6. Performance

    Evaluate language-model labels of free text as a measurement instrument and decide whether they are fit for the analysis.

    Given two thousand synthetic complaints and two hundred human codes.

    Evidence a report with chance-corrected agreement, errors by class, rerun stability, a headline proportion corrected with the human sample, and a use decision.

Topics

Sourcing

  • Data requirements from the question
  • Found data versus designed data
  • Licences, coverage and selection bias

Linking and cleaning

  • Keys, grain and join cardinality
  • Linkage without shared keys: blocking, similarity, clerical review
  • Arabic name variants and transliteration
  • Linkage error and its effect on counts
  • Rules as code and change logs

Missing data and measurement error

  • Missing completely at random, at random, not at random
  • Single and multiple imputation
  • Proxies and misclassification
  • Sensitivity ranges

Labelling with language models

  • Labels as measurement
  • Codebooks and human-coded samples
  • Chance-corrected agreement
  • Correcting estimates for label error
  • Drift after model or prompt changes

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Dataframe and analytical SQL engine
pandas, Polars, DuckDB
Data validation rules
Pandera, Great Expectations, SQL assertions
Record linkage and string similarity
Splink, RapidFuzz
Imputation and agreement statistics
statsmodels, scikit-learn
Language model for labelling
a locally served open-weight model, a hosted open-weight model, any commercial API

How the work is assessed

  • Supervised check without AI on missing data and joins (20%)
  • Graded labs (30%)
  • Capstone, live rebuild and defence (50%)
To pass
70% overall and at least 60% on the capstone

Use of AI in the course

AI-off for the supervised check and first join exercises. AI-tutor in other labs. AI-full in the capstone; the labelling model is the instrument under test and is logged.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
