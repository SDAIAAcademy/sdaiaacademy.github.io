Badge

Helps prepare for the SDAIA Data Science badge, Assistant level.

Description

Participants assemble an analysis dataset for a fictional food bank network from four sources: registrations with personal data, branch logs, a donations API and open population data. They record provenance, join with key and cardinality checks, clean Arabic and English text, dates and units, write validation rules that rerun on every build, and measure how missing data and measurement error move a headline estimate. Personal data are minimised and pseudonymised, and the dataset rebuilds from raw sources with one command.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Describe missing-data mechanisms and kinds of measurement error and the bias each can introduce.

    Given six scenarios from the case.

    Evidence mechanism and bias direction for each, at least five of six correct.

  2. Applied

    Prepare a provenance record per source covering origin, owner, coverage, sharing basis, refresh date and limits.

    Given the four sources and their documentation.

    Evidence a provenance file that passes a reviewer's checklist.

  3. Applied

    Implement joins with key checks, cardinality tests and reconciliation counts so that no row is silently lost or duplicated.

    Given tables with seeded duplicate, missing and mistyped keys.

    Evidence a join log of row counts per step and set-aside rows with reasons.

  4. Applied

    Configure validation rules for types, ranges, uniqueness, completeness and cross-field consistency that run on every rebuild.

    Given the joined table and its data dictionary.

    Evidence a rule suite that passes on the clean build and fails readably on a corrupted batch.

  5. Applied

    Analyse how complete-case analysis, imputation and a sensitivity range change a headline estimate.

    Given parcels per eligible household by district, with 18% of household sizes missing.

    Evidence a comparison table and a recommended estimate with its reason.

  6. Performance

    Build a rebuildable analysis dataset from raw sources with personal data minimised and pseudonymised.

    Given a question set by the food bank and the four raw sources.

    Evidence a repository that rebuilds with one command, with provenance, rules and quality report, defended live.

Day by day

Four sessions a day. Each session presents the concepts with a demonstration, then ends in a lab.

#SessionLab
Day 1 Find and document the sources
1.1Start from the question, not the filesList the variables the question needs and a source for each
1.2Files, APIs and databasesLoad logs, page through the donations API and query registrations in SQL
1.3Provenance and sharing basisWrite provenance records for two sources, with sharing basis and gaps
1.4Coverage and sampling framesCompare registrations with open population data; flag under-covered districts
Day 2 Join and clean
2.1Encodings and Arabic textRepair mixed encodings and normalise Arabic letters and digits in names
2.2Keys and cardinalityJoin logs to registrations and report rows that break one-to-many
2.3Matching without a clean keyMatch 300 records across branches; measure false matches on labelled pairs
2.4Types, units and datesStandardise three date formats and two weight units, logging each change
Day 3 Missing data and measurement
3.1Why data go missingClassify six missingness patterns by likely mechanism
3.2Imputation and its costEstimate parcels per household with complete cases and two imputations
3.3Sensitivity rangesBound the estimate under best-case and worst-case assumptions
3.4Measurement error and proxiesSimulate self-report error in household size and measure the shift
Day 4 Validate and protect
4.1Quality dimensions as rulesWrite type, range, uniqueness and completeness rules for the joined table
4.2Cross-field and cross-source checksAdd three consistency rules and run them on a corrupted batch
4.3Minimise and pseudonymiseReplace national ID numbers with a keyed hash and attempt re-linkage
4.4A data-quality reportDraft the quality report and choose the capstone question

How the work is assessed

  • AI-off supervised entry quiz and exit check with items in the badge-exam style (20%)
  • Capstone repository on a rubric: provenance 15, joins and reconciliation 25, cleaning and validation 25, missing data and sensitivity 20, personal data and reproducibility 15 (60%)
  • Live defence with a rebuild from raw files (20%)
To pass
70% overall and at least 60% on both the capstone rubric and the supervised check

Use of AI in the course

AI-off for supervised checks and the first attempt at each join and rule. AI-tutor for regular expressions and rule syntax, hinting only. AI-full in the capstone, but no personal data, synthetic or real, goes to an external assistant; every rule is defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
