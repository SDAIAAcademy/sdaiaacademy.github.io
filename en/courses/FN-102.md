## Description

Participants take a working but fragile analysis project and make it something another person can rebuild, review and trust. The case is a fictional public library network whose monthly loans report sits in one folder with hard-coded paths, no history, unpinned packages and a key in a configuration file. Over three days they script the shell, put the project under version control, review and merge through pull requests, lock the environment, add tests that run on every push, and write a README that reports measured results. A peer then rebuilds it on a clean machine.

## Learning outcomes

By the end, the participant can:

- Explain what a commit, a branch, a merge and a pull request record, and how each can be undone safely.
- Identify where secrets, personal data, large outputs and machine-specific paths leak into a project.
- Use shell pipelines, redirection and exit codes to inspect and summarise files without writing a program.
- Use branches, pull requests and review comments to integrate a change, resolving a merge conflict without losing either side's work.
- Configure a project environment with declared dependencies and a lock file so that it installs identically on a clean machine.
- Implement tests that run in continuous integration and a README that reports measured results with the command that produced them.

## Topics

### The shell

- Paths, permissions and environment variables
- Pipes, redirection and filters
- Exit codes and short scripts
- Remote login with secure shell (SSH) keys

### Version control and review

- Commits, staging and history
- Branches, merges and conflicts
- Pull requests and review etiquette
- Undoing mistakes without rewriting shared history

### Reproducible environments

- Virtual environments
- Declared dependencies and lock files
- Pinned interpreter versions
- Data and outputs kept outside the code

### Tests and continuous integration

- Unit tests for calculations
- Small synthetic test data
- A pipeline that runs on every push

### Hygiene and reporting

- Secrets out of history: rotate, then clean
- Ignore files and pre-commit hooks
- A README that reports results
- A change log and a tagged release
