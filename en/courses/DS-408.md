## Description

Participants build the analytics product of the fictional Qamar Telecom, whose 300 managers want to ask questions in Arabic and English about usage, billing, collections and complaints. They define metrics once as tested code with owners, design a semantic layer with conformed time, tariff history and access rules by region and classification, expose it to tools and agents, and evaluate a conversational assistant on certified questions, ending with a policy on which questions the assistant may answer. DS-307 covers single-area metrics, dashboards and a first agent test; this course designs the layer across business areas and governs the assistant.

## Learning outcomes

By the end, the participant can:

- Design a semantic layer with entities, grain, conformed time and governed metrics for several business areas.
- Implement metric definitions as code with owners, tests and change control.
- Configure row-level access and field masking in the semantic layer according to data classification.
- Evaluate a conversational assistant on certified questions, measuring accuracy, stability, wrong but plausible answers and the contribution of each kind of semantic context.
- Decide which question types the assistant may answer and under which safeguards.
- Review the design of a peer's analytics product for correctness, portability and governance.

## Topics

### Metrics as products

- One definition, one owner, tests
- Ratio, cumulative and derived metrics
- Certification, versioning and deprecation

### Semantic layer design

- Conformed dimensions across business areas
- Pre-aggregation, caching and query cost
- Classification-aware access rules
- Open interchange specifications

### Conversational analytics

- Certified question sets by area and difficulty
- Which context helps: synonyms, descriptions, examples
- Execution accuracy and wrong but plausible answers
- Stability across repeated runs

### Shipping and governing

- Serving metrics to tools and agents
- Showing the metric, filters and grain behind each figure
- Routing by measured risk
