AE-205

Deploying AI Services: Containers, Serving and Monitoring

  • Level 200 · Apply
  • Intensive
  • 5 days · 26 h
  • Available

On the learning path: AI Engineering

Participants take two trained models from a notebook to a monitored service. For a fictional mutual insurer they package a claims-triage classifier and a similar-claims embedding model with pinned dependencies, register model versions, serve them behind a versioned API with input validation, build and scan a container image, run it on a single-node local cluster with health checks, add metrics, structured logs and traces, load-test and size the service, release a new version by canary and roll it back, and detect drift in a replayed stream of claims.

Who it is for

Audience: practitioner

Graduates and early-career developers who have completed the FN courses or passed the placement test, and software engineers moving into AI work.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Explain the path from a trained model to a served prediction, naming the artefact, image, registry, runtime, endpoint and monitor at each step.

  2. Applied

    Prepare a model artefact with pinned dependencies, a version, an input and output signature and a reproducible build.

  3. Applied

    Implement a versioned prediction API with input validation, typed errors and separate health and readiness checks.

  4. Applied

    Configure a container image for the service, scan it for vulnerabilities and run it with resource limits on a single-node cluster.

  5. Applied

    Implement metrics, structured logs and traces for the service and a dashboard for latency percentiles, error rate and prediction distribution.

  6. Applied

    Measure latency and throughput under load and size workers and replicas to meet a latency objective at the lowest cost.

  7. Performance

    Deliver a new model version by canary release, decide on promotion or rollback from monitored metrics and detect drift in replayed traffic.

How the work is assessed

  • Supervised entry quiz and exit check without AI assistance: read a container file and a manifest, interpret a latency histogram, choose a release strategy for a scenario (20%)
  • Capstone repository scored on a five-criterion rubric: packaging and API 20, container and deployment 20, observability 20, sizing against the objective 15, release, rollback and drift 25 (60%)
  • Live defence in which the participant rolls back a version and explains a dashboard the assessor selects (20%)
To pass
70% overall, with at least 60% on the capstone rubric and at least 60% on the supervised check

Use of AI in the course

AI-off for the supervised checks and for the first attempt at the container file and the alert rules. AI-tutor in the other labs: the course assistant explains errors and suggests the next step without writing the manifest. AI-full in the capstone, which the participant defends live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
