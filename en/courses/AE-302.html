AE-302

Agentic Systems Engineering: Loops, Context and Harnesses

  • Level 300 · Develop
  • Intensive
  • 5 days · 26 h
  • Available

Participants build an agent as a model in a loop calling typed tools inside a sandbox, with most of the engineering in the harness. For a fictional ports authority they write the loop from scratch, budget the context, add a context file, a skill and a Model Context Protocol (MCP) server, compare an agent SDK with their own harness, gate bookings in a checkpointed state graph, and ship a traced, evaluated and contained agent behind an API.

Who it is for

Audience: practitioner

Engineers who have completed the level 200 set or can show equivalent work: a deployed model or language model application they built and can explain.

Learning outcomes

By the end, the participant can:

  1. Applied

    Implement a tool-calling agent loop without a framework, with typed tool schemas, a step budget and explicit completion criteria.

  2. Applied

    Apply compaction, offloading of tool results and staged loading of skills, and measure the effect on tokens and success.

  3. Applied

    Implement a protocol server over a document store and connect the agent to it through capability discovery.

  4. Performance

    Design a checkpointed state-graph agent with a human approval gate at a defined risk threshold.

  5. Performance

    Evaluate the agent over repeated trials, including runs against a seeded prompt injection.

  6. Performance

    Deliver the agent as a traced API service gated by a smoke evaluation in continuous integration.

More about this course

Topics

From model to agent

  • Typed tool schemas and useful tool errors
  • The loop written from scratch
  • Completion criteria and step budgets

Context and protocols

  • Context as a budget
  • Compaction, offloading and cache-aware layout
  • Context files, skills and memory files
  • Model Context Protocol, current revision; agent-to-agent delegation as a concept

Harness and loop

  • Tools, context, state and feedback as the harness
  • Agent SDKs against an own loop
  • Verification inside the loop

Graphs and several agents

  • Checkpoints and interrupts
  • Approval at risk thresholds, and approval prompts nobody reads
  • When several agents pay

Securing and shipping

  • The agentic risk list of the Open Worldwide Application Security Project (OWASP)
  • Private data, untrusted content, exit path: remove one leg
  • Sandboxes and egress allowlists

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Language model access
a locally served open-weight model, a free hosted open-weight model, any commercial API
Agent framework with state graphs and checkpoints
LangGraph, Pydantic AI with its graph library
Agent SDK for the comparison
smolagents, OpenAI Agents SDK, Google Agent Development Kit
Protocol server SDK
official Model Context Protocol Python SDK, FastMCP
Tracing and evaluation
OpenTelemetry with Langfuse, Arize Phoenix, Inspect
Execution sandbox
Docker or Podman containers with no network by default, OpenSandbox
API service and continuous integration
FastAPI, GitLab CI, GitHub Actions

How the work is assessed

  • Supervised entry and exit checks without AI assistance: reading a trace and predicting the next step (20%)
  • Capstone repository on a five-criterion rubric: working agent 25, context and harness design 20, evaluation over trials 20, containment 20, reproducibility 15 (60%)
  • Live defence of one harness decision (20%)
To pass
70% overall and at least 60% on the capstone rubric

Use of AI in the course

AI-off for the supervised checks and for writing the first loop. AI-tutor in the other labs: the assistant hints but does not write harness code. AI-full in the capstone, coding agents included, with transcripts kept and the result defended live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
