AE-203

Building Applications on Language Models

  • Level 200 · Apply
  • Intensive
  • 5 days · 26 h
  • Available

On the learning path: AI Engineering

Participants build a bilingual rider assistant for a fictional transit authority on top of any language model, hosted or open-weight. They call models through a provider-neutral interface, extract validated structured data from rider messages, add tool calls to a synthetic trip-status service, ground answers in a policy corpus with citations and abstention, write a small evaluation set and run the assistant against it, and add input and output checks for personal data and instruction-like text. The result is a small tested web service.

Who it is for

Audience: practitioner

Graduates and early-career developers who have completed the FN courses or passed the placement test, and software engineers moving into AI work.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Compare the main model API shapes and identify what changes in code when an application switches provider or moves to a local model.

  2. Applied

    Implement structured extraction from free-text messages with schema validation, bounded retries and a fallback path.

  3. Applied

    Implement tool calling for two services with typed arguments, argument validation and handling of tool errors.

  4. Applied

    Implement a grounded answering step that retrieves policy passages, cites them and declines when the corpus holds no answer.

  5. Applied

    Prepare a small evaluation set and measure the assistant with code-based checks and one model-graded check validated against labels.

  6. Applied

    Configure input and output checks for personal data, off-topic requests and instruction-like text inside retrieved content.

  7. Performance

    Build a bilingual assistant service that combines structured extraction, tool calls and grounded answers behind a tested API.

Topics

Calling models

  • Tokens, context and cost
  • Chat, response and message API shapes, and the Open Responses specification
  • Provider-neutral clients and gateways
  • Prompt caching and stable context order
  • Streaming, timeouts and retries
  • Choosing a model per task

Prompts as code

  • System and user instructions
  • Examples in the prompt
  • Templates under version control
  • A prompt change is a release

Structured outputs

  • JSON Schema
  • Constrained decoding versus validate and retry
  • Typed models in code
  • Fallback to a human queue

Tool calling

  • Tool schemas
  • The call, execute and return cycle
  • Argument validation and tool errors
  • Workflow or agent
  • Tool servers over the Model Context Protocol (MCP), at concept level

Grounded answers

  • Chunking and indexing
  • Lexical, dense and hybrid search
  • Citations
  • Abstention
  • Arabic text normalisation

Small evaluations

  • Golden cases
  • Code-based checks
  • One model grader checked against labels
  • Re-running on every change

Input and output safety

  • Personal data detection and masking
  • Instruction-like text in retrieved content
  • Output validation
  • Logging without leaking

Shipping the service

  • A web API around the assistant
  • Tests with recorded model responses
  • Configuration and secrets

How the work is assessed

  • Supervised entry quiz and exit check without AI assistance: read a request and response trace, spot a schema violation, estimate token cost, find instruction-like text in a retrieved passage (20%)
  • Capstone repository scored on a five-criterion rubric: working service and tests 25, structured output and tools 20, grounding and abstention 20, evaluation 20, safety checks and limits 15 (60%)
  • Live defence in which the participant runs the evaluation and explains a failing case the assessor selects (20%)
To pass
70% overall, with at least 60% on the capstone rubric and at least 60% on the supervised check

Use of AI in the course

AI-off for the supervised checks and for the first attempt at the schema and tool-calling labs. AI-tutor in the other labs: the course assistant hints and explains but does not write the module. AI-full in the capstone, which the participant defends live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
