FN-101

Python for Data and AI Work

  • Level 100 · Explain
  • Intensive
  • 5 days · 26 h
  • Available

On the learning path: Foundations

Participants write Python the way data and AI work needs it: small typed functions over collections and files, errors that fail loudly, and code moved out of notebooks into scripts that rerun. The case is a fictional regional water utility with synthetic meter readings in comma-separated values (CSV) files and bilingual service tickets in JavaScript Object Notation (JSON) Lines. Each day opens with an AI-off drill in reading, tracing or debugging code by hand, and the labs grow into a command-line tool that validates readings, flags anomalies and writes a summary report. Arabic text normalisation and SQL are left to FN-104, version control to FN-102.

Who it is for

Audience: beginner

Graduates and career changers entering the AI Engineering or Data Science track; computing and data graduates who pass the placement test skip the courses it covers.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Explain what a short program prints, step by step, including name binding, shared mutable lists and dictionaries, and scope.

  2. Awareness

    Distinguish when a notebook, a script or an importable module is the right home for a piece of code.

  3. Applied

    Implement typed functions that load, validate and aggregate records with lists, dictionaries, sets and comprehensions.

  4. Applied

    Apply exception handling and input validation so that each bad record is reported with a reason instead of crashing or passing silently.

  5. Applied

    Use a repeatable debugging method: reproduce, shrink the input, form a hypothesis, test it, fix, and add a regression check.

  6. Applied

    Prepare a command-line tool from an exploratory notebook, with an entry point, arguments and a written report.

Format and days

Format
Intensive: 4 teaching days of four sessions and a capstone day, with guided pre-work and a tracked follow-up task
Total hours
26 h

The days and sessions of the published course.

  1. Day 1 Read before you write

    1. Values, names and references
    2. Functions with clear contracts
    3. Type hints and a checker
    4. Parsons problems

  2. Day 2 Collections for data work

    1. Dictionaries for counting and grouping
    2. Sets and membership
    3. Comprehensions and generators
    4. Records as data classes

  3. Day 3 Files, text and failure

    1. CSV and JSON Lines
    2. Text, bytes and encodings
    3. Exceptions that explain
    4. A debugging method

  4. Day 4 From notebook to tool

    1. What notebooks hide
    2. Scripts, modules and an entry point
    3. Tests as a safety net
    4. Learning with an assistant without losing the skill

  5. Day 5 Capstone project presentations

More about this course

Topics

Reading and tracing code

  • Values, names and references
  • Mutation and aliasing
  • Scope and the call stack
  • Predict-the-output and Parsons problems

Functions and types

  • Decomposing a task into small functions
  • Type hints and a type checker
  • Docstrings and doctests
  • Modules and the standard library

Collections for data

  • Lists, tuples, dictionaries and sets
  • Comprehensions and generators
  • Sorting with keys, counting and grouping
  • Data classes for records

Files, text and errors

  • CSV and JSON Lines
  • Bytes, UTF-8 and decoding errors, with Arabic examples
  • Exceptions that explain
  • Reading tracebacks

From notebook to tool

  • Hidden state in notebooks
  • Entry points and arguments
  • Logging instead of print
  • Assistants as tutors, not authors

How the work is assessed

  • Supervised AI-off check: tracing, a Parsons problem and one debugging task in a locked editor (30%)
  • Capstone repository on a five-criterion rubric: correctness on hidden tests 30, validation and errors 20, structure and types 20, reproducibility 15, README 15 (50%)
  • Live walkthrough with a requested change (20%)
To pass
70% overall and at least 60% on the AI-off check

Use of AI in the course

AI-off for the daily drills, the first attempt at each debugging lab and the supervised check. AI-tutor in the other labs, set by the course repository's agent instructions to give hints, not code. AI-full in the capstone, which the participant walks through and changes live.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
