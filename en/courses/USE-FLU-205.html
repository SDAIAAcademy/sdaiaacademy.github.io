USE-FLU-205

Building Small Tools without Code

  • Level 200 · Apply
  • Workshop
  • 3 days · 16 h
  • Available

Participants who do not program turn a team need, such as a request tracker, into a small, tested internal tool with a generative coding platform. They specify users, data, rules and access levels, direct the coding agent through an instruction file, accept each change only after a test, check for exposed data, secrets and missing access control, and write a hand-over note. Production deployment belongs to developers (DEV-SWE-201).

Who it is for

Audience: practitioner

Staff in any role and sector, from new hires to managers, who use or will use dashboards, AI assistants and agents in routine work; no technical background is assumed and delivery is Arabic-first in the Kingdom.

Learning outcomes

By the end, the participant can:

  1. Awareness

    Distinguish a team prototype from a production system and identify requests that need developers.

  2. Applied

    Draft a one-page specification with users, data fields, rules, access levels and acceptance tests.

  3. Applied

    Use a generative coding platform and an instruction file to build the tool in small, tested, reversible steps.

  4. Applied

    Test a prototype for exposed personal data, hard-coded secrets, missing access control and wrong calculations.

  5. Performance

    Deliver a tested internal tool with a hand-over note naming owner, permitted data, access levels, limits and when developers take over.

Topics

From need to specification

  • Who sees, edits and administers

Directing a coding agent

  • Instruction files and project context

Testing without code

  • Edge cases and hand-checked calculations
  • Testing in each user role
  • Arabic text and right-to-left screens

Safety and ownership

  • No real personal or classified data
  • Secrets, keys and public links
  • Owner, support and retirement

Tools and platforms

These are examples. Any equivalent tool may be used instead.

Generative coding platform
an open-source coding agent in a sandboxed workspace, an approved browser-based app builder
Prototype data store
a local SQLite file, a spreadsheet table
Secrets scan
gitleaks, run by the facilitator, the platform's security scan

How the work is assessed

  • Supervised AI-off check: acceptance tests and faults in screenshots (20%)
  • Lab artefacts (30%)
  • Capstone tool and note (25%)
  • Live demonstration (25%)
To pass
70% overall, 60% on the AI-off check, and no real personal data, hard-coded secret or open administrator access in the capstone

Use of AI in the course

AI-off for the check and first drafts of the specification and tests; AI-tutor when refining them; AI-full in the build, where the participant tests, accepts and owns each change.

AI-off: no AI assistance. AI-tutor: an assistant that hints and explains but does not give the answer. AI-full: any assistance; the participant owns the result and defends it.
